Schemaを定義する

組織で共通の情報は、名前と型を固定します

今日これだけ

Schemaはschema.usdaに書いてusdGenSchemaで生成する codelessならC++のビルドは要らない

公式情報に基づく説明

自分の組織のためのSchemaを足す

STEP 14で、SchemaにはTypedとAPIの2系統があると見ました。ここではそれを自分で追加する側に回ります。

なぜ足すのかというと、STEP 11のcustomなPropertyでは足りない場面があるからです。customは誰でも好きな名前で書けるので、綴りの揺れを止められず、既定値も型の保証もありません。組織で共通に使う情報なら、Schemaとして定義して名前と型を固定するほうが確実です。

定義はschema.usdaという1つのファイルに書きます。そこからコード生成ツールusdGenSchemaを走らせると、C++とPythonのクラスが出てきます。

OpenUSD Academy Note

Codeless Schemaという選択肢があります。schema.usdaにskipCodeGeneration = trueを書くと、コードを生成せず定義だけを登録します。専用のクラスは作られませんが、prim.GetAttribute("myField")のような汎用APIで扱え、既定値も型の検査も効きます。C++のビルド環境が要らないので、まずはこちらから始めるのが現実的です。

USDA

schema.usdaの書き方

schema.usda（抜粋）USDA
#usda 1.0
(
    subLayers = [
        @usd/schema.usda@
    ]
)

over "GLOBAL" (
    customData = {
        string libraryName = "academyExample"
        string libraryPath = "./"
        bool skipCodeGeneration = true
    }
)
{
}

class "AcademyAssetInfoAPI" (
    inherits = </APISchemaBase>
    customData = {
        token apiSchemaType = "singleApply"
    }
)
{
    string academy:assetName = "" (
        doc = "このAssetの名前"
    )
    int academy:version = 1 (
        doc = "このAssetの版"
    )
}

読み方の要点は3つです。over "GLOBAL"のcustomDataにライブラリ全体の設定を書きます。skipCodeGeneration = trueがCodeless Schemaの指定です。

次に、Schema本体をclassで定義します。inheritsの先で系統が決まります。/APISchemaBaseならAPI Schema、/Typedやその子孫（/Xformableなど）ならTyped Schemaです。apiSchemaTypeでsingleApplyかmultipleApplyを選びます。

波括弧の中がPropertyの定義です。ここに書いた値が既定値（Fallback Value）になります。docは説明文で、後からGetDocumentation()で読めます。

生成

usdGenSchemaを走らせる

ターミナルコマンド
# schema.usda からコードと plugInfo.json を生成する
$ usdGenSchema schema.usda .

# 生成されるもの（codeless でない場合）
#   tokens.h / tokens.cpp
#   academyAssetInfoAPI.h / .cpp
#   wrapAcademyAssetInfoAPI.cpp     … Pythonバインディング
#   plugInfo.json                   … USDへ登録するための情報
#   generatedSchema.usda            … 定義そのもの

# codeless の場合は、生成されるのは次の2つだけ
#   plugInfo.json
#   generatedSchema.usda

USDが起動時に読むのはplugInfo.jsonです。ここに「このディレクトリにこういうSchemaがある」と書かれていて、PXR_PLUGINPATH_NAMEという環境変数でその場所を教えます。登録されると、STEP 14で使ったUsd.SchemaRegistryから自分のSchemaが見えるようになります。

Python

適用できるかを事前に確かめる

API Schemaには「どのPrimに付けられるか」の制限を持たせられます。適用する前に確かめるのがCanApplyです。

can_apply.pyPython
from pxr import Usd, UsdGeom, UsdShade

stage = Usd.Stage.CreateNew("t.usda")
mesh = UsdGeom.Mesh.Define(stage, "/M")
scope = UsdGeom.Scope.Define(stage, "/S")

for prim, label in ((mesh.GetPrim(), "Mesh"), (scope.GetPrim(), "Scope")):
    ok, why = UsdShade.MaterialBindingAPI.CanApply(prim)
    print("%-6s MaterialBindingAPI: %s %s"
          % (label, ok, ("/ 理由: " + why) if why else ""))

registry = Usd.SchemaRegistry
for name in ("Mesh", "MaterialBindingAPI", "CollectionAPI", "Imageable"):
    print("%-20s kind=%-24s applied=%s multiple=%s"
          % (name, registry.GetSchemaKind(name),
             registry.IsAppliedAPISchema(name),
             registry.IsMultipleApplyAPISchema(name)))
実行結果Output
Mesh   MaterialBindingAPI: True 
Scope  MaterialBindingAPI: True 
Mesh                 kind=ConcreteTyped            applied=False multiple=False
MaterialBindingAPI   kind=SingleApplyAPI           applied=True multiple=False
CollectionAPI        kind=MultipleApplyAPI         applied=True multiple=True
Imageable            kind=AbstractTyped            applied=False multiple=False

MaterialBindingAPIは適用先を制限していないので、どちらもTrueです。制限を持つSchemaではFalseと理由が返ります。適用の前にCanApplyで確かめるのが、変換ツールを書くときの作法です。

下半分はSTEP 14と同じ内容ですが、自分で定義したSchemaもここに同じ形で出てきます。登録できたかどうかは、このGetSchemaKind()が期待どおりの値を返すかで確かめられます。

Beginner notes

customで足りるか、Schemaにすべきか

OpenUSD Academy Note

判断の目安は「他人が書くか」です。自分のツールが書いて自分だけが読むならcustomで十分です。複数の人やツールが同じ情報を書くなら、綴りと型を固定する意味があるのでSchemaにします。

この教材の例で使っているcustom string academy:assetNameは、本来ならSchemaにすべき情報です。customのままにしているのは、Schemaの登録には環境変数の設定が要り、教材として再現しにくいためです。実務では、組織で共通に使う情報はSchemaにします。

よくある間違い

定義したのに認識されない

PXR_PLUGINPATH_NAMEを設定していない

生成したplugInfo.jsonの場所を教えないと、USDは自作Schemaを見つけられません。GetSchemaKind()が空を返したらここを疑います。

inheritsの先を間違える

API Schemaなら/APISchemaBase、Typed Schemaなら/Typed系です。ここを取り違えると、意図と違う種類として登録されます。

Property名に接頭辞を付けない

assetNameのような一般的な名前は、他のSchemaと衝突します。academy:assetNameのように名前空間を付けます。

codelessなのにクラスをimportしようとする

Codeless Schemaは専用クラスを生成しません。prim.GetAttribute()のような汎用APIで扱います。

既定値を書かずに「値が無い」と扱う

Schemaに既定値を書けば、書かれていなくてもその値が返ります。STEP 28のFallback Valueと同じ仕組みです。

Glossary

このレッスンの用語

schema.usda
Schemaの定義を書くファイル。classでSchemaを、over "GLOBAL"でライブラリ全体の設定を書く。
usdGenSchema
schema.usdaからC++・PythonのコードとplugInfo.jsonを生成するツール。
Codeless Schema
skipCodeGeneration = trueを指定し、コードを生成せず定義だけを登録するSchema。ビルド環境が要らない。
plugInfo.json
USDが起動時に読む登録情報。PXR_PLUGINPATH_NAMEで場所を教える。
CanApply
そのAPI SchemaをこのPrimに適用できるかを、理由つきで返すPython API。
apiSchemaType
API Schemaの種類を指定するcustomData。singleApplyかmultipleApply。
