Workstream Layers

作業の種類ごとにファイルを分け、同じ場所を奪い合わないようにします

今日これだけ

1つの作業に1枚のLayer。積む順番が上書きの強さになる

公式情報に基づく説明

同じ形へ、別々のファイルから書く

1つのAssetは、形を作る人・色を付ける人・動きを付ける人など、複数の作業が関わります。この作業の単位ごとにSTEP 49 Sublayerを分けたものをWorkstream Layerと呼びます。各Layerは同じPathに対して、それぞれ自分の担当ぶんだけを書きます。誰も他人のファイルを開く必要がなく、同じファイルを同時に編集することもありません。

OpenUSD Academy Note

ここがOpenUSDの共同作業のいちばんの利点です。他の多くの形式では「1つのオブジェクト＝1か所」なので、色を変えるにはモデルのファイルを開いて書き換えることになります。OpenUSDでは、色の担当は自分のファイルにoverを書くだけで済みます。

USDA

形の担当が書くファイル

lamp_geom.usdaUSDA
#usda 1.0
(
    defaultPrim = "Lamp"
    metersPerUnit = 1
    upAxis = "Y"
)

def Xform "Lamp"
{
    def Cylinder "Base"
    {
        double height = 0.12
        double radius = 0.45
        uniform token axis = "Y"
    }

    def Cylinder "Stem" { ... }

    def Cone "Shade"
    {
        double height = 0.6
        double radius = 0.5
        uniform token axis = "Y"
        double3 xformOp:translate = (0, 1.75, 0)
        uniform token[] xformOpOrder = ["xformOp:translate"]
    }
}

形の担当はdefでPrimを定義し、形に関することだけを書きます。色は一切書きません。

このUSDAファイルを開く

USDA

色の担当が書くファイル

lamp_look.usdaUSDA
#usda 1.0
(
    defaultPrim = "Lamp"
    metersPerUnit = 1
    upAxis = "Y"
)

over "Lamp"
{
    over "Base"
    {
        color3f[] primvars:displayColor = [(0.35, 0.35, 0.38)]
    }

    over "Stem"
    {
        color3f[] primvars:displayColor = [(0.35, 0.35, 0.38)]
    }

    over "Shade"
    {
        color3f[] primvars:displayColor = [(0.95, 0.8, 0.35)]
    }
}

色の担当はすべてoverです。Primを定義せず、色の意見だけを重ねます。形の担当のファイルには一切触れていません。Pathさえ合っていれば、これで届きます。

このUSDAファイルを開く

USDA

まとめ役が積む

lamp_contents.usdaUSDA
#usda 1.0
(
    defaultPrim = "Lamp"
    metersPerUnit = 1
    subLayers = [
        @lamp_look.usda@,
        @lamp_geom.usda@
    ]
    upAxis = "Y"
)

def Xform "Lamp"
{
}

subLayersの並びが強さの順です。先に書いたほうが強いので、lamp_look.usdaがlamp_geom.usdaより優先されます。色の担当が形の担当の値を上書きできるのは、この順序があるからです。

このUSDAファイルを開く

結果

どの値がどのファイルから来たかを確かめる

check_workstreams.pyPython
from pxr import Sdf, Usd

stage = Usd.Stage.Open("lamp_contents.usda")

for layer in stage.GetLayerStack():
    print(layer.GetDisplayName())
# lamp_contents-session.usda
# lamp_contents.usda
# lamp_look.usda
# lamp_geom.usda

shade = stage.GetPrimAtPath("/Lamp/Shade")

for spec in shade.GetPrimStack():
    print(spec.layer.GetDisplayName(), spec.specifier)
# lamp_look.usda  Sdf.SpecifierOver     … 色の担当（強い）
# lamp_geom.usda  Sdf.SpecifierDef      … 形の担当（定義を与えている）

print(shade.GetAttribute("height").Get())                  # 0.6
print(shade.GetAttribute("primvars:displayColor").Get())   # [(0.95, 0.8, 0.35)]

同じ/Lamp/ShadeというPrimに、2つのファイルが寄与しています。大きさは形のファイルから、色は色のファイルから来ています。STEP 68 Prim Stackを見れば、誰の担当かが一目で分かります。

Diagram

担当ごとに1枚

Python

Layerを1枚足す

add_workstream.pyPython
from pxr import Sdf, Usd

# 新しい担当（たとえば配置調整）のLayerを作る
layout = Sdf.Layer.CreateNew("lamp_layout.usda")
layout.defaultPrim = "Lamp"

# まとめ役のいちばん上（＝いちばん強い位置）へ足す
contents = Sdf.Layer.FindOrOpen("lamp_contents.usda")
contents.subLayerPaths.insert(0, "lamp_layout.usda")
contents.Save()

print(list(contents.subLayerPaths))
# ['lamp_layout.usda', 'lamp_look.usda', 'lamp_geom.usda']

担当を増やすときは、Layerを1枚作ってsubLayerPathsへ挿入するだけです。既存のファイルは1文字も変わりません。強くしたければ先頭へ、弱くしたければ末尾へ入れます。

Beginner notes

一覧の先頭に出るsession layer

OpenUSD Academy Note

GetLayerStack()の先頭にlamp_contents-session.usdaという、書いた覚えのないLayerが出てきます。これはSession Layerで、Stageを開いたときに自動で用意される、保存されない一時的な作業場所です。ビューアで一時的に何かを隠したときなどの変更が、ここへ入ります。ファイルとしては存在しないので、気にしなくて構いません。

よくある間違い

担当の境界をまたいで書く

色の担当がdefでPrimを作る

形の担当と定義が二重になります。色の担当は必ずoverだけを書きます。

Pathがずれて色が届かない

overは存在しないPathにも黙って書けます。効かないときは、まずPathの綴りを確認します。

subLayersの順序を意識しない

先に並べたほうが強くなります。形が色を上書きしてしまうときは、順序が逆です。

1枚のLayerに複数の担当を混ぜる

同時編集の衝突が戻ってきます。分ける意味がなくなるので、担当ごとに1枚にします。

Glossary

このレッスンの用語

Workstream Layer
作業の種類ごとに分けたLayer。同じPathへ、担当ぶんだけを書く。
Layer Stack
root layerとそのSublayerからなる、強さの順に並んだLayerの列。
Session Layer
Stageを開いたときに用意される、保存されない一時的なLayer。
subLayerPaths
Sublayerの一覧を保持するPython側のリスト。
