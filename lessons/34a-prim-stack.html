Prim Stack

そのPrimが、どのファイルの記述からできているかを調べます

今日これだけ

GetPrimStackは寄与するPrim Specを強い順に返す

公式情報に基づく説明

合成前の記述を強い順に並べたもの

Stage上の一つのPrimは、複数のLayerに書かれたSTEP 31 Prim Specが合成されてできています。GetPrimStack()は、そのPrimへ寄与しているPrim Specを強い順に並べたリストを返します。各要素からは、どのLayerの、どのPathに、どんなSpecifierで書かれているかが分かります。

OpenUSD Academy Note

これはOpenUSDのデバッグで最初に使う道具です。「なぜこの値になるのか分からない」と思ったとき、まずPrim Stackを表示すれば、関係しているファイルが一目で並びます。合成の結果だけを見ていても原因は分かりません。寄与している記述の一覧を見るのが最短です。

USDA

STEP 32のsublayerの例を使う

specifier-over.usda（抜粋）USDA
#usda 1.0
(
    subLayers = [
        @specifier-base.usda@
    ]
)

over "World"
{
    over "Retouched"
    {
        color3f[] primvars:displayColor = [(0.15, 0.35, 0.85)]
    }
}

土台のspecifier-base.usdaにはdef Cube "Retouched"があり、赤い色が書かれています。上のLayerはoverで青を重ねています。つまり/World/Retouchedには、2つのファイルからの記述が寄与しています。

このUSDAファイルを開く

結果

2つのPrim Specが強い順に並ぶ

prim_stack.pyPython
from pxr import Usd

stage = Usd.Stage.Open("specifier-over.usda")
prim = stage.GetPrimAtPath("/World/Retouched")

for spec in prim.GetPrimStack():
    print(spec.layer.GetDisplayName(), spec.path, spec.specifier)

# specifier-over.usda  /World/Retouched  Sdf.SpecifierOver
# specifier-base.usda  /World/Retouched  Sdf.SpecifierDef

1行目が強い側です。上のLayerがoverで、下のLayerがdefであることが読み取れます。STEP 32で確かめた「書いたのはoverだが、合成後のGetSpecifier()はdef」という話が、このリストを見れば一目で分かります。

Stackの読み方

Python

調べたい情報を取り出す

inspect_stack.pyPython
from pxr import Usd

stage = Usd.Stage.Open("specifier-over.usda")
prim = stage.GetPrimAtPath("/World/Retouched")

for spec in prim.GetPrimStack():
    print("layer      :", spec.layer.identifier)   # ファイルの場所
    print("path       :", spec.path)               # そのLayer内でのPath
    print("specifier  :", spec.specifier)          # def / over / class
    print("properties :", list(spec.properties.keys()))
    print("---")

# どのLayerが定義を与えているかだけ知りたいとき
defining = [s for s in prim.GetPrimStack()
            if s.specifier == Sdf.SpecifierDef]

返ってくるのはSdf.PrimSpecで、これは合成前の生の記述です。spec.propertiesには、そのLayerに書かれたPropertyだけが入ります。合成後の値ではないので、Stage側のGetAttribute(...).Get()とは結果が違います。

Beginner notes

PathはLayerごとに違うことがある

OpenUSD Academy Note

Sublayerの場合、寄与するLayerの中でも同じPathになります。しかしSTEP 40 Referenceで持ち込まれた場合は、参照先のファイル内では/Crate/Bodyのような別のPathになっています。Prim StackのpathはそのLayerの中でのPathなので、行き先のファイルを開いて探すときに役立ちます。

よくある間違い

合成結果と生の記述を混同する

PrimSpecから合成後の値を取ろうとする

spec.propertiesはそのLayerに書かれた分だけです。最終値はprim.GetAttribute(...).Get()で取ります。

1つしか返らないので合成されていないと思う

1つのLayerにしか書かれていなければ、要素は1つです。それが正常です。

順番を弱い順だと思う

先頭が最も強い側です。上書きの原因を探すときは先頭から見ます。

Glossary

このレッスンの用語

Prim Stack
あるPrimへ寄与するPrim Specを、強い順に並べたリスト。
Sdf.PrimSpec
一つのLayerに書かれた、合成前のPrimの記述を表すオブジェクト。
identifier（Layer）
そのLayerを一意に示す文字列。多くはファイルのPath。
寄与する（contribute）
あるLayerの記述が、合成結果に関わっていること。
