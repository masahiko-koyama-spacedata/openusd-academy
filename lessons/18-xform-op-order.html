STEP 23 · TRANSFORMS

XformOpOrder

どのxformOpを、どの順序で変換stackへ積むかを指定するtoken配列

今日これだけ

変換結果は値だけでなくxformOpOrderで決まる

Translate、Rotate、ScaleのAttributeが同じでも、xformOpOrderの並びが違えば結果は変わり得ます。

公式情報に基づく説明

Attributeの表示順では評価順が分からない

公式: UsdGeomXformableの変換操作はxformOp namespaceの動的Attributeとして記述されます。Attributeは辞書順で表示されることがあるため、ファイル内で上に見える順を評価順として使いません。

公式: xformOpOrderは操作Attributeの名前を、transform stackへpushする正確な順序で保持します。AddXformOp()は新しい操作を配列の末尾へ、よりlocalな操作として追加します。

OpenUSD Academy Note

コードブロックを読むときは値を見つけたあと、必ずxformOpOrderへ視線を移します。Propertyの行順ではなく、この配列が説明書です。

なんのためにあるのか

自由な変換列を失わず交換する

OpenUSDは固定されたTranslate・Rotate・Scale欄だけに限定せず、複数のRotate、用途別suffix付きTranslate、pivot、逆操作を並べられます。その自由な操作列を正確に復元するため、操作名と順序を明示します。

Diagram

配列を上からtransform stackへ積む

USDA

標準的なTranslate・Rotate・Scaleを並べる

ordered-transform.usdaUSDA
#usda 1.0

def Xform "Crate" {
    float3 xformOp:rotateXYZ = (0, 45, 0)
    float3 xformOp:scale = (2, 2, 2)
    double3 xformOp:translate = (5, 0, 0)
    uniform token[] xformOpOrder = [
        "xformOp:translate",
        "xformOp:rotateXYZ",
        "xformOp:scale"
    ]
}

三つのAttributeは名前の辞書順に見えますが、評価の手順は最後のtoken配列から読みます。角括弧は配列、カンマは要素の区切り、引用符は各tokenの範囲です。インデントは配列の所属を読みやすくします。

一行ずつ読む

uniform token[] xformOpOrderを分解する

  1. uniform

    時間ごとに変化させる目的ではないProperty variabilityです。

  2. token[]

    tokenを複数保持する配列型です。[]が複数要素を示します。

  3. xformOpOrder

    使用する変換操作名とtransform stack上の順序を保持するAttributeです。

  4. 配列の各文字列

    実在するxformOp Attribute名と一致させます。

順序で結果が変わる例題

ScaleとTranslateを入れ替えて比較する

原点にある点(1, 0, 0)を考えます。「2倍してからXへ3移動」なら結果は(5, 0, 0)です。「Xへ3移動してから全体を2倍」なら結果は(8, 0, 0)です。

Scale → Translate

1 × 2 + 3 = 5

Translate → Scale

(1 + 3) × 2 = 8

OpenUSD Academy Note

この計算は「操作順で結果が変わる」ことを直感的に示す簡略例です。USDAの配列をそのまま左から算数式へ置き換えず、実際のlocal transformationはOpenUSD APIで確認します。

特殊なtoken

inverseとstack resetも配列へ入る

  1. !invert!xformOp:translate:pivot

    対応するpivot操作の逆変換を評価します。逆値を別Attributeへ重複して保存しません。

  2. !resetXformStack!

    配列の先頭にあると、namespace上の親から変換を継承しないことを示します。

どちらも通常のAttribute名ではなく、xformOpOrder内で特別な意味を持つtokenです。

Python

操作を追加してorderを確認する

inspect_order.pyPython
from pxr import Gf, Usd, UsdGeom

stage = Usd.Stage.CreateNew("ordered-transform.usda")
crate = UsdGeom.Xform.Define(stage, "/Crate")
xformable = UsdGeom.Xformable(crate)

translate = xformable.AddTranslateOp()
rotate = xformable.AddRotateXYZOp()
scale = xformable.AddScaleOp()

translate.Set(Gf.Vec3d(5, 0, 0))
rotate.Set(Gf.Vec3f(0, 45, 0))
scale.Set(Gf.Vec3f(2, 2, 2))

print(xformable.GetXformOpOrderAttr().Get())
stage.Save()

Add...Op()を呼んだ順に操作がorderへ追加されます。返されたxformOpへSet()で値を設定します。最後のGet()はauthorされたtoken配列を取得します。

例題

どの操作が評価されるか答える

問題1 Scale Attributeはあるがorderに名前がない

答え: そのScaleはlocal transformationの評価へ参加しません。

問題2 orderに存在しないAttribute名がある

答え: 正しい操作列を復元できません。名前の綴りとsuffixをAttributeに一致させます。

問題3 親変換を継承したくない

答え: reset xform stackを使います。USDAでは配列先頭の!resetXformStack!として表れます。

よくある間違い

Propertyの行順を評価順だと思わない

上に書かれたAttributeから実行する

原因: USDAの表示順を手続き型コードの実行順と考えています。

解決策: xformOpOrderだけを操作列の根拠にします。

配列内の綴りを省略する

原因: translateだけで通じると思っています。

解決策: xformOp:translateの完全なAttribute名を書きます。

配列を変えても結果は同じだと思う

原因: 変換操作は一般に可換だと考えています。

解決策: Scale・Rotate・Translateは順序で結果が変わり得ます。小さい数値例かGetLocalTransformation()で確認します。

Glossary

このページで出た言葉

xformOpOrder
使用するxformOpとtransform stack上の順序を保持するtoken配列。
transform stack
複数の変換操作を順序付きで積み重ねる評価の考え方。
identity
変換結果を変えない値。Translateは0、Scaleは1など。
reset xform stack
親Primの変換継承を止める指定。
commutative
順序を入れ替えても結果が同じ性質。一般の変換操作は可換とは限らない。
