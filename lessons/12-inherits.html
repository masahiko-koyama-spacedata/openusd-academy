Opinionから合成結果へ

USDA

記述を読む

inherits.usdaUSDA
#usda 1.0

class Sphere "_BallClass" {
    double radius = 1
}

def Sphere "BallA" (
    inherits = </_BallClass>
) {
}

def Sphere "BallB" (
    inherits = </_BallClass>
) {
    double radius = 2
}

#usda 1.0はUSDAヘッダーです。引用符は名前や文字列、波括弧はPrim内容、丸括弧はMetadata、/はPrim Pathの階層を表します。インデントは所属を読みやすくするためにそろえます。

結果

どのOpinionが見えるか

BallAは継承値1、BallBはより強いLocal値2。クラスを直すと未上書きの継承先へ変更が届きます。

Python

合成結果をAPIで確認する

inspect.pyPython
from pxr import Usd
stage = Usd.Stage.Open("inherits.usda")
print(stage.GetPrimAtPath("/BallA").GetAttribute("radius").Get())
print(stage.GetPrimAtPath("/BallB").GetAttribute("radius").Get())

ピリオドはオブジェクトの機能へ進む記号、丸括弧は関数への入力、引用符はPathやファイル名、字下げはPythonの処理範囲を表します。

例題

用途を判断する

問題: 非描画のclassから半径を共有し、一つだけLocalで変更する

答え: I · Inherits。複数Layer StackにあるPrimへ共有Opinionをbroadcastし、個別のLocal overrideも許したい場面。

公式の論点を残す

Referenceとの違いはbroadcast

公式: Inherit Arcのsource Primに書かれたPrim SpecやProperty Specは継承先へ適用されます。強いLayerからsource Primを変更すると、異なるLayer Stackにある複数の継承先へ変更をbroadcastできます。Referenceが作る利用先は互いに分離される点が違います。

公式: 継承用の抽象的な階層には通常class Specifierを使います。意図を伝えられ、Hydraはclass Primとその子孫を画像化しません。継承先へさらに強いLocal Opinionを書けば、その個体だけ調整できます。

OpenUSD Academy Note

「全コピーへ同じ修正を届けたい」がInherits、「同じアセットを独立して置きたい」がReferenceです。

よくある間違い

Referenceと同じだと思う

誤解

原因: Arcの役割と強度順序を混同しています。

解決策: Referenceは分離されたコピーを作ります。Inheritsは強いLayerからsource classを変更して継承先へbroadcastできます。
