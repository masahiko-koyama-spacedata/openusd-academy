領域別のSchema

Physics・Vol・Media・UI・Proc の位置づけ

今日これだけ

OpenUSDには領域別のSchemaが並んでいて どれも同じ読み方で読める

公式情報に基づく説明

ここまでで、読み方は身についている

この教材ではUsdGeom・UsdShade・UsdLux・UsdSkel・UsdRenderを扱ってきました。OpenUSDには、ほかにも領域別のSchemaが同梱されています。

ここで全部を詳しく学ぶ必要はありません。大事なのは存在を知っておくことと、同じ読み方が通用すると分かっていることです。どのSchemaも、STEP 14で見たTypedとAPIの2系統でできていて、Propertyの名前には接頭辞が付き、Applied API SchemaはapiSchemasに積まれます。

OpenUSD Academy Note

この一覧はpip install usd-coreに入っているプラグインから作りました。つまり特別な準備なしに使えるものです。手元で確かめられるので、気になったらUsd.SchemaRegistry.GetSchemaKind("PhysicsRigidBodyAPI")のように種類を聞いてみるところから始められます。

Python

実在と種類を、その場で確かめる

list_schemas.pyPython
from pxr import Plug, Usd

registry = Usd.SchemaRegistry
names = ["PhysicsRigidBodyAPI", "PhysicsCollisionAPI", "PhysicsScene",
         "Volume", "OpenVDBAsset", "SpatialAudio",
         "Backdrop", "NodeGraphNodeAPI", "GenerativeProcedural"]

for name in names:
    print("%-24s %s" % (name, registry.GetSchemaKind(name)))

libs = sorted({p.name for p in Plug.Registry().GetAllPlugins()
               if p.name.startswith("usd")})
print(libs)

Plug.Registry()は、いま読み込まれているプラグインの一覧を返します。...Validatorsで終わるものは検査の定義で、STEP 104で扱ったAsset Validationの土台です。

種類が返ってくること自体が「使える」という確認になります。自作Schemaを登録したときも、同じやり方で確かめられます（STEP 15）。

USDA

読み方は、ここまでと同じ

physics.usda（抜粋）USDA
def PhysicsScene "Physics"
{
    vector3f physics:gravityDirection = (0, -1, 0)
    float physics:gravityMagnitude = 9.8
}

def Cube "Box" (
    prepend apiSchemas = ["PhysicsRigidBodyAPI", "PhysicsCollisionAPI"]
)
{
    double size = 1
    bool physics:collisionEnabled = 1
    bool physics:rigidBodyEnabled = 1
    vector3f physics:velocity = (0, 0, 0)
}

特別なことは何もありません。def PhysicsSceneはTyped Schema、apiSchemasに並ぶ2つはApplied API Schemaです。Property名にはphysics:という接頭辞が付いています。

この構造はUsdGeomやUsdShadeとまったく同じです。接頭辞がprimvars:かinputs:かphysics:かが違うだけで、読み方は変わりません。

Beginner notes

書けることと、動くことは別

OpenUSD Academy Note

UsdPhysicsのSchemaを書いても、OpenUSD自身が物理シミュレーションをするわけではありません。あくまで「この物体は剛体である」「重力はこの向き」という記述です。実際に動かすのは、その記述を読む物理エンジンです。

これはSTEP 93のUsdRenderと同じ関係です。OpenUSDは共通の書き方を決める役で、実行する側は別にいます。この分担がOpenUSDの設計そのものなので、新しいSchemaに出会ったら「これは記述であって実行ではない」と考えると位置づけを間違えません。

よくある間違い

Schemaの位置づけを取り違える

書けば動くと思う

Schemaは記述です。読んで実行する側（物理エンジン、Renderer）が必要です。

環境に無いSchemaを使う

プラグインが読み込まれていなければ、型は認識されずdefしただけの型なしPrimになります。GetSchemaKind()で確かめます。

接頭辞を省く

physics:gravityMagnitudeのphysics:は名前の一部です。省くと別のPropertyになります。

すべてを覚えようとする

領域別Schemaは今後も増えます。骨格（TypedとAPI、接頭辞、apiSchemas）を押さえておけば、必要になったときに読めます。

Glossary

このレッスンの用語

UsdPhysics
物理シミュレーションのための記述を扱うSchemaの集まり。実行は外部のエンジンが行う。
UsdVol
煙や雲などのボリュームを扱うSchemaの集まり。VolumeとOpenVDBAssetを持つ。
UsdMedia
音を扱うSchemaの集まり。SpatialAudioで空間内の音源を表す。
UsdUI
編集画面での見た目を扱うSchemaの集まり。Backdropなど。
UsdProc
手続き的な生成を扱うSchemaの集まり。GenerativeProceduralを持つ。
Plug.Registry
いま読み込まれているプラグインの一覧を返すPython API。使えるSchemaの確認に使える。
