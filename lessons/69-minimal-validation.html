検査は、失敗の記録から育てる

STEP 82 Asset Validationでは、規則を先に決めて検査を書きました。ここでは逆から作ります。実際に踏んだ失敗を、そのつど1つずつ検査に足していくやり方です。最初から完璧な検査を書こうとすると始められませんが、この方法なら1つ目から役に立ちます。

OpenUSD Academy Note

この教材を作る過程でも、いくつも失敗しました。存在しないPathを指したBinding、開いていないPayloadをArcで探して見つからなかった判定、同名Cameraで真っ白になった描画。どれもエラーにならずに間違った結果が出る種類の失敗です。こういうものこそ検査に向いています。

Python

1つの形にそろえる

validate.pyPython
from pxr import Usd, UsdGeom, UsdShade

CHECKS = []


def check(name):
    """検査を1つ登録するための飾り。"""
    def wrap(fn):
        CHECKS.append((name, fn))
        return fn
    return wrap


def run(path):
    """登録された検査をすべて回し、問題の一覧を返す。"""
    stage = Usd.Stage.Open(path)          # 変数に持つ（後述）
    problems = []
    for name, fn in CHECKS:
        for message in fn(stage):
            problems.append("[%s] %s" % (name, message))
    return problems

検査を足すときは、この下に関数を1つ書くだけにします。形をそろえておくと、失敗を見つけるたびに1分で追加できます。追加のコストが低いことが、検査が育つかどうかを決めます。

Python

踏んだ失敗を、順に足していく

validate.py（つづき）Python
@check("dangling-target")
def no_dangling_targets(stage):
    """存在しないPathを指すRelationshipが無いこと。usdcheckerは黙っている。"""
    for prim in stage.TraverseAll():
        for rel in prim.GetRelationships():
            for target in rel.GetTargets():
                if not stage.GetPrimAtPath(target.GetPrimPath()):
                    yield "%s -> %s" % (rel.GetPath(), target)


def children_of(prim):
    """Instanceの中身はPrototype側にあるので、そちらを見る。"""
    if prim.IsInstance():
        proto = prim.GetPrototype()
        return list(proto.GetChildren()) if proto else []
    return list(prim.GetChildren())


@check("empty-reference")
def no_empty_references(stage):
    """参照しているのに中身が来ていないPrimが無いこと。"""
    for prim in stage.Traverse():
        if prim.HasAuthoredReferences() and not children_of(prim):
            yield "%s: 参照はあるが子がいない" % prim.GetPath()


@check("primvar-count")
def primvar_counts_match(stage):
    """Primvarの個数が interpolation と合っていること。"""
    expected = {
        UsdGeom.Tokens.constant:    lambda pts, cnt: 1,
        UsdGeom.Tokens.uniform:     lambda pts, cnt: len(cnt),
        UsdGeom.Tokens.vertex:      lambda pts, cnt: len(pts),
        UsdGeom.Tokens.varying:     lambda pts, cnt: len(pts),
        UsdGeom.Tokens.faceVarying: lambda pts, cnt: sum(cnt),
    }
    for prim in stage.Traverse():
        if not prim.IsA(UsdGeom.Mesh):
            continue
        mesh = UsdGeom.Mesh(prim)
        pts = mesh.GetPointsAttr().Get() or []
        cnt = mesh.GetFaceVertexCountsAttr().Get() or []
        for pv in UsdGeom.PrimvarsAPI(prim).GetAuthoredPrimvars():
            values = pv.ComputeFlattened()
            want = expected[pv.GetInterpolation()](pts, cnt)
            if values is not None and len(values) != want:
                yield "%s: %s が %d 個（期待 %d）" % (
                    prim.GetPath(), pv.GetName(), len(values), want)


@check("duplicate-camera")
def unique_camera_names(stage):
    """同じ名前のCameraが複数無いこと。--camera が定まらなくなる。"""
    seen = {}
    for prim in stage.Traverse():
        if prim.IsA(UsdGeom.Camera):
            seen.setdefault(prim.GetName(), []).append(str(prim.GetPath()))
    for name, paths in seen.items():
        if len(paths) > 1:
            yield "Camera名 '%s' が重複: %s" % (name, paths)

4つとも、この教材を作る過程で実際に踏んだ失敗です。どれも例外を投げず、間違った結果が静かに出るものばかりでした。

OpenUSD Academy Note

2つ目の検査にchildren_ofという関数があるのは、失敗したからです。最初はprim.GetChildren()を直接見ていましたが、それだとSTEP 99の公園シーンで正しいベンチ3台すべてが「参照はあるが子がいない」と報告されました。STEP 88 Instanceの中身はPrototype側にあり、GetChildren()には出てこないためです。誤検知する検査は、無いより悪いものです。信用されなくなり、本当の問題も見過ごされます。検査を足したら、正しいデータで空になることを必ず確かめてください。

Beginner notes

Stageは必ず変数に持つ

OpenUSD Academy Note

検査をまとめて回すコードで、次のように書くと落ちます。

counts = [len(list(Usd.Stage.Open(p).Traverse())) for p in paths]
# RuntimeError: Invalid range starting with expired prim

Usd.Stage.Open()の戻り値をどこにも保持していないため、走査の途中でStageが片付けられます。run()でstage = Usd.Stage.Open(path)と変数に受けているのは、このためです。これも実際に踏んだ失敗です。

よくある間違い

検査が育たない書き方

最初に完璧を目指す

始められません。1つ目から役に立つので、踏んだものから足します。

検査ごとに書き方がばらばら

追加のコストが上がり、足されなくなります。形をそろえます。

問題を見つけて直して終わりにする

同じ失敗をまた踏みます。検査に変えるところまでやります。
