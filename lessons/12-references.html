R · References

Referenceは別LayerのPrim階層を参照元Primへ接ぎ木し、Pathを新しいnamespaceへ変換する

今日これだけ

Referenceは別LayerのPrim階層を参照元Primへ接ぎ木し、Pathを新しいnamespaceへ変換する

公式情報に基づく説明

このArcが解決すること

asset.usdaの/Chairを/World/HeroChairへ参照する

OpenUSD Academy Note

完成したアセットを複数のPathへ再利用する場面です。ここではReference自体に集中するため、参照元Prim Pathを明示します。

Diagram

Opinionから合成結果へ

USDA

記述を読む

shot.usdaUSDA
# asset.usda
#usda 1.0
def Xform "Chair" {
    def Cube "Seat" {}
}

# shot.usda
#usda 1.0
def Xform "World" {
    def Xform "HeroChair" (
        references = @./asset.usda@</Chair>
    ) {}
}

#usda 1.0はUSDAヘッダーです。引用符は名前や文字列、波括弧はPrim内容、丸括弧はMetadata、/はPrim Pathの階層を表します。インデントは所属を読みやすくするためにそろえます。

結果

どのOpinionが見えるか

assetの/Chair/Seatは、結果では/World/HeroChair/Seatになります。参照元rootの名前Chairを子として残すのではなく、HeroChairへ接ぎ木してPathを変換します。

試験で問われるPath

参照元Pathと参照先Pathを分ける

  1. 参照元

    @./asset.usda@</Chair>

    @ @の内側はAsset Path、山括弧の内側は参照元Prim Pathです。

  2. 参照先

    /World/HeroChair

    Reference Arcを記述したPrimです。参照元の/Chairがここへ対応します。

  3. 子Primの結果

    /Chair/Seat → /World/HeroChair/Seat

    参照元rootの名前ChairはPathへ一段追加されません。

OpenUSD Academy Note

二つのPathを別々に読みます。「どこから取るか」が/Chair、「どこへ置くか」が/World/HeroChairです。

参照元USDAを開く · 参照するUSDAを開く

Python

合成結果をAPIで確認する

inspect.pyPython
from pxr import Usd
stage = Usd.Stage.CreateNew("shot.usda")
p = stage.DefinePrim("/World/HeroChair", "Xform")
p.GetReferences().AddReference("./asset.usda", "/Chair")
stage.Save()

ピリオドはオブジェクトの機能へ進む記号、丸括弧は関数への入力、引用符はPathやファイル名、字下げはPythonの処理範囲を表します。

例題

結果のPathを答える

問題: /Chair/Seatを/Set/Prop_01へReferenceしました。Seatの合成後Pathはどれですか。

答え: /Set/Prop_01/Seatです。/Set/Prop_01/Chair/Seatではありません。

公式の論点を残す

External・Internal・prepend・Encapsulation

公式: External Referenceは別LayerのPrim、Internal Referenceは同じLayer内のPrimを対象にできます。Referenceは対象Primのnamespaceを参照先Primへ接ぎ木し、Prim名とPathを新しいnamespaceへ変換します。

公式: prepend referencesは、弱いLayerですでに存在するReferenceより前へ項目を追加し、より強く寄与させます。UsdReferences.AddReference()の既定動作もprependです。

公式: Reference対象の下に収まる内容はencapsulatedです。対象の外側にあるPrimは自動では一緒に入りません。必要な依存関係を入口Primの下へ収めるAsset Structureが重要です。

OpenUSD Academy Note

Referenceは「ファイルを読む」だけではありません。「どのPrimを入口にし、どのPathへ接ぎ木するか」をセットで追います。

よくある間違い

参照元rootの名前が一段残ると思う

誤解

原因: Referenceを単純な親子追加だと考えています。

解決策: 参照元rootは参照先Primへ対応します。/Chair/Seatを/Set/Prop_01へ参照した結果は/Set/Prop_01/Seatです。
