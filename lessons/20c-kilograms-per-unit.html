STEP 52 · STAGE METADATA

kilogramsPerUnit

質量の「1」が何キログラムなのかを記録します

今日これだけ

kilogramsPerUnitは質量の尺度を宣言するMetadataで 既定値は1

公式情報に基づく説明

長さと同じ考え方を質量にも当てはめる

kilogramsPerUnitは、そのLayerで使われる質量の「1」が実世界の何キログラムにあたるかを示すLayer Metadataです。1ならキログラム、0.001ならグラムです。Physicsを扱うSchemaが質量を解釈するときの基準になります。STEP 50 metersPerUnitとまったく同じ考え方で、宣言であって自動変換ではありません。書かなかった場合の既定値は1です。

OpenUSD Academy Note

このMetadataはUsdPhysicsモジュールが扱います。長さのmetersPerUnitがUsdGeomにあるのと対になっていると覚えると、どちらのモジュールをimportすればよいか迷いません。

USDA

グラムで質量を扱うLayer

mass-units.usdaUSDA
#usda 1.0
(
    defaultPrim = "World"
    metersPerUnit = 1
    upAxis = "Y"
    kilogramsPerUnit = 0.001
)

def Xform "World"
{
    def Cube "Brick"
    {
        double size = 0.2
        custom float academy:mass = 2500
    }
}

kilogramsPerUnit = 0.001なので、この世界の質量の「1」は1グラムです。2500は2500グラム、つまり2.5キログラムを意味します。metersPerUnitやupAxisと同じ丸括弧の中に並べて書きます。

Diagram

3つの尺度が同じ場所に並ぶ

この3つはどれもLayer Metadataで、ファイル先頭の同じ丸括弧の中に書きます。どれも「宣言するだけで、値そのものは変えない」という性質を共有しています。

Python

UsdPhysicsから読み書きする

mass_units.pyPython
from pxr import Usd, UsdPhysics

stage = Usd.Stage.CreateNew("mass.usda")

print(UsdPhysics.StageHasAuthoredKilogramsPerUnit(stage))   # False
print(UsdPhysics.GetStageKilogramsPerUnit(stage))           # 1.0

UsdPhysics.SetStageKilogramsPerUnit(stage, UsdPhysics.MassUnits.grams)
print(UsdPhysics.GetStageKilogramsPerUnit(stage))           # 0.001

stage.Save()

UsdPhysics.MassUnitsにはkilograms、grams、slugsが用意されています。StageHasAuthoredKilogramsPerUnitは、値が実際に書かれているかどうかを返します。既定値の1が返ってきたときに「書いてあって1なのか、書いていないだけなのか」を区別できます。

Beginner notes

モジュールの分かれ方

OpenUSD Academy Note

長さの単位はfrom pxr import UsdGeom、質量の単位はfrom pxr import UsdPhysicsです。同じLayer Metadataでも、扱うモジュールが分かれています。これは、Metadataの意味がどの領域に属するかで整理されているためです。defaultPrimのようにどの領域にも属さないものは、Usd.Stageから直接扱います。

よくある間違い

質量の単位を暗黙に決める

書かずにグラムのつもりで数値を入れる

書かなければ既定値の1、つまりキログラムとして解釈されます。2500と書けば2500キログラムです。

metersPerUnitに合わせて自動で決まると思う

長さと質量の尺度は独立しています。センチメートルのシーンでも、質量の既定値はキログラムのままです。

UsdGeomから探してしまう

kilogramsPerUnitを扱うのはUsdPhysicsです。UsdGeomには用意されていません。
