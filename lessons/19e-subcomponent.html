STEP 65 · MODEL HIERARCHY

subcomponent

component内部の重要なPrimを検索可能にするKind

今日これだけ

subcomponentはModelではない

component内部で意味のある部品を示しますが、Model Hierarchyのleaf modelを新しく作りません。

公式情報に基づく説明

component内部へ目印を付ける

公式: componentは別のcomponent modelを子孫に持てません。内部の重要なPrimを識別するためにsubcomponentを使えます。

公式: subcomponentはmodel kindではなく、subcomponent同士を入れ子にできます。

OpenUSD Academy Note

公開Assetを増やすのではなく、Robot内部のArmやWheelをツールから見つけやすくする目印です。

なんのためにあるのか

Asset境界を壊さず重要部品を見つける

Rig、選択UI、検査ツールがcomponent内部の意味ある部品を検索できます。componentのleaf規則を保ったまま、詳細へ役割を与えます。

丸括弧はMetadata、波括弧はPrim内容です。subcomponentは引用符で囲むKind tokenで、XformというPrim型とは別です。

Python

subcomponentを設定する

create_subcomponent.pyPython
from pxr import Kind, Usd, UsdGeom

stage = Usd.Stage.CreateNew("subcomponent.usda")
robot = UsdGeom.Xform.Define(stage, "/Robot")
arm = UsdGeom.Xform.Define(stage, "/Robot/Arm")

Usd.ModelAPI(robot).SetKind(Kind.Tokens.component)
Usd.ModelAPI(arm).SetKind(Kind.Tokens.subcomponent)
print(Usd.ModelAPI(arm).GetKind())
stage.Save()

GetKind()はsubcomponentを返します。ピリオドはAPIの機能へ進み、丸括弧は引数を囲みます。

USDA → Python mapping

Kind tokenを対応させる

例題

componentとの違いを答える

別ファイルとして販売するWheel Asset

答え: 独立Assetならcomponentを検討します。

Robot内部で選択したいWheel

答え: subcomponent。RobotのAsset境界を保ちながら重要部品を示すためです。

よくある間違い

小さいcomponentだと思わない

subcomponentをleaf modelとして扱う

原因: 名前にcomponentが含まれるためです。

解決策: subcomponentはmodel kindではありません。

内部の全Primへ付ける

原因: 重要な検索点という目的を失っています。

解決策: 下流ツールが識別する必要のあるPrimだけに付けます。
