LESSON 24G

Primvar Inheritance

親のconstant Primvarを子へ届ける

今日これだけ

階層を下って適用されるのはconstantだけ

公式情報に基づく説明

公式: Primvarは多くの通常Attributeと異なり、Scene Namespaceを下って子のImageable Primへ暗黙に適用されます。子が同名PrimvarのOpinionを持てば上書きします。継承されるのはconstant interpolationだけです。

OpenUSD Academy Note: Topology依存値を異なる形の子へ配ると個数が合わないため、vertexやfaceVaryingは継承されません。

概念図

USDA

#usda 1.0
def Xform "World"
{
    color3f[] primvars:displayColor = [(1,0,0)] (
        interpolation = "constant"
    )
    def Cube "Body" { }
    def Cube "BluePart"
    {
        color3f[] primvars:displayColor = [(0,0,1)] (
            interpolation = "constant"
        )
    }
}

Bodyは親の赤を受け取り、BluePartは自分のOpinionで青にします。波括弧はPrimの範囲、引用符はPrim名とtoken値を囲みます。

Python

from pxr import Gf, Sdf, Usd, UsdGeom
stage = Usd.Stage.CreateNew("inheritance.usda")
world = UsdGeom.Xform.Define(stage, "/World")
UsdGeom.Cube.Define(stage, "/World/Body")
blue = UsdGeom.Cube.Define(stage, "/World/BluePart")
pv = UsdGeom.PrimvarsAPI(world).CreatePrimvar("displayColor", Sdf.ValueTypeNames.Color3fArray, UsdGeom.Tokens.constant)
pv.Set([Gf.Vec3f(1,0,0)])
blue.GetDisplayColorPrimvar().Set([Gf.Vec3f(0,0,1)])
stage.Save()

/World/BodyはBodyがWorldの子であることを示します。分岐がないためインデントは左端をそろえます。

USDA → Python対応

親のPrimvar → PrimvarsAPI(world).CreatePrimvar(...)
子の同名Opinion → blue.GetDisplayColorPrimvar().Set(...)

例題

親のvertex Primvarは子へ届くでしょうか。届きません。継承されるのはconstantだけです。

よくある間違い

症状: 親のvertex colorが子へ届かない。
原因: Topology依存Primvarも継承できると思った。
解決策: 共有値にはconstantを使い、Topology依存値は対象Gprimへ直接書きます。

このレッスンで出た言葉

Primvar Inheritance
constant PrimvarがNamespaceを下って子へ適用される仕組み。
Imageable
画像化されるPrimに共通する性質を持つSchema基盤。
Sparse Authoring
同じ情報を必要な最小箇所だけへ書く考え方。
