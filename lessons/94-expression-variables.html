STEP 75 · EXPRESSION VARIABLES

Expression Variable

変数ひとつで、読むファイルを切り替えます

今日これだけ

Expression Variableは 合成のときにAsset Pathの一部を変数で差し替える仕組み

公式情報に基づく説明

参照先を、開くときに切り替えたい

同じシーンを、Assetの版を変えて開きたいことがあります。bench_v1.usdaとbench_v2.usdaがあるとき、シーンの参照を書き換えて回るのは大変です。

Expression Variableは、Layerに変数を定義し、Asset Pathの中でその変数を使う仕組みです。変数の値を変えるだけで、参照先が切り替わります。

定義はLayerのMetadataに書きます。使うときはバッククォートで式を囲み、その中で${変数名}と書きます。この式は合成のときに評価されます。

OpenUSD Academy Note

STEP 55のVariant Setと似た用途に見えますが、切り替える対象が違います。Variantは「Prim記述の中身」を切り替え、Expression Variableは「どのファイルを読むか」を切り替えます。ファイル単位でまるごと差し替えたいならこちら、1つのAssetの中で形を選ばせたいならVariantです。

USDA

変数を定義し、Asset Pathで使う

scene.usdaUSDA
#usda 1.0
(
    defaultPrim = "World"
    metersPerUnit = 1
    upAxis = "Y"
    expressionVariables = {
        string VERSION = "v1"
    }
)

def Xform "World"
{
    def Xform "Bench" (
        prepend references = @`"./bench_${VERSION}.usda"`@
    )
    {
    }
}

書き方が独特なので、記号を分けて読みます。外側の@ @はいつものAsset Pathです。その内側のバッククォート` `が「ここは式である」という印です。式の中では文字列をダブルクォートで囲み、${VERSION}で変数を差し込みます。

つまり@`"./bench_${VERSION}.usda"`@は、VERSIONが"v1"のとき@./bench_v1.usda@として解決されます。

このUSDAファイルを開く

Python

変数を変えて、参照先が変わることを確かめる

expression_variables.pyPython
from pxr import Sdf, Usd

stage = Usd.Stage.Open("scene.usda")
print("VERSION=v1 radius:",
      stage.GetPrimAtPath("/World/Bench").GetAttribute("radius").Get())

# Layer の変数を書き換えて開き直す
layer = Sdf.Layer.FindOrOpen("scene.usda")
layer.expressionVariables = {"VERSION": "v2"}
stage2 = Usd.Stage.Open(layer)
print("VERSION=v2 radius:",
      stage2.GetPrimAtPath("/World/Bench").GetAttribute("radius").Get())
実行結果Output
VERSION=v1 radius: 0.5
VERSION=v2 radius: 0.9

bench_v1.usdaのradiusは0.5、bench_v2.usdaは0.9です。シーン側の参照の記述は1文字も変えていません。変数の値だけで、読むファイルが切り替わりました。

Beginner notes

バッククォートを忘れると、ただの文字列

OpenUSD Academy Note

この教材を書く途中で、@./bench_`${VERSION}`.usda@のようにバッククォートを変数の部分だけに付けてしまい、参照が解決できませんでした。Could not open asset @.../bench_`${VERSION}`.usda@という警告が出て、値はNoneのままでした。

正しくはパス全体を式にする形です。@`"./bench_${VERSION}.usda"`@のように、バッククォートで全体を囲み、その中の文字列をダブルクォートで囲みます。式であることを示す印がバッククォート、文字列であることを示す印がダブルクォート、と2段になっています。

よくある間違い

変数が効かない

バッククォートで全体を囲まない

式として扱われず、ただの文字列になります。解決に失敗しますが、例外ではなく警告とNoneで現れます。

式の中で文字列をクォートし忘れる

バッククォートの中はプログラムの式です。パスは文字列なので、ダブルクォートで囲みます。

変数を定義せずに使う

定義されていない変数は展開されません。使うLayerかその上位でexpressionVariablesを定義します。

Variantと同じ用途だと思う

Expression Variableはファイル単位、Variantは1つのAssetの中の選択です。粒度が違います。

値を変えたのに開き直さない

合成のときに評価されるので、変えたら開き直す（または再合成させる）必要があります。

Glossary

このレッスンの用語

Expression Variable
Layerに定義し、Asset Pathの中で${名前}として展開できる変数。合成のときに評価される。
expressionVariables
変数を定義するLayer Metadata。辞書として書く。
Variable Expression
バッククォートで囲んだ式。中の文字列はダブルクォートで囲む。
