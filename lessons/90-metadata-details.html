STEP 16 · METADATA

実務で使うMetadata

値ではなく、値についての情報を置きます

今日これだけ

customDataは自由に使ってよい入れ物 assetInfoは素性を書く決まった場所 docは説明

公式情報に基づく説明

データではない情報を、どこへ置くか

STEP 13で、MetadataがPrimやPropertyに付ける補助情報だと見ました。ここでは、実務でよく使うMetadataを具体的に扱います。値そのものではなく、その値についての情報を置く場所です。

Metadata用途USDAでの見え方
customData自由に使ってよい辞書。組織やツールが好きに書くcustomData = { ... }
assetInfoAssetの素性。名前・版・識別子を決まった鍵で書くassetInfo = { ... }
documentation説明文。docと書くdoc = "..."
displayName画面に見せる名前。Prim名と別にできるdisplayName = "..."
commentファイルに残る注記丸括弧の中に文字列だけ
hiddenブラウザ表示のヒント。描画には影響しないhidden = true

大事なのはcustomDataとassetInfoの使い分けです。どちらも辞書ですが、assetInfoは「このAssetは何者か」を書く場所として役割が決まっています。name・version・identifierといった鍵が使われます。それ以外の、自分の組織だけで使う情報はcustomDataへ入れます。

OpenUSD Academy Note

customDataは自由な分、綴りの揺れも自由です。ownerとOwnerが混ざっても誰も止めません。複数の人やツールが書くなら、STEP 15のSchemaとして定義するほうが確実です。customDataは「一時的なメモ」や「1つのツールしか読まない情報」に向いています。

USDA

6種類を1つのPrimに書いてみる

metadata.usdaUSDA
#usda 1.0
(
    defaultPrim = "Asset"
    metersPerUnit = 1
    upAxis = "Y"
)

def Xform "Asset" (
    "この行はファイルに残る注記"
    assetInfo = {
        asset identifier = @./bench.usda@
        string name = "Bench"
        string version = "1.0"
    }
    customData = {
        dictionary team = {
            string owner = "layout"
            bool reviewed = 1
        }
    }
    displayName = "見せる名前"
    doc = "Assetの説明。GetDocumentation()で読める"
    hidden = true
)
{
}

すべて丸括弧の中にあることに注目してください。STEP 04のとおり、丸括弧はMetadataの場所です。波括弧の中は空で、Propertyは1つもありません。

先頭の"この行はファイルに残る注記"だけ、鍵がなく文字列だけが置かれています。これがcommentの書き方です。

辞書は入れ子にできます。customDataの中のdictionary teamがそれで、Pythonからは"team:owner"のようにコロンでつないだ鍵で読み書きします。

このUSDAファイルを開く

Python

読み書きと、専用のAPI

metadata.pyPython
from pxr import Sdf, Usd, UsdGeom

stage = Usd.Stage.CreateNew("metadata.usda")
prim = UsdGeom.Xform.Define(stage, "/Asset").GetPrim()
stage.SetDefaultPrim(prim)

prim.SetMetadata("comment", "この行はファイルに残る注記")
prim.SetMetadata("documentation", "Assetの説明。GetDocumentation()で読める")
prim.SetDisplayName("見せる名前")
prim.SetMetadata("hidden", True)

prim.SetAssetInfoByKey("name", "Bench")
prim.SetAssetInfoByKey("version", "1.0")
prim.SetAssetInfoByKey("identifier", Sdf.AssetPath("./bench.usda"))

prim.SetCustomDataByKey("team:owner", "layout")
prim.SetCustomDataByKey("team:reviewed", True)

print("displayName       :", prim.GetDisplayName())
print("GetDocumentation():", prim.GetDocumentation())
print("IsHidden()        :", prim.IsHidden())
print("assetInfo         :", dict(prim.GetAssetInfo()))
print("customData        :", dict(prim.GetCustomData()))
実行結果（抜粋）Output
displayName       : 見せる名前
GetDocumentation(): Assetの説明。GetDocumentation()で読める
IsHidden()        : True
assetInfo         : {'identifier': Sdf.AssetPath(authoredPath='./bench.usda'),
                     'name': 'Bench', 'version': '1.0'}
customData        : {'team': {'owner': 'layout', 'reviewed': True}, ...}

SetCustomDataByKey("team:owner", ...)のようにコロンで入れ子の鍵を指定できます。辞書を丸ごと作って渡す必要はありません。

documentationにはGetDocumentation()という専用のAPIがあります。hiddenにはIsHidden()、displayNameにはGetDisplayName()があります。よく使うMetadataには読みやすい入口が用意されています。

Beginner notes

hiddenは見えなくならない

OpenUSD Academy Note

名前から誤解されやすいのですが、hiddenは描画に影響しません。「シーンブラウザの一覧では畳んでおいてよい」というツールへのヒントです。実際に描かないようにするのはSTEP 30のvisibilityとpurposeです。

この3つは名前が似ていますが、効く場所が違います。hiddenはUI、visibilityは描画、purposeは用途と整理しておきます。

よくある間違い

書いた情報が使われない

hiddenで非表示にしようとする

描画には影響しません。消したいならvisibility = "invisible"です。

customDataに共通情報を溜め続ける

綴りや型が保証されないので、書く人が増えると壊れます。共通で使うならSchemaにします。

assetInfoに独自の鍵を足す

役割が決まっている場所です。独自の情報はcustomDataへ入れます。

displayNameでPrimを指せると思う

Pathに使われるのはPrim名です。displayNameは表示用で、参照や検索の対象にはなりません。

commentに鍵を書く

commentは丸括弧の中に文字列だけを置く特別な形です。comment = "..."とは書きません。

Glossary

このレッスンの用語

customData
自由に使ってよい辞書のMetadata。組織やツールが独自の情報を入れる。綴りや型は保証されない。
assetInfo
Assetの素性を書くための辞書のMetadata。name・version・identifierといった鍵が使われる。
documentation（doc）
説明文のMetadata。GetDocumentation()で読める。
displayName
画面に見せる名前のMetadata。Prim名とは別で、Pathには使われない。
comment
ファイルに残る注記。丸括弧の中に鍵なしの文字列として書く。
hidden
ブラウザ表示のヒント。描画には影響しない。visibilityとは別。
