STEP 14 · PROPERTIES

Custom Properties

Schemaに用意されていない情報を、自分で足します

今日これだけ

customはSchemaに無いPropertyを自分で足したという宣言

公式情報に基づく説明

SchemaのPropertyと、自分で足したProperty

Primが持つPropertyには、Schemaがあらかじめ定義しているものと、利用者が独自に足すものがあります。後者をCustom Propertyと呼び、USDAでは名前の前にcustomを書きます。customはMetadataの一種で、「これはSchemaの一部ではない」という意思表示です。AttributeにもRelationshipにも付けられます。

OpenUSD Academy Note

customを書かなくても値は保存できます。しかし書いておくと、読む人とツールに「これはこのSchemaの標準ではない」と伝わります。制作現場では、独自の管理情報（担当、工程、社内ID など）をここに載せることがよくあります。

USDA

SchemaのradiusとCustom Propertyを並べる

custom-properties.usdaUSDA
#usda 1.0
(
    defaultPrim = "World"
    metersPerUnit = 1
    upAxis = "Y"
)

def Xform "World"
{
    def Sphere "Ball"
    {
        double radius = 2

        custom string academy:owner = "lighting"
        custom float academy:score = 12.5
        custom rel academy:relatedTo = </World/Box>
    }

    def Cube "Box"
    {
        double size = 1
    }
}

radiusはSphereSchemaが定義しているのでcustomは付きません。下の3つはSchemaに無いのでcustomを付けています。3つ目はrelなので、値ではなく別のPrimを指すCustom Relationshipです。academy:という前置きはNamespaceで、名前の衝突を避けるために付けています。

このUSDAファイルを開く

確かめる

IsCustomで見分けられる

check_custom.pyPython
from pxr import Usd

stage = Usd.Stage.Open("custom-properties.usda")
prim = stage.GetPrimAtPath("/World/Ball")

for name in prim.GetAuthoredPropertyNames():
    prop = prim.GetProperty(name)
    print(name, prop.IsCustom(), type(prop).__name__)

# academy:owner       True    Attribute
# academy:relatedTo   True    Relationship
# academy:score       True    Attribute
# radius              False   Attribute

GetAuthoredPropertyNames()は、実際に書かれたPropertyだけを返します。Schemaが持つだけで値を書いていないもの（extentやdoubleSidedなど）は含まれません。IsCustom()で、Schema由来かどうかを判別できます。

Propertyの出どころで分ける

Python

CreateAttributeのcustom引数

create_custom.pyPython
from pxr import Sdf, Usd, UsdGeom

stage = Usd.Stage.CreateNew("custom.usda")
UsdGeom.Xform.Define(stage, "/World")
ball = UsdGeom.Sphere.Define(stage, "/World/Ball")
prim = ball.GetPrim()

prim.CreateAttribute("academy:score", Sdf.ValueTypeNames.Float, custom=True).Set(12.5)
prim.CreateAttribute("academy:quiet", Sdf.ValueTypeNames.Float, custom=False).Set(1.0)

rel = prim.CreateRelationship("academy:relatedTo", custom=True)
rel.SetTargets(["/World/Box"])

stage.Save()

保存されたUSDAは次のようになります。custom=Falseにするとcustomが付かず、IsCustom()もFalseになります。

custom.usda（該当部分）USDA
    def Sphere "Ball"
    {
        float academy:quiet = 1
        custom float academy:score = 12.5
    }

どちらも値は保存されます。違うのはcustomという宣言の有無だけです。CreateAttributeのcustom引数は省略するとTrueになります。

Beginner notes

Namespaceで名前の衝突を避ける

OpenUSD Academy Note

Custom Propertyの名前は自由に付けられますが、scoreのような短い名前は将来Schemaに同じ名前が増えたときにぶつかります。academy:scoreのように、自分たちの名前をNamespaceとして前に付けるのが安全です。コロンで区切った名前はPythonでもSplitName()で分解でき、['academy', 'score']のように取り出せます。STEP 27で見たprimvars:displayColor:indicesも同じ仕組みです。

よくある間違い

customを付ける対象を取り違える

SchemaのPropertyにcustomを付ける

custom double radius = 2のように書くのは誤りです。radiusはSphereSchemaが定義しているので、customは付けません。

customを付ければ何でも表示されると思う

Custom PropertyはRendererにとって意味を持ちません。描画に効かせたいなら、Schemaが定めるPropertyか、STEP 21 Primvarとして書く必要があります。

Namespaceを付けずに短い名前を使う

将来の衝突を避けるため、独自のNamespaceを前に付けます。

GetPropertyNamesとGetAuthoredPropertyNamesを混同する

前者はSchemaが持つ未記述のPropertyも含みます。実際に書かれたものだけを見たいときは後者です。

Glossary

このレッスンの用語

Custom Property
Schemaが定義していない、利用者が独自に足したProperty。
custom
そのPropertyがSchemaの一部ではないことを示すMetadata。
Custom Relationship
custom relで書く、Schema外のRelationship。
IsCustom
そのPropertyがCustomかどうかを返すPython API。
GetAuthoredPropertyNames
実際に記述されたPropertyの名前だけを返すPython API。
SplitName
Namespaceで区切られたProperty名を要素に分解するPython API。
