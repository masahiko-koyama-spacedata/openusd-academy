STEP 17 · TRANSFORMS

Translate

PrimをX・Y・Z方向へ移動する変換操作

今日これだけ

Translateは三つの数で移動量を指定する

(X, Y, Z)の順に、Primのlocal空間でどれだけ移動するかを記述します。

公式情報に基づく説明

位置を直接保存するのではなく変換操作を記述する

公式: XformとtransformableなGeometry Primは、translation・rotation・scaleなどのxformOpを持てます。親Primの変換は子孫へ階層的に作用します。

公式: XformCommonAPIのSetTranslate()は一般的な単一のtranslationをauthorします。USDAでは通常、xformOp:translate Attributeと、その操作を列挙するxformOpOrderとして保存されます。

OpenUSD Academy Note

Translateは「最終的なworld座標を直接書く欄」とは限りません。親が動けば、同じlocal translateでもworld上の結果は変わります。

なんのためにあるのか

形を変えずに配置を変える

椅子を部屋の右側へ置く、Robot全体を開始位置へ移す、親Xformの下にある複数部品をまとめて動かすために使います。Geometryのpointsを書き換える方法と違い、元の形状データを保ったまま配置できます。

Diagram

三つの軸へ移動量を分ける

USDA

CubeをX方向へ3移動する

translate.usdaUSDA
#usda 1.0

def Xform "World" {
    def Cube "Box" {
        double size = 2
        double3 xformOp:translate = (3, 0, 0)
        uniform token[] xformOpOrder = [
            "xformOp:translate"
        ]
    }
}

double3はdouble精度の数を三つ持つ型です。xformOpとtranslateの間のコロンはnamespace区切り、=は値の設定、丸括弧は三成分の値をまとめます。角括弧は配列、引用符はtoken値の範囲です。

一行ずつ読む

double3 xformOp:translate = (3, 0, 0)を分解する

  1. double3

    X・Y・Zに対応する三つのdouble精度数を持つ型です。

  2. xformOp:translate

    translation操作のAttribute名です。

  3. (3, 0, 0)

    Xへ+3、YとZへ0移動します。カンマは三成分を区切ります。

  4. xformOpOrder

    このPrimの変換評価へxformOp:translateを参加させます。

親子関係

親のTranslateは子にも届く

parent-translate.usdaUSDA
def Xform "Robot" {
    double3 xformOp:translate = (10, 0, 0)
    uniform token[] xformOpOrder = ["xformOp:translate"]

    def Cube "Body" {
        double3 xformOp:translate = (0, 2, 0)
        uniform token[] xformOpOrder = ["xformOp:translate"]
    }
}

/RobotはlocalでXへ10移動します。/Robot/Bodyは親の空間でYへ2移動するため、回転やscaleがないこの最小例ではworld上の移動結果を(10, 2, 0)として考えられます。

OpenUSD Academy Note

親にrotationやscaleがある場合、world上の結果は単純な足し算だけでは求められません。変換順序と行列を後続ページで扱います。

Python

XformCommonAPIで移動を書く

create_translate.pyPython
from pxr import Gf, Usd, UsdGeom

stage = Usd.Stage.CreateNew("translate.usda")
world = UsdGeom.Xform.Define(stage, "/World")
box = UsdGeom.Cube.Define(stage, "/World/Box")

api = UsdGeom.XformCommonAPI(box)
api.SetTranslate(Gf.Vec3d(3.0, 0.0, 0.0))

stage.Save()

Gf.Vec3dは三つのdouble精度数を持つvectorです。SetTranslate()へ渡すことで、対応するtranslate AttributeとxformOpOrderをauthorします。ピリオドはmoduleやobjectの機能へ進む記号です。

USDA → Python mapping

値と操作を対応させる

  1. USDA

    double3 xformOp:translate = (3, 0, 0)↓

    Python

    api.SetTranslate(Gf.Vec3d(3, 0, 0))

  2. USDA

    xformOpOrder = ["xformOp:translate"]↓

    Python

    XformCommonAPIが共通構成のorderをauthorします。

例題

値と結果を答える

問題1 Xへ5、Yへ-2、Zへ0移動する

答え: xformOp:translate = (5, -2, 0)です。成分順はX・Y・Zです。

問題2 親が(4, 0, 0)、子が(0, 3, 0)移動する

答え: 親子に回転・scaleがない最小条件では、子のworld上の結果を(4, 3, 0)と考えられます。

問題3 Cubeの形状を変えずに別の場所へ置く

答え: pointsやsizeではなくtranslateを使います。配置と形状を分離できるためです。

よくある間違い

値を書くだけで適用されると思わない

xformOpOrderへ追加しない

原因: Attributeの存在と変換評価を同じだと考えています。

解決策: "xformOp:translate"をxformOpOrderへ含めます。

成分をY・X・Zの順に書く

原因: 画面上の見た目だけで軸を推測しています。

解決策: 値は(X, Y, Z)の順です。StageのupAxisとは「三成分の並び」と「どの軸を上として扱うか」を分けて考えます。

local値をworld位置だと思う

原因: 親の階層変換を無視しています。

解決策: translate AttributeはPrimのlocal変換に参加します。world変換は祖先の変換も合成して求めます。

metersPerUnitが自動で数値を変えると思う

原因: 単位Metadataと変換値を混同しています。

解決策: metersPerUnitは解釈する尺度を示します。異なる尺度のAssetをCompositionするときの補正は別ページで扱います。

Glossary

このページで出た言葉

Translate
X・Y・Z方向の移動量を表す変換操作。
local space
親Primを基準にした、そのPrim自身の座標空間。
world space
祖先の階層変換を合成したStage全体の座標空間。
Gf.Vec3d
三つのdouble精度数からなるGf moduleのvector型。
xformOpOrder
使用するxformOpと評価順序を列挙するtoken配列。詳細は独立ページで扱う。
