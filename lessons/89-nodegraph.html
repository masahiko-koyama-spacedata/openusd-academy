STEP 43 · NODEGRAPH

NodeGraphとMaterialX

Shaderが増えたら、まとめて口だけ見せます

今日これだけ

NodeGraphはShaderをまとめて外向きの口だけ見せる箱で Material自身もその一種

公式情報に基づく説明

Shaderが増えたら、まとめて名前を付ける

STEP 41で、テクスチャを貼るのに3つのShaderが並ぶことを見ました。実際の見た目はもっと複雑で、10個も20個もつながることがあります。そのまま平らに並べると、どこからどこまでが「色を作る部分」なのかが読めません。

NodeGraphは、Shaderのまとまりを1つのPrimに閉じ込め、外から見える口だけを公開する仕組みです。inputs:で受け取り、outputs:で出す。中身がいくつのShaderでできているかは、使う側は知らなくて済みます。

ここまでのMaterialとまったく同じ考え方です。実際、MaterialはNodeGraphの一種です。Materialは「表面としての口（outputs:surface）を持つNodeGraph」だと考えると、2つの関係がすっきりします。

OpenUSD Academy Note

STEP 96のAsset Interface、STEP 99のReference/Payload Pattern と、同じ形がまた出てきました。「中身は隠し、外向きの口だけを決める」という設計が、OpenUSDでは繰り返し現れます。1つ理解すると他が読めるようになるのは、このためです。

USDA

色を作る部分を、1つの箱にまとめる

nodegraph.usda（抜粋）USDA
def Material "Paint"
{
    token outputs:surface.connect = </Looks/Paint/PBR.outputs:surface>

    def NodeGraph "ColorBlock"
    {
        color3f inputs:tint = (1, 0.9, 0.8)
        color3f outputs:rgb.connect = </Looks/Paint/ColorBlock/Tex.outputs:rgb>

        def Shader "Tex"
        {
            uniform token info:id = "UsdUVTexture"
            asset inputs:file = @./checker.png@
            color3f outputs:rgb
        }
    }

    def Shader "PBR"
    {
        uniform token info:id = "UsdPreviewSurface"
        color3f inputs:diffuseColor.connect = </Looks/Paint/ColorBlock.outputs:rgb>
        token outputs:surface
    }
}

読む順は外から内です。PBRのdiffuseColorはColorBlockという箱のoutputs:rgbにつながっています。中のTexを直接指してはいません。ColorBlockの中でoutputs:rgbがどこから来るかは、箱の中の話です。

inputs:tintは箱の外から中へ値を渡す口です。使う側はこれを書き換えるだけで、中身の構成を知らずに調整できます。

Python

外から見た接続を確かめる

nodegraph.pyPython
from pxr import Gf, Sdf, Usd, UsdShade

stage = Usd.Stage.CreateNew("ng.usda")
material = UsdShade.Material.Define(stage, "/Looks/Paint")

graph = UsdShade.NodeGraph.Define(stage, "/Looks/Paint/ColorBlock")
tex = UsdShade.Shader.Define(stage, "/Looks/Paint/ColorBlock/Tex")
tex.CreateIdAttr("UsdUVTexture")
tex.CreateInput("file", Sdf.ValueTypeNames.Asset).Set(Sdf.AssetPath("./checker.png"))

# 箱の外向きの口
graph.CreateInput("tint", Sdf.ValueTypeNames.Color3f).Set(Gf.Vec3f(1, 0.9, 0.8))
out = graph.CreateOutput("rgb", Sdf.ValueTypeNames.Color3f)
out.ConnectToSource(tex.ConnectableAPI(), "rgb")

pbr = UsdShade.Shader.Define(stage, "/Looks/Paint/PBR")
pbr.CreateIdAttr("UsdPreviewSurface")
pbr.CreateInput("diffuseColor", Sdf.ValueTypeNames.Color3f).ConnectToSource(out)

print("型            :", graph.GetPrim().GetTypeName())
print("NodeGraphの出力:", [o.GetFullName() for o in graph.GetOutputs()])
print("NodeGraphの入力:", [(i.GetBaseName(), i.Get()) for i in graph.GetInputs()])

source, name, kind = pbr.GetInput("diffuseColor").GetConnectedSource()
print("PBRの接続先    :", source.GetPath(), "/", name, "/", kind)
print("MaterialはNodeGraphか:", bool(UsdShade.NodeGraph(material.GetPrim())))
実行結果Output
型            : NodeGraph
NodeGraphの出力: ['outputs:rgb']
NodeGraphの入力: [('tint', Gf.Vec3f(1.0, 0.9, 0.8))]
PBRの接続先    : /Looks/Paint/ColorBlock / rgb / Output
MaterialはNodeGraphか: True

最後の行が要点です。UsdShade.NodeGraph(material.GetPrim())がTrueを返しました。MaterialはNodeGraphとしても扱えます。だからMaterialにもinputs:を作れて、STEP 42で見たInterface Inputとして値を持てるのです。

MaterialX

より本格的なノードグラフの標準

UsdPreviewSurfaceは、どこでも同じに解釈されることを優先した最小限のShaderでした。より作り込んだ見た目を、ツールをまたいで持ち運びたい場合の標準がMaterialXです。

MaterialXはOpenUSDとは別に定められた仕様ですが、USDから利用できます。MaterialXのノードグラフは、USD側ではNodeGraphとShaderの入れ子としてそのまま表現されます。info:idにND_standard_surface_surfaceshaderのようなMaterialXのノード名が入る形です。

つまり、このレッスンで見た構造がそのまま使われます。NodeGraphの読み方を押さえておけば、MaterialXのマテリアルを開いても構造は追えます。

OpenUSD Academy Note

使い分けの目安は再現性の要求です。ビューアやARで確実に同じに見えればよいならUsdPreviewSurface、DCCツール間で作り込んだ質感を保ちたいならMaterialXです。両方を書いておき、用途で使い分けることもできます。

Beginner notes

箱の中を直接指さない

OpenUSD Academy Note

NodeGraphの外から、中のShaderのoutputs:を直接つなぐことは技術的にはできます。しかしそれをすると、箱にした意味がなくなります。中身を作り替えたときに、外側のつなぎ先も壊れるからです。

外からは必ず箱のoutputs:を指す。これはSTEP 96で「Assetの中身を直接参照しない」と言ったのと同じ約束です。

よくある間違い

まとめたつもりで、まとまっていない

NodeGraphのoutputsを作り忘れる

中にShaderを置いただけでは、外から値を取り出せません。outputs:を作り、中のShaderへconnectして初めて口になります。

外から中のShaderを直接つなぐ

動きますが、中身を作り替えると壊れます。箱の口を指します。

MaterialとNodeGraphを別物だと思う

MaterialはNodeGraphの一種です。だからMaterialにもinputs:を作れます。

UsdPreviewSurfaceとMaterialXを同時に必須だと思う

どちらか一方で構いません。交換のしやすさを取るならUsdPreviewSurface、作り込みを取るならMaterialXです。

Glossary

このレッスンの用語

NodeGraph
Shaderのまとまりを1つのPrimに閉じ込め、inputs:とoutputs:だけを外へ見せるPrim。
Interface Input
NodeGraphやMaterialが外向きに持つ入力。中身を知らずに調整するための口。
MaterialX
ツール間で見た目を持ち運ぶための標準。USD側ではNodeGraphとShaderの入れ子として表される。
ConnectableAPI
接続を扱うためのAPI。Shader・NodeGraph・Materialのいずれからも得られる。
