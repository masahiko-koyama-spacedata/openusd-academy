STEP 62 · NESTED VARIANTS

入れ子のVariant Set

選択肢の中に、さらに選択肢を置きます

今日これだけ

Variant Setは入れ子にできて 外側の選択ごとに内側の選択肢を持てる

公式情報に基づく説明

選択肢の中に、さらに選択肢を置く

STEP 43で、Variant Setが「一つのPrimに名前付きの選択肢を用意する仕組み」だと見ました。この選択肢の中身は普通のPrim記述なので、その中にもう一つVariant Setを置けます。これが入れ子（nested）のVariant Setです。

使いどころは、外側の選択によって内側の選択肢が変わる場合です。たとえば椅子のsizeを選び、そのサイズごとに用意されたcolorを選ぶ、という構造が作れます。

選択そのものはPrimのMetadataとして書かれます。variantSetsが「このPrimはどのVariant Setを持つか」、variantsが「いまどれを選んでいるか」です。入れ子の場合、内側のvariantSetsとvariantsは、外側の選択肢の中に書かれます。

OpenUSD Academy Note

入れ子にすると組み合わせの数が掛け算で増えます。sizeが2つ、colorが2つなら4通りです。すべての組み合わせを書く必要があるのは内側だけで、外側の選択肢ごとに内側を書き分けられる点が入れ子の利点です。逆に、組み合わせが独立していて掛け算にする意味がないなら、入れ子にせず同じPrimに2つのVariant Setを並べるほうが記述が減ります。

USDA

sizeの中にcolorを置く

nested.usda（抜粋）USDA
def Xform "Chair" (
    prepend variantSets = "size"
    variants = {
        string size = "small"
    }
)
{
    variantSet "size" = {
        "small" (
            prepend variantSets = "color"
            variants = {
                string color = "red"
            }
        ) {
            def Sphere "Seat"
            {
                double radius = 0.4
            }

            variantSet "color" = {
                "blue" {
                    over "Seat"
                    {
                        color3f[] primvars:displayColor = [(0.2, 0.4, 0.9)] (
                            interpolation = "constant"
                        )
                    }
                }
                "red" {
                    over "Seat"
                    {
                        color3f[] primvars:displayColor = [(0.9, 0.2, 0.2)] (
                            interpolation = "constant"
                        )
                    }
                }
            }
        }
    }
}

読み方の手がかりは入れ子の深さです。variantSet "size" = { ... }の波括弧の中に"small" ( ... ) { ... }があり、その波括弧の中にさらにvariantSet "color" = { ... }があります。丸括弧の中はMetadata、波括弧の中は中身、という読み分けはSTEP 04と同じです。

選択の組み合わせ

Python

組み合わせを切り替えて確かめる

nested_variants.pyPython
from pxr import Usd

stage = Usd.Stage.Open("nested.usda")
prim = stage.GetPrimAtPath("/Chair")

print("Variant Set:", prim.GetVariantSets().GetNames())

for size in ("small", "large"):
    for color in ("red", "blue"):
        prim.GetVariantSets().SetSelection("size", size)
        prim.GetVariantSets().SetSelection("color", color)
        seat = stage.GetPrimAtPath("/Chair/Seat")
        print("size=%-5s color=%-4s -> radius=%s color=%s"
              % (size, color,
                 seat.GetAttribute("radius").Get(),
                 seat.GetAttribute("primvars:displayColor").Get()))
実行結果Output
Variant Set: ['size', 'color']
size=small color=red  -> radius=0.4 color=[(0.9, 0.2, 0.2)]
size=small color=blue -> radius=0.4 color=[(0.2, 0.4, 0.9)]
size=large color=red  -> radius=0.8 color=[(0.9, 0.2, 0.2)]
size=large color=blue -> radius=0.8 color=[(0.2, 0.4, 0.9)]

GetNames()が['size', 'color']を返している点に注目してください。内側のVariant Setも、外側が選ばれていれば同じPrimのVariant Setとして見えます。逆に言うと、外側でlargeを選んだときにcolorを用意し忘れていれば、そこではcolorが現れません。

Beginner notes

選択は「値」ではなくMetadata

OpenUSD Academy Note

variants = { string size = "small" }は、Primの丸括弧の中に書かれるMetadataです。Attributeではないので、attr.Get()では取れません。GetVariantSets().GetVariantSelection("size")で読みます。

この選択もOpinionなので、より強いLayerが別の選択を書けば、そちらが勝ちます。Assetがsmallを選んでいても、シーン側でlargeと書けばシーンの選択が使われます。これがVariantを「下流から差し替えられる仕組み」として使える理由です。

よくある間違い

入れ子にしたのに切り替わらない

外側の選択肢の一部にだけ内側を書く

smallの中にだけcolorを作り、largeに作り忘れると、largeを選んだ瞬間にcolorが消えます。エラーにはなりません。

入れ子にする必要のないものを入れ子にする

sizeとcolorが独立なら、同じPrimに2つ並べるだけで足ります。入れ子にすると内側を選択肢の数だけ書くことになり、記述が増えます。

Variant Edit Contextの外で書く

STEP 57のとおり、選択肢の中身はGetVariantEditContext()の中で書きます。外で書くとVariantの外側、つまりどの選択でも共通の記述になります。

選択をAttributeとして探す

選択はMetadataです。GetVariantSelection()で読みます。

Glossary

このレッスンの用語

Nested Variant Set（入れ子のVariant Set）
Variantの選択肢の中に、さらに別のVariant Setを置いた構造。外側の選択ごとに内側の選択肢を変えられる。
variantSets
そのPrimがどのVariant Setを持つかを表すMetadata。
variants
いまどの選択肢を選んでいるかを表すMetadata。Opinionなので、より強いLayerが上書きできる。
GetVariantSelection
現在の選択を読むPython API。選択はAttributeではないのでGet()では取れない。
