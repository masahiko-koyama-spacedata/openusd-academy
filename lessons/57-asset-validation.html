Asset Validation

守ってほしい規則を、文章ではなくコードにします

今日これだけ

usdcheckerで一般の規則を、自前の関数でプロジェクトの規則を確かめる

公式情報に基づく説明

2種類の規則がある

アセットが守るべき規則には2種類あります。OpenUSD一般の規則と、そのプロジェクト固有の規則です。前者はusdcheckerが確かめてくれます。後者は自分で書きます。どちらも「人が目で見る」のではなく、実行できる形にしておくことが要点です。文章で決めた規則は、必ず守られなくなります。

OpenUSD Academy Note

検査を書く場所は、書き出し処理の最後です。壊れたものを配ってから気付くのではなく、配る前に止めるためにあります。受け取る側でも同じ検査を通すようにすると、どこで壊れたかがすぐ分かります。

道具1

usdchecker — 一般の規則

ターミナルコマンド
$ usdchecker tile.usda
Validation Result with no explicit variants set
Success!

問題があると、次のように内容と場所が出ます。これは実際に、先頭のMetadataを書かないファイルを検査したときの出力です。

失敗したときの出力コマンド
Error: (usdGeomValidators:StageMetadataChecker.MissingMetersPerUnitMetadata)
Stage with root layer <cp2.usda> does not specify its linear scale in metersPerUnit.
Error: (usdGeomValidators:StageMetadataChecker.MissingUpAxisMetadata)
Stage with root layer <cp2.usda> does not specify an upAxis.
Error: (usdValidation:StageMetadataChecker.MissingDefaultPrim)
Stage with root layer <cp2.usda> has an invalid or missing defaultPrim.
Failed!

終了コードが0以外になるので、そのまま自動化に組み込めます。STEP 48 Default PrimとSTEP 49 metersPerUnitで扱った3つが、ここで検査されているのが分かります。

道具2

自前の検査 — プロジェクトの規則

validate.pyPython
from pxr import Usd, UsdGeom, UsdShade

REQUIRED_INTERFACE = ("academy:assetName", "academy:version")


def check_entry_point(stage):
    """入口が約束どおりか。Payloadを開かずに済む検査。"""
    problems = []
    prim = stage.GetDefaultPrim()
    if not prim:
        return ["defaultPrim がない"]
    if not prim.GetMetadata("kind"):
        problems.append("kind がない")
    if not prim.HasAuthoredPayloads():
        problems.append("中身へのPayloadがない")
    for name in REQUIRED_INTERFACE:
        if not prim.GetAttribute(name).HasAuthoredValue():
            problems.append("%s がない" % name)
    return problems


def check_geometry(stage):
    """形が壊れていないか。中身を開いて確かめる検査。"""
    problems = []
    for prim in stage.Traverse():
        if not prim.IsA(UsdGeom.Mesh):
            continue
        mesh = UsdGeom.Mesh(prim)
        counts = mesh.GetFaceVertexCountsAttr().Get() or []
        indices = mesh.GetFaceVertexIndicesAttr().Get() or []
        points = mesh.GetPointsAttr().Get() or []

        if sum(counts) != len(indices):
            problems.append("%s: faceVertexIndices の長さが合わない" % prim.GetPath())
        if len(indices) and max(indices) >= len(points):
            problems.append("%s: 範囲外のpoint番号がある" % prim.GetPath())
        if not UsdShade.MaterialBindingAPI(prim).ComputeBoundMaterial()[0]:
            problems.append("%s: Materialが結び付いていない" % prim.GetPath())
    return problems

2つに分けているのは、かかる時間が違うからです。入口の検査はLoadNoneで一瞬で終わるので、大量のアセットに対して回せます。形の検査は中身を開くので重く、書き出しの直後だけに絞ります。

結果

実際に走らせる

run_validation.pyPython
from pxr import Usd

light = Usd.Stage.Open("lamp.usda", Usd.Stage.LoadNone)
print(check_entry_point(light))
# []                        … 入口は約束どおり

heavy = Usd.Stage.Open("tile.usda")
print(check_geometry(heavy))
# []                        … 形も壊れていない

broken = Usd.Stage.Open("lamp_geom.usda", Usd.Stage.LoadNone)
print(check_entry_point(broken))
# ['kind がない', '中身へのPayloadがない',
#  'academy:assetName がない', 'academy:version がない']

正しいものは空のリスト、そうでないものは理由のリストが返ります。lamp_geom.usdaは形を作る担当のファイルで、そもそも単体で配るものではありません。検査が「これは配れない」と言ってくれるのが、この形の価値です。

Beginner notes

Stageを変数に持っておく

OpenUSD Academy Note

検査を書いていると、次のような書き方をしたくなります。

counts = [len(list(Usd.Stage.Open(p).Traverse())) for p in paths]   # 失敗する

これはRuntimeError: Invalid range starting with expired primで落ちます。Usd.Stage.Open()の戻り値をどこにも保持していないため、走査している途中でStageが片付けられてしまうからです。Stageは必ず変数に受けてから使う、と覚えてください。実際に手元で踏んだ失敗です。

よくある間違い

検査を後回しにする

規則を文章だけで決める

守られているかを誰も確かめられません。実行できる関数にします。

重い検査を毎回全部に回す

時間がかかりすぎて、結局回されなくなります。軽い検査と重い検査を分けます。

usdcheckerだけで十分だと考える

プロジェクト固有の約束（入口の名乗りなど）は検査されません。自分で書きます。

Stageを変数に持たずに走査する

途中で片付けられて例外になります。
