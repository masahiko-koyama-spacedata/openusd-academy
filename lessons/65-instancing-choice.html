STEP 93 · INSTANCING

ScenegraphとPointの選択

2つのInstancingを、用途で選び分けます

今日これだけ

一つずつ指したいならScenegraph、数を優先するならPoint

公式情報に基づく説明

決定的な違いはPathを持つかどうか

STEP 86 Scenegraph Instancingで置いた一つ一つは、Pathを持つPrimです。選んだり、overで上書きしたり、走査で見つけたりできます。STEP 91 Point Instancingで置いた一つ一つは、配列の要素にすぎません。Pathを持たないため、個別に指すことができません。この違いが、そのまま選び方の基準になります。

OpenUSD Academy Note

「どちらが速いか」で選ぶと迷います。まず「一つずつ触る必要があるか」で決めてください。触る必要があるならScenegraph、無いならPointです。速さは、そのうえで数が問題になったときに考えます。

選び方の分かれ道

結果

同じ「軽くする」でも中身が違う

これまでのレッスンで実際に測った数字を並べます。どちらもPrimの数は大きく減りますが、減り方の意味が違います。

compare.py の出力Output
# Scenegraph Instancing — 椅子4脚
instanced.usda      : Prim 6個   （instanceable なし版は 14個）
  /World/Chair_1 … Path を持つ。over で上書きできる
  Prototype 1つを4つで共有

# Nested Instancing — 3列 x 3脚 = 9脚
nested.usda         : Prim 5個
  Prototype 2つ（椅子の中身、列の中身）

# Point Instancing — 15配置
point-instancer.usda: Prim 6個
  個々の配置は Path を持たない。配列の要素

Scenegraphは「中身を共有しつつ、置いたものはPrimのまま」です。Pointは「置いたものがそもそもPrimではない」ので、数を増やしてもPrimは増えません。

比較

できること・できないこと

Point Instancingでも、向き（orientations）・大きさ（scales）・色（primvars）は配列で個体差を付けられます。できないのは「特定の1個をPathで指してoverで編集する」ことです。idsやinvisibleIdsで個体を識別したり隠したりする手段は別にあります。

USDA

同じ目的を2通りで書く

Scenegraph — 1つずつPrimとして置くUSDA
def "Chair_1" (
    references = @instance-chair.usda@
    instanceable = true
)
{
    double3 xformOp:translate = (-2.4, 0, 0)
    uniform token[] xformOpOrder = ["xformOp:translate"]
}
Point — 配列でまとめて置くUSDA
def PointInstancer "Scatter"
{
    rel prototypes = [ </World/Scatter/Prototypes/Box> ]
    point3f[] positions = [(-2.4, 0, 0), (-0.8, 0, 0), (0.8, 0, 0)]
    int[] protoIndices = [0, 0, 0]
}

Scenegraphは「置く数だけPrimを書く」、Pointは「置く数だけ配列の要素を書く」です。3個なら手間は変わりませんが、3万個になると書き方も読み込み方もまったく違ってきます。

Python

どちらで置かれているか調べる

which_instancing.pyPython
from pxr import Usd, UsdGeom


def describe(stage):
    for prim in stage.Traverse():
        if prim.IsInstance():
            print("Scenegraph Instance:", prim.GetPath(),
                  "-> Prototype", prim.GetPrototype().GetPath())
        elif prim.IsA(UsdGeom.PointInstancer):
            pi = UsdGeom.PointInstancer(prim)
            print("PointInstancer     :", prim.GetPath(),
                  "配置数", len(pi.GetPositionsAttr().Get()))


describe(Usd.Stage.Open("instanced.usda"))
describe(Usd.Stage.Open("point-instancer.usda"))

受け取ったシーンがどちらで組まれているかは、IsInstance()とIsA(UsdGeom.PointInstancer)で判別できます。編集を頼まれたときは、まずこれを確認してから手を付けます。Point Instancingで組まれていれば、個別の編集は依頼として成立しないと分かります。

Beginner notes

途中で乗り換えるのは高くつく

OpenUSD Academy Note

ScenegraphからPointへ移すと、それまで書いていた個別のoverがすべて無効になります。逆にPointからScenegraphへ移すと、配置の数だけPrimを作ることになります。どちらも作り直しに近い作業です。だからこの判断は、STEP 85 Asset Modularityと同じく、なるべく早い段階で決めておきます。

よくある間違い

速さだけで選ぶ

とにかく軽いからPointにする

あとで「この1本だけ差し替えたい」と言われたときに、Pathが無いのでoverでは応えられません。触る予定があるならScenegraphです。

数が増えてもScenegraphのまま置き続ける

どこから重くなるかはシーン・Renderer・機材で変わるので、実際に測って判断します。個別に触らないなら、Pointにするか、STEP 87 Nested Instancingで入れ子にします。

PointInstancerの中身をoverで直そうとする

配置はPrimではないので、Pathがありません。直すのは配列そのものです。

両方を同じシーンで混ぜて把握できなくなる

混ぜること自体は問題ありませんが、どちらで置かれているかを判別できるようにしておきます。

Glossary

このレッスンの用語

Scenegraph Instancing
Pathを持つPrimとして置き、中身をPrototypeで共有する方式。
Point Instancing
配列で位置と種類を並べ、Primを増やさずに置く方式。
orientations / scales
PointInstancerで、向きと大きさを配置ごとに指定する配列。
IsA
そのPrimが指定したSchemaの型かどうかを判定するPython API。
