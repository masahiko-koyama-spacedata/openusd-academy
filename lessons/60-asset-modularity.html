Asset Modularity

どこまでを一つのまとまりにするかを決めます

今日これだけ

再利用の単位を決めることが、共有できる範囲を決める

公式情報に基づく説明

まとまりの切り方が、あとの全部に効いてくる

OpenUSDでは、独立したファイルとして参照できるまとまりをAssetと呼びます。どこで切るかは自由ですが、その切り方が「どこを差し替えられるか」「どこを共有できるか」「どこまでLoadを遅らせられるか」をそのまま決めます。STEP 62 componentで扱ったKindは、この切り方をシーンの中で宣言する仕組みです。

OpenUSD Academy Note

細かく切りすぎるとファイルと参照が増えて管理が重くなり、粗く切りすぎると一部だけ差し替えたいときに丸ごと作り直すことになります。判断の基準は一つで、「これは単体で置かれることがあるか」です。単体で置くなら独立したAsset、必ず親と一緒にしか出てこないなら親の一部にします。

Diagram

切り方が決める3つのこと

USDA

椅子を一つのAssetとして切る

instance-chair.usdaUSDA
#usda 1.0
(
    defaultPrim = "Chair"
    metersPerUnit = 1
    upAxis = "Y"
)

def Xform "Chair"
(
    kind = "component"
)
{
    def Cube "Seat"
    {
        double size = 0.8
        color3f[] primvars:displayColor = [(0.15, 0.35, 0.85)]
    }

    def Cube "Back"
    {
        double size = 0.8
        color3f[] primvars:displayColor = [(0.2, 0.7, 0.3)]
        double3 xformOp:translate = (0, 0.8, -0.3)
        double3 xformOp:scale = (1, 1, 0.25)
        uniform token[] xformOpOrder = ["xformOp:translate", "xformOp:scale"]
    }
}

この1ファイルが「椅子」というまとまりです。3つの印が付いています。defaultPrimで入口を示し、kind = "component"で再利用の単位だと宣言し、座面と背もたれはその内部として閉じています。STEP 56 Encapsulationで扱ったとおり、外からはChairだけを見ます。

このUSDAファイルを開く

結果

切ったから、置き方を選べる

椅子を独立したAssetにしたことで、この先の選択肢が開きます。

逆に、椅子を切らずに会場のファイルへ直接書いてしまうと、この4つのどれも選べません。共有もLoad制御も、まとまりの単位に対してしか効かないためです。

Python

切り方が正しいかを確かめる

check_modularity.pyPython
from pxr import Sdf, Usd

layer = Sdf.Layer.FindOrOpen("instance-chair.usda")
print(layer.defaultPrim)          # Chair … 入口がある

stage = Usd.Stage.Open("instance-chair.usda")
chair = stage.GetPrimAtPath("/Chair")

print(Usd.ModelAPI(chair).GetKind())   # component … 再利用の単位だと宣言されている
print(chair.IsModel())                 # True

# 単体で開いて成立するか（他のファイルに依存していないか）
print([str(p.GetPath()) for p in stage.Traverse()])
# ['/Chair', '/Chair/Seat', '/Chair/Back']

Assetとして切れているかは、この3つで確かめられます。入口があるか、Kindが宣言されているか、単体で開いて成立するかです。単体で開いたときに何かが欠ける場合、そのファイルはまだ独立したAssetになっていません。

Beginner notes

粒度の目安

OpenUSD Academy Note

迷ったときの目安です。単体で置かれるもの（椅子、机、木、車）は独立したAssetにします。必ず親と一緒のもの（椅子のネジ1本、机の脚）は親の中に入れます。まとまりとして繰り返すもの（椅子3脚の列、部屋一式）は、部品のAssetを参照する別のAssetにします。この3段階は、そのままcomponent・内部Prim・assemblyというKindの区別に対応します。

よくある間違い

切り方を後回しにする

全部を1ファイルに書く

共有もLoad制御も差し替えもできません。あとから切り直すと、参照している側を全部直すことになります。

部品ごとに細かく切りすぎる

ファイルと参照が増え、どれが入口か分からなくなります。単体で置かれないものは切りません。

入口を決めずにファイルだけ分ける

defaultPrimが無いと、使う側が内部のPathを名指しすることになります。

Kindを付け忘れる

ファイルとしては分かれていても、シーンの中で「ここが再利用の単位」と伝わりません。

Glossary

このレッスンの用語

Asset
独立して参照できるまとまり。多くは1ファイル。
Asset Modularity
どこで切ってAssetにするかという設計上の判断。
再利用の単位
差し替え・共有・Loadの制御が効く最小のまとまり。
粒度（granularity）
まとまりの細かさ。細かすぎても粗すぎても扱いにくくなる。
