Prim Hierarchy Transformation

受け取った階層を、こちらの流儀へ組み替えます

今日これだけ

階層を変えるときは、位置と結び付きを保ったまま移す

公式情報に基づく説明

相手の階層とこちらの規則は違う

他のツールから来たデータは、その道具の都合で階層が組まれています。STEP 88 Converterの構造で決めたとおり、こちらには「形はGeomの下、見た目はLooksの下」といった規則があります。この差を埋める処理がPrim Hierarchy Transformationです。単に名前を変えるだけでなく、Pathが変わることで壊れるものに注意が要ります。

OpenUSD Academy Note

Pathが変わると、そのPathを指していたものがすべて外れます。STEP 06 Relationshipのtarget、STEP 90 Material Binding、STEP 49 Referenceの行き先などです。組み替えのバグの大半は、移すのを忘れた参照から生まれます。

Python

作り直すのがいちばん安全

rebuild_hierarchy.pyPython
from pxr import Sdf, Usd, UsdGeom, UsdShade


def rebuild(src_path, dst_path, asset_name):
    """入力のStageを読み、こちらの規則の階層へ組み直して書き出す。"""
    src = Usd.Stage.Open(src_path)
    dst = Usd.Stage.CreateNew(dst_path)
    UsdGeom.SetStageMetersPerUnit(dst, UsdGeom.GetStageMetersPerUnit(src))
    UsdGeom.SetStageUpAxis(dst, UsdGeom.GetStageUpAxis(src))

    root = UsdGeom.Xform.Define(dst, "/" + asset_name)
    dst.SetDefaultPrim(root.GetPrim())
    geom = UsdGeom.Scope.Define(dst, root.GetPath().AppendChild("Geom"))
    looks = UsdGeom.Scope.Define(dst, root.GetPath().AppendChild("Looks"))

    moved = {}                      # 旧Path -> 新Path
    for prim in src.Traverse():
        if prim.IsA(UsdGeom.Mesh):
            dest = geom.GetPath().AppendChild(prim.GetName())
        elif prim.IsA(UsdShade.Material):
            dest = looks.GetPath().AppendChild(prim.GetName())
        else:
            continue
        Sdf.CopySpec(src.GetRootLayer(), prim.GetPath(),
                     dst.GetRootLayer(), dest)
        moved[prim.GetPath()] = dest

    dst.Save()
    return dst, moved

Sdf.CopySpecは、記述をそのまま別のPathへ写します。値を一つずつ読み書きするより確実で、書き忘れが起きません。戻り値のmovedに旧Pathと新Pathの対応を残しているのが要点で、このあとの付け替えに使います。

OpenUSD Academy Note

この関数は最初、Meshだけを移すように書いていました。動かしてみると/Rebuilt/Geom/Panel.material:binding → /Tile/Looks/Paintという、存在しないPathを指したBindingが残りました。Materialを移していなかったからです。例外も警告も出ません。移す対象を数え落とすと、こうして静かに壊れます。だから移動の対応表と、最後の検査の両方が要ります。

Python

指していたものを付け替える

fix_targets.pyPython
from pxr import Usd, UsdShade


def fix_relationships(stage, moved):
    """移動でずれたRelationshipのtargetを、新しいPathへ差し替える。"""
    fixed = 0
    for prim in stage.Traverse():
        for rel in prim.GetRelationships():
            targets = rel.GetTargets()
            if not targets:
                continue
            new = [moved.get(t, t) for t in targets]
            if new != list(targets):
                rel.SetTargets(new)
                fixed += 1
    return fixed


def check_bindings(stage):
    """付け替え漏れがないかを確かめる。"""
    broken = []
    for prim in stage.Traverse():
        for rel in prim.GetRelationships():
            for target in rel.GetTargets():
                if not stage.GetPrimAtPath(target.GetPrimPath()):
                    broken.append("%s -> %s" % (rel.GetPath(), target))
    return broken

GetRelationships()ですべてのRelationshipを回れます。STEP 90 Material BindingもRelationshipなので、この処理で一緒に直ります。最後にcheck_bindingsを通し、存在しないPathを指しているものが残っていないかを確かめます。

実際に走らせた結果Python
dst, moved = rebuild("tile.usda", "out.usda", "Rebuilt")

print(moved)
# {'/Tile/Looks/Paint': '/Rebuilt/Looks/Paint',
#  '/Tile/Geom/Panel': '/Rebuilt/Geom/Panel'}

print(check_bindings(dst))
# ['/Rebuilt/Geom/Panel.material:binding -> /Tile/Looks/Paint']
#   写しただけでは、まだ古いPathを指している

print(fix_relationships(dst, moved))   # 1
print(check_bindings(dst))             # []   … 直った

print(UsdShade.MaterialBindingAPI(
    dst.GetPrimAtPath("/Rebuilt/Geom/Panel")).ComputeBoundMaterial()[0].GetPath())
# /Rebuilt/Looks/Paint

写した直後は、まだ古いPathを指したままです。fix_relationshipsを通して初めて新しいPathへ向き、check_bindingsが空になります。写す・付け替える・確かめるの3つで一組だと考えてください。

tile.usda（抜粋・入力）USDA
def Xform "Tile"
{
    def Scope "Looks"
    {
        def Material "Paint"
        {
            token outputs:surface.connect = </Tile/Looks/Paint/Surface.outputs:surface>
        }
    }

    def Scope "Geom"
    {
        def Mesh "Panel" (
            prepend apiSchemas = ["MaterialBindingAPI"]
        )
        {
            rel material:binding = </Tile/Looks/Paint>
        }
    }
}

この階層を/Rebuilt以下へ組み直します。注目するのはrel material:bindingの値が</Tile/Looks/Paint>という絶対Pathである点です。Meshだけを写すと、この行だけが古い場所を指したまま残ります。角括弧の外にある丸括弧はMetadata、波括弧の中はProperty、< >で囲まれているのがPathです。

Beginner notes

移すより、作り直すほうが安全

OpenUSD Academy Note

既にあるStageの中でPrimを動かす方法もありますが、Converterでは読み込んで、新しいStageへ組み直すほうが安全です。入力側を壊さずに済み、失敗しても出力を捨てるだけで戻せます。STEP 48 rElocatesのようにComposition側でPathを移す仕組みもありますが、それは「参照した先の階層を、参照する側で付け替える」ための機能で、Converterの用途とは別です。

よくある間違い

形だけ移して満足する

Relationshipのtargetを直し忘れる

Material Bindingも含めて外れます。移動の対応表を持ち、まとめて付け替えます。

親の変換を引き継がずに移す

元の親が持っていたxformOpが付いてこないと、位置がずれます。移す先で同じ変換を持たせるか、値を焼き込みます。

単位と上方向を写し忘れる

新しいStageには何も設定されていません。入力から読んで設定します。

付け替え漏れを確かめない

存在しないPathを指すRelationshipは、エラーにならず静かに効かなくなります。最後に必ず検査します。
