    payload = @./contents.usda@</Robot>

#usda 1.0はUSDAヘッダーです。引用符は名前や文字列、波括弧はPrim内容、丸括弧はMetadata、/はPrim Pathの階層を表します。インデントは所属を読みやすくするためにそろえます。

結果

どのOpinionが見えるか

LoadNoneではPayload内容を辿らず、Load後に内容が合成されます。入口LayerのLocal情報はPayloadより強く、未ロードでも見せる設計にできます。

Python

合成結果をAPIで確認する

inspect.pyPython
from pxr import Usd
stage = Usd.Stage.Open("payload.usda", load=Usd.Stage.LoadNone)
robot = stage.GetPrimAtPath("/Robot")
print(robot.IsLoaded())
robot.Load()
print(robot.IsLoaded())

ピリオドはオブジェクトの機能へ進む記号、丸括弧は関数への入力、引用符はPathやファイル名、字下げはPythonの処理範囲を表します。

例題

用途を判断する

問題: 重いcontents.usdaをAssetの入口から必要時だけロードする

答え: P · Payloads。大きなGeometryなど、Stageを開いた時点では不要な内容を作業集合から外したい場面。

公式の論点を残す

Arcは残り、内容を辿るかを制御する

公式: PayloadはReferenceと同様にExternalまたはInternalのPrimを対象にできますが、Load・UnloadでCompositionに内容を含めるか制御できます。Usd.Stage.Open(..., load=Usd.Stage.LoadNone)ではPayload Arc自体は記録されても、その先の内容を最初から辿りません。

公式: LoadはPrim単位で作業集合を制御します。ReferenceとPayloadの主な使い分けは「弱いから」ではなく、内容を遅延ロードする必要があるかです。Prim Pathを省略するExternal PayloadでもdefaultPrimが入口になります。

OpenUSD Academy Note

入口Layerには名前やBoundsなど、Payloadを開く前にも必要な情報を置き、重いGeometryをPayload側へ分ける設計があります。

よくある間違い

Referenceより弱いからPayloadを選ぶ

誤解

原因: Arcの役割と強度順序を混同しています。

解決策: 主な選択理由はロード制御です。強度差だけで置き換えず、アセットの入口と重い内容を分けます。
