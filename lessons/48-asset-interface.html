Asset Interface

外へ見せる情報だけを、入口に並べます

今日これだけ

入口に書いたものが約束。書かなかったものは内部実装

公式情報に基づく説明

公開する面を意識して決める

AssetのSTEP 82 Entry Pointに置いた情報の集まりを、Asset Interfaceと呼びます。使う側が読んだり変えたりしてよいのはここだけ、という約束です。名前・バージョン・種別のようなidentityと、外から調整してよいparameterの2種類を置きます。中身のPathやPrim名はInterfaceに含めません。

OpenUSD Academy Note

プログラムの公開APIと同じ考え方です。「公開したものは簡単に変えられない、公開していないものは自由に変えられる」という性質があるので、迷ったら公開しないのが原則です。あとから足すのは簡単ですが、あとから消すのは使っている側を壊します。

USDA

identityとparameterを分けて置く

lamp.usda — Interfaceの部分USDA
def Xform "Lamp" (
    kind = "component"
    payload = @lamp_contents.usda@</Lamp>
)
{
    custom string academy:assetName = "Lamp"
    custom string academy:version = "1.0"

    double3 xformOp:translate = (0, 0, 0)
    uniform token[] xformOpOrder = ["xformOp:translate"]
}

ここに並んでいるものだけが、外から見える面です。kindは種別、academy:assetNameとacademy:versionはidentity、xformOpは置き場所を決めるためのものです。中身のBase・Stem・Shadeという名前は、どこにも出てきません。

確かめる

Interfaceだけを一覧にする

list_interface.pyPython
from pxr import Usd

stage = Usd.Stage.Open("scene.usda", Usd.Stage.LoadNone)
lamp = stage.GetPrimAtPath("/World/Lamp_1")

print("kind      :", lamp.GetMetadata("kind"))
for name in lamp.GetAuthoredPropertyNames():
    print("%-24s %s" % (name, lamp.GetAttribute(name).Get()))

# kind      : component
# academy:assetName        Lamp
# academy:version          1.0
# xformOp:translate        (-1.4, -1, 0)
# xformOpOrder             [xformOp:translate]

Payloadを開いていない状態で読めるものが、そのままInterfaceです。GetAuthoredPropertyNames()を使うと、Schemaが持つだけで書かれていないものを除いて、実際に公開しているものだけが並びます。この一覧が「使う側との約束」だと考えてください。

Python

Interfaceを検査する仕組みにする

check_interface.pyPython
from pxr import Usd

REQUIRED = ("academy:assetName", "academy:version")


def check_interface(path):
    """入口だけを開いて、約束どおりの情報があるかを確かめる。"""
    stage = Usd.Stage.Open(path, Usd.Stage.LoadNone)
    prim = stage.GetDefaultPrim()
    problems = []

    if not prim:
        return ["defaultPrim がない"]
    if not prim.GetMetadata("kind"):
        problems.append("kind がない")
    for name in REQUIRED:
        if not prim.GetAttribute(name).HasAuthoredValue():
            problems.append("%s がない" % name)
    return problems


print(check_interface("lamp.usda"))    # []

Interfaceを決めたら、その約束を守っているかを機械で確かめられるようにします。Usd.Stage.LoadNoneで開いているので、中身がどれだけ重くても一瞬で終わります。この検査はこのあと扱うAsset Validationで扱う仕組みの、いちばん小さな形です。

Beginner notes

Namespaceを決めておく

OpenUSD Academy Note

独自に足す情報には、必ず自分たちのNamespaceを付けます（ここではacademy:）。STEP 10 Custom Propertiesで扱ったとおり、短い名前は将来Schemaとぶつかります。プロジェクトの最初にNamespaceを1つ決めて、Interfaceに置くものはすべてその下に並べると、あとから「どれが自前の約束か」が一目で分かります。

よくある間違い

公開する面が広がりすぎる

内部のPrim名を使わせてしまう

一度使われると、中の名前を変えられなくなります。中を指す必要があるなら、Interfaceに専用のRelationshipを用意します。

迷ったものをとりあえず公開する

公開は取り消しにくい判断です。迷ったら公開しません。

Namespaceを付けずに独自の値を足す

将来のSchemaとぶつかります。

identityをPayloadの中に置く

中身を開かないと読めなくなり、入口を薄くした意味がなくなります。

Glossary

このレッスンの用語

Asset Interface
Assetが外へ公開する情報の集まり。使う側との約束。
identity
そのAssetが何であるかを示す情報。名前・バージョン・種別など。
parameter
使う側が調整してよい値。
内部実装
公開していない部分。Prim名や階層の形など、自由に変えてよいもの。
HasAuthoredValue
そのAttributeに値が実際に書かれているかを返すPython API。
