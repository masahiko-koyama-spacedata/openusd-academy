公式情報に基づく説明

同じ形を、用途で描き分ける

重いAssetを扱うと、確認のたびに数百万ポリゴンを描くのは現実的ではありません。かといって、最終画では正確な形が要ります。1つのAssetの中に、用途の違う複数の形を入れておき、場面に応じて描き分けるための仕組みがpurposeです。

purposeはすべてのImageableが持つuniform tokenで、値は4つです。

値意味使いどころ
default（既定）用途を限定しない。常に描かれる普通の形
render最終描画のときだけ描く正確で重い形
proxy確認のときだけ描く軽い代役の形
guide作業用の補助表示基準線・当たり判定の可視化

大事なのは子孫へ受け継がれることです。renderを親に書けば、その下のGprimはすべてrenderになります。1つずつ書く必要はありません。

OpenUSD Academy Note

purposeとvisibilityは混同しやすいですが、軸が違います。visibilityは「見せるか見せないか」、purposeは「どの用途のときに描くか」です。proxyのPrimはvisibility = inheritedのままでも、最終描画では描かれません。逆に、purpose = renderのPrimをinvisibleにすれば、最終描画でも消えます。2つは独立して効きます。

USDA

重い形と軽い代役を、同じAssetに入れる

purpose.usda（抜粋）USDA
def Xform "Hero" (
    kind = "component"
)
{
    rel proxyPrim = </Hero/Proxy>

    # 最終描画用。正確だが重い
    def Mesh "Render"
    {
        uniform token purpose = "render"
    }

    # 確認用。軽い代役
    def Cube "Proxy"
    {
        uniform token purpose = "proxy"
        double size = 1
    }
}

rel proxyPrimは、このHeroの代役がどれかを指すRelationshipです。STEP 06で見たとおり< >で囲むのがPathです。これを書いておくと、代役を使う側が「どれを描けばよいか」をたどれます。purposeの指定だけでも描き分けはできますが、対応関係を明示するために書きます。

このUSDAファイルを開く

Python

継承と、解決された結果を見る

check_purpose.pyPython
from pxr import Usd, UsdGeom

stage = Usd.Stage.CreateNew("purpose.usda")
hero = UsdGeom.Xform.Define(stage, "/World/Hero")
hi = UsdGeom.Mesh.Define(stage, "/World/Hero/Render")
hi.CreatePurposeAttr("render")
lo = UsdGeom.Cube.Define(stage, "/World/Hero/Proxy")
lo.CreatePurposeAttr("proxy")
hero.CreateProxyPrimRel().SetTargets(["/World/Hero/Proxy"])
sub = UsdGeom.Mesh.Define(stage, "/World/Hero/Render/Sub")

print("Render      :", hi.ComputePurpose())
print("Proxy       :", lo.ComputePurpose())
print("Render/Sub  :", sub.ComputePurpose(), "← 親から継ぐ")
print("Hero(未指定) :", hero.ComputePurpose())
print("proxyPrim   :", [str(t) for t in hero.GetProxyPrimRel().GetTargets()])
実行結果Output
Render      : render
Proxy       : proxy
Render/Sub  : render ← 親から継ぐ
Hero(未指定) : default
proxyPrim   : ['/World/Hero/Proxy']

Render/Subにはpurposeを書いていませんが、renderが返っています。親のRenderから受け継いだためです。ComputePurpose()は、この継承をたどった解決後の値を返します。書いた値だけを見たいならGetPurposeAttr().Get()です。

ツールでの切り替え

どのpurposeを描くかは、見る側が決める

ターミナルコマンド
# usdview では Display メニューから purpose ごとに表示を切り替える
$ usdview purpose.usda

# usdrecord の purposes 指定（既定は default と proxy）
$ usdrecord --purposes render purpose.usda out.png

purposeを書いても、それだけでは何も変わりません。描く側が「今回はどの用途か」を選んで初めて効きます。usdviewの既定はdefaultとproxyで、renderは表示されません。「renderにしたら消えた」というのは、この既定のためです。

USDA → Python mapping

行ごとに対応させる

  1. USDA

    uniform token purpose = "render"↓

    Python

    imageable.CreatePurposeAttr(UsdGeom.Tokens.render)

  2. USDA

    rel proxyPrim = </Hero/Proxy>↓

    Python

    hero.CreateProxyPrimRel().SetTargets(["/World/Hero/Proxy"])

  3. USDA

    （継承をたどった結果が知りたい）↓

    Python

    imageable.ComputePurpose()

  4. USDA

    uniform token visibility = "invisible"↓

    Python

    imageable.CreateVisibilityAttr("invisible")

Beginner notes

Assetの入口にはpurposeを書かない

OpenUSD Academy Note

purposeは子孫へ受け継がれるので、Assetの一番上のPrimにrenderと書くとそのAsset全体が最終描画専用になります。代役を入れる余地が無くなり、確認のときに何も見えなくなります。

書く場所は、用途の分かれる枝の根元です。/Hero/Renderと/Hero/Proxyのように分けて、/Hero自身はdefaultのままにします。

よくある間違い

描かれない理由を取り違える

purposeを書いたのに切り替わらない

描く側が用途を選んでいなければ効きません。usdviewのDisplayメニュー、usdrecord --purposesを確認します。

renderにしたら消えたので壊れたと思う

usdviewの既定はdefaultとproxyです。renderは表示対象に入っていません。正しい動作です。

visibilityで代役を切り替える

visibilityはファイルに書く値なので、見る人ごとに変えられません。用途で切り替えたいならpurposeです。

Assetのrootにpurposeを書く

子孫全部に効きます。用途が分かれる枝の根元に書きます。

proxyPrimさえ書けば代役になると思う

proxyPrimは対応関係を示すRelationshipです。描き分けを決めるのはpurposeのほうです。

Glossary

このレッスンの用語

purpose
どの用途のときに描くかを表すAttribute。default・render・proxy・guideの4つ。子孫へ受け継がれる。
render（purpose）
最終描画のときだけ描く指定。正確で重い形に付ける。
proxy（purpose）
確認のときだけ描く指定。軽い代役の形に付ける。
guide（purpose）
作業用の補助表示。基準線や当たり判定の可視化に使う。
proxyPrim
代役がどのPrimかを指すRelationship。対応関係を明示するために書く。
ComputePurpose
継承をたどった結果のpurposeを返すPython API。
Imageable
描画に関わる性質を持つPrimの抽象Schema。purposeとvisibilityはここが定める。
