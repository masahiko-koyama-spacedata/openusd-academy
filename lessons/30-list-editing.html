List Editing

一覧を丸ごと置き換えずに、足す・消す・並べ替えます

今日これだけ

prepend・append・delete・reorderは一覧を部分的に編集する

公式情報に基づく説明

一覧を持つ項目だけの特別な書き方

OpenUSDには、値ではなく一覧を持つ項目がいくつかあります。STEP 09 Relationshipのtarget、STEP 40 references、STEP 37 inherits、STEP 41 payload、specializes、apiSchemasなどです。こうした一覧に対しては、上のLayerからprepend（先頭へ足す）、append（末尾へ足す）、delete（取り除く）、reorder（並べ替える）という編集を書けます。この仕組みをList Editingと呼びます。

OpenUSD Academy Note

キーワードを付けずにrel members = ...と書くと、下のLayerの一覧を丸ごと置き換えます。これをexplicitな記述と呼びます。他の人が下のLayerで足した項目まで消えてしまうため、共同作業ではprependやappendを使うほうが安全です。

USDA

土台の一覧を用意する

list-base.usda（抜粋）USDA
def Xform "World"
{
    def Scope "Team"
    {
        custom rel members = [
            </World/A>,
            </World/B>,
        ]
    }

    def Cube "A"
    {
        double size = 1
    }

    ... B, C, D も同様に定義 ...
}

この時点のmembersは[A, B]です。

このUSDAファイルを開く

USDA

3種類の編集を同時に書く

list-edited.usdaUSDA
#usda 1.0
(
    defaultPrim = "World"
    metersPerUnit = 1
    subLayers = [
        @list-base.usda@
    ]
    upAxis = "Y"
)

over "World"
{
    over "Team"
    {
        prepend rel members = </World/C>
        append rel members = </World/D>
        delete rel members = </World/A>
    }
}

キーワードは型名relの前に置きます。同じProperty名に対して、3種類の編集を並べて書けます。

このUSDAファイルを開く

結果

合成すると [C, B, D] になる

check_list.pyPython
from pxr import Usd

base = Usd.Stage.Open("list-base.usda")
print(base.GetPrimAtPath("/World/Team").GetRelationship("members").GetTargets())
# [Sdf.Path('/World/A'), Sdf.Path('/World/B')]

edited = Usd.Stage.Open("list-edited.usda")
print(edited.GetPrimAtPath("/World/Team").GetRelationship("members").GetTargets())
# [Sdf.Path('/World/C'), Sdf.Path('/World/B'), Sdf.Path('/World/D')]

順を追うと、まず土台の[A, B]からdeleteでAが消えて[B]になり、prependでCが先頭に付いて[C, B]、appendでDが末尾に付いて[C, B, D]です。

Diagram

4つのキーワードの働き

確かめる

explicitとreorderの違い

同じ土台に対して、キーワードを変えるとどうなるかを実際に確かめた結果です。

explicitな記述USDA
        rel members = </World/D>

合成結果は[D]です。土台の[A, B]は完全に消えます。

reorderの記述USDA
        reorder rel members = [</World/B>, </World/A>]

合成結果は[B, A]です。項目は増えも減りもせず、順番だけが入れ替わります。

Python

Sdfから一覧の中身を見る

inspect_list.pyPython
from pxr import Sdf

layer = Sdf.Layer.FindOrOpen("list-edited.usda")
spec = layer.GetPropertyAtPath("/World/Team.members")
targets = spec.targetPathList

print(targets.isExplicit)        # False
print(list(targets.explicitItems))    # []
print(list(targets.prependedItems))   # [Sdf.Path('/World/C')]
print(list(targets.appendedItems))    # [Sdf.Path('/World/D')]
print(list(targets.deletedItems))     # [Sdf.Path('/World/A')]
print(list(targets.orderedItems))     # []

List Editingの中身は、Sdf側のListOpとして5つの入れ物に分かれて保存されています。isExplicitがTrueのときはexplicitItemsだけが使われ、他の4つは無視されます。RelationshipならtargetPathList、ReferenceならreferenceListのように、項目ごとに名前が違います。

USDA → Python mapping

行ごとに対応させる

  1. USDA

    prepend rel members = </World/C>↓

    Python

    rel.AddTarget(path, Usd.ListPositionFrontOfPrependList)

  2. USDA

    append rel members = </World/D>↓

    Python

    rel.AddTarget(path, Usd.ListPositionBackOfAppendList)

  3. USDA

    delete rel members = </World/A>↓

    Python

    rel.RemoveTarget(path)

  4. USDA

    rel members = ...（explicit）↓

    Python

    rel.SetTargets([...])

Beginner notes

なぜ順番が大事なのか

OpenUSD Academy Note

Relationshipのtargetでは、順番は「対象の並び」という意味しか持ちません。しかしreferencesやinheritsでは、先に書かれたものほど強いという規則があります。だからprependは「今までのどれより強くする」、appendは「今までのどれより弱くする」という意味になります。STEP 34で扱った強度の話が、ここで具体的な書き方として出てきます。

よくある間違い

explicitで他人の記述を消してしまう

キーワードを付けずに書く

rel members = ...は置き換えです。下のLayerで他の人が足した項目も消えます。足したいだけならprependかappendを使います。

キーワードを型名の後ろに置く

rel prepend membersとは書けません。キーワードはprepend rel membersのように、いちばん前に置きます。

reorderで項目を足そうとする

reorderは既にある項目の順番を変えるだけです。一覧に無いPathを書いても追加されません。

deleteしたのに残っていると悩む

deleteが効くのは、より弱いLayerが持つ項目に対してです。同じLayerの中でappendとdeleteの両方に同じPathを書いた場合の結果は直感的でないため、避けてください。

Glossary

このレッスンの用語

List Editing
一覧を持つ項目に対して、部分的な追加・削除・並べ替えを記述する仕組み。
prepend
一覧の先頭へ項目を足すキーワード。
append
一覧の末尾へ項目を足すキーワード。
delete
一覧から項目を取り除くキーワード。
reorder
既にある項目の順番だけを変えるキーワード。
explicit
キーワードを付けずに書き、一覧を丸ごと置き換える記述。
ListOp
List Editingの内容を保持するSdf側のデータ構造。
