STEP 71 · PRIM INDEX

Prim Index

合成の結果ではなく、結果を作る木を見ます

今日これだけ

Prim Indexは合成の設計図で ここまで見てきたStackやArcはすべてそこから取り出したもの

公式情報に基づく説明

合成の結果ではなく、結果を作る仕組み

ここまで、あるPrimの値がどこから来たのかをSTEP 68のPrim StackやSTEP 62のPrimCompositionQueryで追ってきました。この2つは、どちらも同じ1つのものを別の角度から見ています。それがPrim Indexです。

Prim Indexは、OpenUSDがあるPrimを合成するときに内部で組み立てる木です。根に「そのPrim自身のLayer Stack」があり、そこからReferenceやInheritsといったArcで枝が伸び、枝の先にはまた別のLayer Stackがあります。値を求めるときは、この木を決まった順序でたどって最初に見つかった意見を採用します。その決まった順序がSTEP 48のLIVERPSです。

この仕組みを担当する部分をPcp（Prim Cache Population）と呼びます。名前を覚える必要はありませんが、エラーメッセージやAPI名にPcpが出てきたら「合成の内部の話だ」と読めます。

OpenUSD Academy Note

Prim Indexを「合成の設計図」だと考えると、これまでの道具の関係が整理できます。Prim Stackは設計図の葉（実際に記述を持つLayer）だけを強い順に並べたもの、PrimCompositionQueryは設計図の枝（Arc）を並べたものです。どちらも新しい情報ではなく、同じ木の違う切り口です。

Diagram

1本の木を、3つの切り口で見る

USDA

枝が2本ある小さな例

indexed.usdaUSDA
#usda 1.0
(
    defaultPrim = "World"
    metersPerUnit = 1
    upAxis = "Y"
)

class Xform "_Style"
{
    color3f[] primvars:displayColor = [(0.2, 0.6, 0.3)] (
        interpolation = "constant"
    )
}

def Xform "World"
{
    def Xform "Chair" (
        inherits = </_Style>
        prepend references = @./base.usda@
    )
    {
    }
}

/World/Chairには枝が2本あります。inheritsで/_Styleへ伸びる枝と、referencesでbase.usdaへ伸びる枝です。丸括弧の中に書かれているのがどちらもArcで、波括弧の中は自分自身の記述です。

Python

木を、枝と葉の両方から見る

inspect_index.pyPython
from pxr import Usd

stage = Usd.Stage.Open("indexed.usda")
prim = stage.GetPrimAtPath("/World/Chair")

print("-- 枝（Composition Arc）--")
for arc in Usd.PrimCompositionQuery(prim).GetCompositionArcs():
    node = arc.GetTargetNode()
    print("  %-10s -> %-10s layers=%s"
          % (arc.GetArcType().displayName, node.path,
             [l.GetDisplayName() for l in node.layerStack.layers]))

print("-- 葉（Prim Stack）--")
for spec in prim.GetPrimStack():
    print("  %-16s %s" % (spec.layer.GetDisplayName(), spec.path))
実行結果Output
-- 枝（Composition Arc）--
  root       -> /World/Chair  layers=['indexed-session.usda', 'indexed.usda']
  inherit    -> /_Style       layers=['indexed-session.usda', 'indexed.usda']
  reference  -> /Base         layers=['base.usda']

-- 葉（Prim Stack）--
  indexed.usda     /World/Chair
  indexed.usda     /_Style
  base.usda        /Base

枝は3本、葉は3枚です。inheritの枝は同じファイルの中を指しているので、Layer Stackがrootと同じになっています。これがSTEP 63のInternal Arcです。referenceだけが別ファイルを指しているのでExternal Arcです。

Prim Stackのほうは、実際に記述を持っていたものだけが強い順に並びます。1行目が/World/Chair自身、2行目がInheritsした/_Style、3行目がReferenceした/Baseです。この並びがそのままLIVERPSの強さの順になっています。

Beginner notes

Pcpという名前が出てきたら

OpenUSD Academy Note

合成でエラーが起きると、メッセージにPcpやPcpErrorTypeという語が出ることがあります。Pcp（Prim Cache Population）はPrim Indexを組み立てる部分の名前です。「合成の途中で問題が起きた」という意味だと読めば十分です。

STEP 112で使ったstage.GetCompositionErrors()は、このPcpが見つけた問題を返すAPIです。参照先が無い、循環している、といった内容が入ります。

よくある間違い

結果だけを見て原因を探す

値が違うときに、書いた場所だけを見直す

自分が書いた行が正しくても、より強い枝が別の値を持っていれば負けます。まず枝（Arc）を見て、次に葉（Prim Stack）を見ます。

Prim StackにすべてのLayerが出ると思う

Prim Stackに出るのは、そのPathに記述を持つLayerだけです。合成の経路に出てくるだけのLayerは含まれません。

Arcの数とPrim Stackの行数が一致すると思う

1本のArcの先に複数のLayerがあることも、記述を持たず0枚のこともあります。一致しないのが普通です。

Prim Indexが読めればInstanceの中も読めると思う

Instanceの内側はPrototypeが持っています。STEP 103で見たとおり、Instance Proxyからは読めても書けません。

Glossary

このレッスンの用語

Prim Index
OpenUSDがPrimを合成するために内部で組み立てる木。根は自分のLayer Stackで、Arcで枝が伸びる。
Pcp（Prim Cache Population）
Prim Indexを組み立てる部分の名前。エラーメッセージやAPI名に現れる。
Composition Arc
Prim Indexの枝。Sublayer・Inherits・Variant・Relocates・References・Payload・Specializesの7種類。
GetCompositionErrors
合成の途中で見つかった問題を返すPython API。参照先が無い、循環しているなどが入る。
