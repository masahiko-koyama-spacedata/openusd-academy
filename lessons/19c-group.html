STEP 58 · MODEL HIERARCHY

group

component modelの祖先となり、複数のModelを整理するKind

今日これだけ

componentの親にはgroup系Kindが必要

Model Hierarchyを正しく保つため、componentのすべての祖先をgroupまたはassemblyなどgroupのsubkindにします。

公式情報に基づく説明

Modelをまとめる高水準の枝を作る

公式: groupはModelを論理的にまとめるmodel kindです。component modelの祖先はgroupまたはgroupのsubkindでなければなりません。

公式: groupはcomponentと異なりleafではなく、group、assembly、componentを子孫に持てます。

OpenUSD Academy Note

ScopeはPrimを整理する型、groupはModel HierarchyでModelを整理する役割です。同じPrimがXform型かつgroup Kindになることがあります。

なんのためにあるのか

componentまで正しく辿れる道を作る

Factory、Props、Vehiclesのような高水準分類を作り、ツールがModelだけを効率よく探索できるようにします。単なる見た目のフォルダではなく、componentの祖先規則を満たします。

Diagram

groupの下へcomponentを置く

USDA

Props groupを作る

group.usdaUSDA
#usda 1.0

def Xform "World" (
    kind = "group"
) {
    def Scope "Props" (
        kind = "group"
    ) {
        def Xform "Chair" (
            kind = "component"
        ) {
        }
    }
}

丸括弧はPrim Metadata、波括弧はPrim内容です。引用符はKind tokenとPrim名の範囲、インデントは親子関係を読みやすくします。Scope型でもKind Metadataを別に持てます。

Python

groupを設定して確認する

create_group.pyPython
from pxr import Kind, Usd, UsdGeom

stage = Usd.Stage.CreateNew("group.usda")
world = UsdGeom.Xform.Define(stage, "/World")
props = UsdGeom.Scope.Define(stage, "/World/Props")

Usd.ModelAPI(world).SetKind(Kind.Tokens.group)
Usd.ModelAPI(props).SetKind(Kind.Tokens.group)
print(props.GetPrim().IsGroup())
stage.Save()

Kind.Tokens.groupはcore tokenです。ピリオドは機能へ進む記号、丸括弧は引数の範囲です。出力はTrueです。

USDA → Python mapping

group Metadataを対応させる

例題

groupが必要か判断する

Propsの下にChair componentがある

答え: Propsをgroupにします。componentの祖先規則を満たすためです。

Chair内部のGeometryを整理する

答え: component境界の内側なので、通常はKindなしのScopeで十分です。

よくある間違い

整理用Primすべてへgroupを付けない

component内部の全Scopeをgroupにする

原因: Scenegraph整理とModel Hierarchyを混同しています。

解決策: Modelをまとめる祖先だけにgroupを使います。

groupをPrim型だと思う

原因: KindとSchemaを混同しています。

解決策: XformやScopeを型として定義し、kind Metadataを別に設定します。
