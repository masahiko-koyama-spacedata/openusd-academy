Layer Stackを調べる

「誰の意見が効いているか」を、順番に並べて確かめます

今日これだけ

値の出どころは、Property Stackの1行目で決まる

公式情報に基づく説明

3つの見方を、粗いほうから使う

思ったとおりの値にならないとき、調べる順番は決まっています。まずどのLayerが積まれているか（Layer Stack）、次にどのLayerがこのPrimに関わっているか（STEP 59 Prim Stack）、最後にこの値はどこから来たか（STEP 60 Property Stack）です。粗いほうから細かいほうへ進めば、無駄なく原因にたどり着けます。

OpenUSD Academy Note

いきなりProperty Stackを見ても、そもそも目当てのLayerが積まれていなければ何も出てきません。「積まれているか」→「このPrimに関わっているか」→「この値を主張しているか」の順に絞ると、どの段階で切れているかが分かります。

見方1

どのLayerが積まれているか

layer_stack.pyPython
from pxr import Usd

stage = Usd.Stage.Open("lamp_contents.usda")

for layer in stage.GetLayerStack():
    print(layer.GetDisplayName())

# lamp_contents-session.usda    … 自動で用意される一時的なLayer
# lamp_contents.usda            … root layer
# lamp_look.usda                … 強い（先に並べた）
# lamp_geom.usda                … 弱い

上から順に強い並びです。STEP 80 Workstream LayersでsubLayersに並べた順が、そのまま出ています。期待したファイルがここに無ければ、原因は積み忘れか、パスの間違いです。この段階で分かることも多くあります。

見方2

どのLayerがこのPrimに関わっているか

prim_stack.pyPython
shade = stage.GetPrimAtPath("/Lamp/Shade")

for spec in shade.GetPrimStack():
    print(spec.layer.GetDisplayName(), spec.path, spec.specifier)

# lamp_look.usda  /Lamp/Shade  Sdf.SpecifierOver
# lamp_geom.usda  /Lamp/Shade  Sdf.SpecifierDef

Layer Stackには4枚ありましたが、このPrimに実際に関わっているのは2枚だけです。lamp_contents.usdaは/Lampまでしか書いていないので出てきません。積まれてはいるが、このPrimには何も書いていないという状態が、ここで見分けられます。

見方3

この値はどこから来たか

property_stack.pyPython
from pxr import Usd

attr = shade.GetAttribute("primvars:displayColor")

for spec in attr.GetPropertyStack(Usd.TimeCode.Default()):
    print(spec.layer.GetDisplayName(), spec.default)

# lamp_look.usda  [(0.95, 0.8, 0.35)]     ← 1行目が勝つ

print(attr.Get())      # [(0.95, 0.8, 0.35)]

print(shade.GetAttribute("height").Get())   # 0.6（lamp_geom.usda から）

色についてはlamp_look.usdaだけが主張しているので、1行しか出ません。同じPrimでもheightはlamp_geom.usdaから来ています。Property単位で出どころが違うことが、この見方で分かります。

絞り込みの順番

Python

3つをまとめて出す

trace.pyPython
from pxr import Usd


def trace(stage, prim_path, prop_name):
    """値の出どころを、粗いほうから順に表示する。"""
    print("--- Layer Stack ---")
    for layer in stage.GetLayerStack():
        print("   ", layer.GetDisplayName())

    prim = stage.GetPrimAtPath(prim_path)
    if not prim:
        print("Primが無い:", prim_path)
        return

    print("--- Prim Stack ---")
    for spec in prim.GetPrimStack():
        print("   ", spec.layer.GetDisplayName(), spec.specifier)

    attr = prim.GetAttribute(prop_name)
    print("--- Property Stack ---")
    stack = attr.GetPropertyStack(Usd.TimeCode.Default())
    if not stack:
        print("    どのLayerにも記述なし（Schemaの既定値）")
    for i, spec in enumerate(stack):
        print("   ", "勝ち" if i == 0 else "    ",
              spec.layer.GetDisplayName(), spec.default)

    print("--- 最終値 ---")
    print("   ", attr.Get())

この関数を1つ持っておくと、調査の最初の一手が決まります。STEP 60 Property Stackで書いたwho_winsを、前後の情報まで含めて広げたものです。

Beginner notes

Layer Stackに出ないもの

OpenUSD Academy Note

GetLayerStack()が返すのは、root layerとそのSublayerだけです。STEP 45 ReferenceやSTEP 46 Payloadで持ち込んだファイルは、別のLayer Stackに属するのでここには出ません。参照先のファイルが関わっているかを見たいときは、Prim Stackのほうを使います。Prim Stackには、参照先のLayerとそこでのPathが並びます。

よくある間違い

いきなり細かいところから見る

Property Stackだけを見て悩む

空だったとき、記述が無いのか、Layerが積まれていないのかが区別できません。粗いほうから見ます。

Layer Stackに参照先が出ると思う

出るのはSublayerまでです。参照先はPrim Stackで確かめます。

session layerを異常だと思う

自動で用意される一時的なLayerです。ファイルとしては存在しません。

Prim Stackが空でないのに値が無いと悩む

そのPrimに何か書いていても、目当てのPropertyを書いているとは限りません。Property Stackで確かめます。
