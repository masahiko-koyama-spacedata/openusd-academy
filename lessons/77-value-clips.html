STEP 68 · VALUE CLIPS

Value Clips

時間で変わる値だけを、別ファイルの並びから読みます

今日これだけ

Value Clipsは 時間で変わる値だけを別ファイルの並びから供給する仕組み

公式情報に基づく説明

1つのファイルに全フレームを入れない

シミュレーションの結果のように、何千フレームぶんものTime Sampleがある場合を考えます。全部を1つのファイルに書くと巨大になり、1フレーム直すだけでもファイル全体を書き直すことになります。

Value Clipsは、時間で変わる値を複数のファイルに分けて置き、時刻に応じて切り替えて読む仕組みです。1フレーム1ファイルでも、100フレームごとでも構いません。書き出す側は分割して並列に書けますし、読む側は必要な時刻のファイルだけを開きます。

設定はPrimのclipsというMetadataに、辞書として書きます。主な項目は4つです。assetPathsが分割されたファイルの一覧、primPathがその中のどのPrimを見るか、activeがどの時刻からどのファイルに切り替えるか、timesが時刻の対応です。

OpenUSD Academy Note

Value Clipsは、これまで見てきたComposition Arcとは別の仕組みです。LIVERPSの7文字の中に入っていません。Arcが「どのPrim記述を持ってくるか」を決めるのに対し、Value Clipsは「すでに決まったPropertyの、時間で変わる値をどこから読むか」だけを決めます。合成の強さの順で言えば、Local Opinionのすぐ下に入る位置づけです。

USDA

3フレームを3ファイルに分ける

clip.001.usda（1つ目のフレーム）USDA
def Sphere "Ball"
{
    double radius.timeSamples = {
        1: 0.5,
    }
}
clipped.usda — まとめる側USDA
#usda 1.0
(
    defaultPrim = "Ball"
    endTimeCode = 3
    metersPerUnit = 1
    startTimeCode = 1
    upAxis = "Y"
)

def Sphere "Ball" (
    clips = {
        dictionary default = {
            double2[] active = [(1, 0), (2, 1), (3, 2)]
            asset[] assetPaths = [@./clip.001.usda@, @./clip.002.usda@, @./clip.003.usda@]
            asset manifestAssetPath = @./clip.manifest.usda@
            string primPath = "/Ball"
            double2[] times = [(1, 1), (2, 2), (3, 3)]
        }
    }
)
{
}

clipped.usdaには時間の値が1つも書かれていません。波括弧の中は空です。それでも、開けば時刻ごとに違うradiusが返ってきます。

activeは(時刻, ファイルの番号)の並びで、「この時刻からこのファイルを使う」という意味です。timesは(こちらの時刻, ファイル内の時刻)で、時刻の読み替えができます。

このUSDAファイルを開く

manifest

どの属性がClipから来るかを先に宣言する

clip.manifest.usdaUSDA
# どの属性がClipから来るかを宣言するだけのLayer。値は持たない
over "Ball"
{
    double radius
}

Manifestは、Clipから供給される属性の一覧です。値は書かず、名前と型だけを宣言します。これがあると、ある属性の値を求めるときに、すべてのClipファイルを開いて探す必要がなくなります。フレーム数が多いほど効きます。

overで書かれていて、double radiusに値が付いていない点に注目してください。STEP 41で見た「上書き用の記述」を、宣言だけのために使っています。

Python

どのファイルが値を出したかまで追える

read_clips.pyPython
from pxr import Usd, UsdGeom

stage = Usd.Stage.Open("clipped.usda")
attr = UsdGeom.Sphere(stage.GetPrimAtPath("/Ball")).GetRadiusAttr()

print("IsDefined   :", attr.IsDefined())
print("timeSamples :", attr.GetTimeSamples())
print("値           :", [(t, attr.Get(t)) for t in (1.0, 2.0, 3.0)])

for t in (1.0, 2.0, 3.0):
    print("t=%.0f ->" % t,
          [spec.layer.GetDisplayName() for spec in attr.GetPropertyStack(t)])
実行結果Output
IsDefined   : True
timeSamples : [1.0, 2.0, 3.0]
値           : [(1.0, 0.5), (2.0, 1.0), (3.0, 1.8)]
t=1 -> ['clip.001.usda']
t=2 -> ['clip.002.usda']
t=3 -> ['clip.003.usda']

STEP 64で使ったGetPropertyStack()に時刻を渡すと、その時刻に値を出したファイルが返ります。時刻ごとに違うファイルが並んでいて、Clipが切り替わっていることがそのまま見えます。

Beginner notes

uniformな値はClipから来ない

OpenUSD Academy Note

Value Clipsが供給するのは時間で変わる値だけです。STEP 24で見たuniform宣言の属性、たとえばxformOpOrderやsubdivisionSchemeはTime Sampleを持てないので、Clipからは来ません。これらはまとめる側のファイルに書きます。

この教材の例でxformOp:translateではなくradiusを動かしているのはそのためです。xformOp:translateを動かすには、xformOpOrderをまとめる側に別途書く必要があり、話が複雑になります。

よくある間違い

設定は書いたのに値が来ない

primPathを間違える

primPathはClipファイルの中でのPathです。まとめる側のPathとは限りません。ここが違うと、エラーにならず値だけが来ません。

manifestを用意せずに大量のClipを置く

動きはしますが、属性を探すためにすべてのClipファイルを開くことになります。フレーム数が多いほど遅くなります。

uniformな属性をClipに入れる

Time Sampleを持てないので供給されません。まとめる側に書きます。

startTimeCodeとactiveの範囲がずれる

再生範囲の外にあるClipは使われません。startTimeCode・endTimeCodeとactiveの範囲を合わせます。

Glossary

このレッスンの用語

Value Clips
時間で変わる値を複数のファイルに分け、時刻に応じて切り替えて読む仕組み。Composition Arcではない。
clips（Metadata）
Value Clipsの設定を書くPrim Metadata。辞書としてassetPaths・primPath・active・timesなどを持つ。
Clip Manifest
どの属性がClipから供給されるかを、名前と型だけで宣言したLayer。全ファイルを開かずに済ませるために使う。
active（clips）
(時刻, ファイルの番号)の並び。どの時刻からどのClipへ切り替えるかを決める。
times（clips）
(こちらの時刻, ファイル内の時刻)の並び。時刻の読み替えを行う。
