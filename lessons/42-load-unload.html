STEP 68 · STAGE CONTROL

LoadとUnload

Payloadの中身を、開くか開かないかを選びます

今日これだけ

Payloadの中身はLoadしたときだけStageに現れる

公式情報に基づく説明

読み込みを後回しにできる唯一のArc

STEP 46 Payloadは、他のComposition Arcと違って「読み込むかどうか」を実行時に選べます。Loadされていないとき、そのPayloadが持ち込むはずのPrimはStageに現れません。Stageを開くときに全部Loadするか、一つもLoadしないかを指定でき、開いたあとから個別に切り替えることもできます。

OpenUSD Academy Note

STEP 67のInactiveと似ていますが、目的が違います。Inactiveは「このPrimはこのシーンでは要らない」というデータの意思表示で、ファイルに書きます。Loadは「今は開かなくていい」という実行時の都合で、Stageを開く側が決めます。

USDA

重い部分をPayloadに分ける

payload-detail.usdaUSDA
#usda 1.0
(
    defaultPrim = "Detail"
    metersPerUnit = 1
    upAxis = "Y"
)

def Xform "Detail"
{
    def Cube "PartA" { ... 青い箱 ... }
    def Cube "PartB" { ... 緑の箱 ... }
}
payload-scene.usdaUSDA
def Xform "World"
{
    def Cube "Always"
    {
        double size = 1
        color3f[] primvars:displayColor = [(0.85, 0.2, 0.2)]
        double3 xformOp:translate = (-2.4, 0, 0)
        uniform token[] xformOpOrder = ["xformOp:translate"]
    }

    def "Heavy" (
        payload = @payload-detail.usda@
    )
    {
        double3 xformOp:translate = (1.2, 0, 0)
        uniform token[] xformOpOrder = ["xformOp:translate"]
    }
}

赤いAlwaysはこのファイルが直接持っています。Heavyは自分では中身を持たず、payloadで別ファイルを指しているだけです。payloadはPrim Metadataなので、Prim名の後ろの丸括弧に書きます。

結果

Loadすると中身が現れる

確かめる

走査結果が変わる

check_load.pyPython
from pxr import Usd

loaded = Usd.Stage.Open("payload-scene.usda", Usd.Stage.LoadAll)
print([str(p.GetPath()) for p in loaded.Traverse()])
# ['/World', '/World/Always', '/World/Heavy',
#  '/World/Heavy/PartA', '/World/Heavy/PartB', '/World/ShotCam']

unloaded = Usd.Stage.Open("payload-scene.usda", Usd.Stage.LoadNone)
print([str(p.GetPath()) for p in unloaded.Traverse()])
# ['/World', '/World/Always', '/World/ShotCam']

heavy = unloaded.GetPrimAtPath("/World/Heavy")
print(heavy.IsLoaded())     # False
heavy.Load()                # あとから開く
print(heavy.IsLoaded())     # True
heavy.Unload()              # また閉じる

Loadしていない状態でも/World/Heavyそのものは存在し、xformOp:translateのような、このファイルに直接書かれた情報は読めます。読めなくなるのはPayloadの中身だけです。

OpenUSD Academy Note

上の一覧に/World/Heavyが出てこないのは、消えたからではありません。Traverse()が既定で使う条件にPrimIsLoadedが含まれており、Loadされていないprimは走査から外れるためです。GetPrimAtPathでは取得できますし、TraverseAll()を使えば一覧にも現れます。この性質は、次のSTEP 73 Asset Entry Pointで、「中身を開かずに入口の情報だけ読む」使い方につながります。

Python

Stage全体と個別を使い分ける

load_control.pyPython
from pxr import Usd

stage = Usd.Stage.Open("payload-scene.usda", Usd.Stage.LoadNone)

# Stage全体をまとめて切り替える
stage.Load("/World/Heavy")
stage.Unload("/World/Heavy")

# 今どれが開いているかを調べる
print(stage.GetLoadSet())
# 開けるPayloadの一覧を調べる
print(stage.FindLoadable())

# Prim側から切り替える
prim = stage.GetPrimAtPath("/World/Heavy")
prim.Load()
print(prim.IsLoaded())   # True

Usd.Stage.LoadAllとUsd.Stage.LoadNoneはStageを開くときの初期状態です。開いたあとはLoadとUnloadでいつでも切り替えられ、切り替えのたびにStageが再構成されます。

Beginner notes

ReferenceとPayloadの違い

OpenUSD Academy Note

書き方も効果もよく似ていますが、STEP 45 Referenceは必ず読み込まれ、Payloadは読み込みを後回しにできます。だから、大きなシーンでは「軽い情報はReferenceで見せ、重い中身はPayloadに置く」という分け方をします。この設計はSTEP 71で扱う予定です。

よくある間違い

Load状態をファイルの内容だと思う

UnloadすればPayloadの記述が消えると思う

消えるのは読み込んだ中身だけです。payload = @...@という記述はファイルに残り続けます。

Loadしていないから壊れていると考える

Payloadの中身が見えないのは正しい動作の場合があります。まずprim.IsLoaded()を確認します。

Inactiveで代用しようとする

Inactiveはファイルに書く意思表示で、他の人がそのファイルを開いても外れたままです。一時的に開かないだけならLoadを使います。

Referenceに対してLoadを呼ぶ

Load制御が効くのはPayloadだけです。Referenceは常に読み込まれます。
