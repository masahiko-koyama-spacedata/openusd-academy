LESSON 24D · PRIMVAR INTERPOLATION

varying interpolation

値の個数はvertexと同じ。違いが出るのは細分化したときだけです

今日これだけ

varyingはPointごとに一値で 面の上を線形に補間する

公式情報に基づく説明

個数はvertexと同じ 補間の規則だけが違う

varyingは、vertexと同じくPointごとに一つの値を対応させます。必要な値の個数はまったく同じで、このPanelなら6個です。違うのは面の内側をどう埋めるかで、varyingはSurfaceの上を線形に補間します。vertexはSurfaceの基底関数にしたがうため、Meshを細分化する設定にしたときに結果が変わります。

OpenUSD Academy Note

この2つは、初学者がいちばん「違いが分からない」と感じる組み合わせです。理由ははっきりしていて、細分化しないMeshでは結果が完全に同じになるからです。下で実際に確かめます。

USDA

vertexの例からinterpolationだけを変える

varying.usdaUSDA
#usda 1.0
(
    defaultPrim = "World"
    metersPerUnit = 1
    upAxis = "Y"
)

def Xform "World"
{
    def Mesh "Panel"
    {
        uniform token subdivisionScheme = "none"
        int[] faceVertexCounts = [4, 4]
        int[] faceVertexIndices = [0, 1, 4, 3, 1, 2, 5, 4]
        point3f[] points = [
            (0, 0, 0), (1, 0, 0), (2, 0, 0),
            (0, 1, 0), (1, 1, 0), (2, 1, 0),
        ]
        color3f[] primvars:displayColor = [
            (0.85, 0.2, 0.2), (0.95, 0.8, 0.15), (0.15, 0.35, 0.85),
            (0.85, 0.2, 0.2), (0.2, 0.7, 0.3), (0.15, 0.35, 0.85),
        ] (
            interpolation = "varying"
        )
    }
}

Lesson 24CのUSDAと比べると、変わっているのはinterpolationの行だけです。値の並びも個数もそのままで構いません。

このUSDAファイルを開く

結果

細分化しないMeshでは vertexと完全に同じになる

同じ入力から同じ絵が出るので、細分化しないMeshだけを扱っているうちは、この2つを見分けることはできません。「見た目で区別できないのが正しい」と知っておくことが、この段階では大切です。

結果

細分化すると違いが現れる

同じ6色のままsubdivisionSchemeをcatmullClarkへ変え、細分化を有効にして描画すると、2つの結果は一致しなくなります。

差はわずかですが、中央の黄と緑を見比べると、vertexのほうが色がならされ、varyingのほうが元の値が濃く残っているのが分かります。この2枚は画像として一致しません。

Python

Tokens.varyingを指定する

create_varying.pyPython
from pxr import Gf, Sdf, Usd, UsdGeom

stage = Usd.Stage.CreateNew("varying.usda")
UsdGeom.Xform.Define(stage, "/World")

mesh = UsdGeom.Mesh.Define(stage, "/World/Panel")
mesh.CreateSubdivisionSchemeAttr("none")
mesh.CreateFaceVertexCountsAttr([4, 4])
mesh.CreateFaceVertexIndicesAttr([0, 1, 4, 3, 1, 2, 5, 4])
mesh.CreatePointsAttr([
    Gf.Vec3f(0, 0, 0), Gf.Vec3f(1, 0, 0), Gf.Vec3f(2, 0, 0),
    Gf.Vec3f(0, 1, 0), Gf.Vec3f(1, 1, 0), Gf.Vec3f(2, 1, 0),
])

pv = UsdGeom.PrimvarsAPI(mesh).CreatePrimvar(
    "displayColor", Sdf.ValueTypeNames.Color3fArray, UsdGeom.Tokens.varying)
pv.Set([
    Gf.Vec3f(0.85, 0.2, 0.2), Gf.Vec3f(0.95, 0.8, 0.15), Gf.Vec3f(0.15, 0.35, 0.85),
    Gf.Vec3f(0.85, 0.2, 0.2), Gf.Vec3f(0.2, 0.7, 0.3), Gf.Vec3f(0.15, 0.35, 0.85),
])

stage.Save()

UsdGeom.Tokens.vertexをUsdGeom.Tokens.varyingへ変えるだけです。値の側は何も変えません。

Beginner notes

subdivisionSchemeの既定値に注意する

OpenUSD Academy Note

UsdGeomMeshのsubdivisionSchemeを書かなかった場合、既定値はcatmullClarkです。つまり何も書かないと細分化される側になります。このAcademyの例では、書いた多角形をそのまま見せたいので、毎回noneを明示しています。自分で試すときも、意図しない細分化を避けるために明示することを勧めます。

よくある間違い

「違いが見えない＝間違い」と考えてしまう

差が出ないので設定を疑ってしまう

細分化しないMeshではvertexとvaryingは同じ絵になります。これは仕様どおりの動作で、設定の誤りではありません。

個数がvertexと違うと思う

どちらもPointの個数と同じです。varyingだけ値を増やしたり減らしたりする必要はありません。

Meshの種類によらず同じだと考える

Meshを細分化する設定にしたときや、NURBSなど別のSurfaceを扱うときには、補間の規則の違いがそのまま結果の違いになります。

Glossary

このレッスンの用語

varying（interpolation）
Pointごとに一つの値を対応させ、Surface上を線形に補間するPrimvar Interpolation。
線形補間
2つの値の間を、距離に比例した割合でまっすぐつなぐ補間。
Subdivision Surface（細分化サーフェス）
粗い多角形Meshを規則にしたがって細かく分割し、なめらかな形を作る仕組み。
catmullClark
OpenUSDのMeshで既定となっている細分化の方式。
