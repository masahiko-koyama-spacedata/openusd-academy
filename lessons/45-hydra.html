STEP 65 · STAGE CONTROL

Hydra

Stageの内容が、絵になるまでの通り道です

今日これだけ

Stageは絵を描かない。Hydraが受け取って、描く側へ渡す

公式情報に基づく説明

データと描画の間に一枚ある

ここまでのレッスンで扱ってきたStageは、シーンの内容を保持するだけで、絵を描く機能は持っていません。内容を受け取り、実際に描く仕組みへ渡すのがHydraです。Hydraは間に立つことで、同じStageを別のRendererで描けるようにしています。描く側の実装をRender Delegateと呼び、Stageの内容を渡す仕組みをScene Indexと呼びます。

OpenUSD Academy Note

この分離があるおかげで、教材でずっと使ってきたusdrecordのようなツールが成り立ちます。ツール側は「Stageを開いてHydraに渡す」だけを書けばよく、実際に絵を作るのはRender Delegateです。STEP 33 Compositionで「データの合成」を、ここで「合成された結果の描画」を扱う、という関係になります。

ターミナルコマンド
$ usdrecord --help

この-rで選ぶものがRender Delegateです。この環境（macOS上のApple USD Tools 0.25.2）ではMetalが使えます。別の環境ではここにStormやRenderManなどが並びます。同じUSDAを渡しても、ここで選んだものによって絵の作られ方が変わります。

教材の画像を作っているコマンドコマンド

このAcademyのレッスンに載っている描画結果は、すべてこのコマンドで作っています。usdrecordがStageを開き、Hydraへ渡し、Render Delegateが画像を作る、という流れがそのまま実行されています。

Hydraが受け取るもの・受け取らないもの

これは実務上とても大事な点です。「見た目がおかしい」という問題を、描画結果だけを見て解決することはできません。原因を追うにはSTEP 53 Prim StackやSTEP 54 Property Stackのように、Stage側を調べる道具が要ります。

確かめる

描かれないものは、Stage側で決まっている

why_not_drawn.pyPython
from pxr import Usd, UsdGeom


def why_not_drawn(stage, path):
    """描かれない理由を、Stage側の状態から切り分ける。"""
    prim = stage.GetPrimAtPath(path)
    if not prim:
        return "そのPathにPrimが無い"
    if not prim.IsDefined():
        return "定義されていない（over だけ）"
    if prim.IsAbstract():
        return "abstract（class）"
    if not prim.IsActive():
        return "active = false"
    if not prim.IsLoaded():
        return "Payloadが未Load"
    imageable = UsdGeom.Imageable(prim)
    if imageable and imageable.ComputeVisibility() == UsdGeom.Tokens.invisible:
        return "visibility = invisible"
    return "Stage側の理由は見当たらない"

Hydraへ渡る前に落ちる理由を、上から順に並べています。STEP 31 over・STEP 32 class・STEP 61 Inactive・STEP 62 Loadと、これまで別々に扱ってきた「描かれない理由」が、ここで一つの表に揃います。

実際に走らせた結果Python
stage = Usd.Stage.Open("traversal.usda")

for path in ("/World/Robot/Body", "/World/Robot/Spare",
             "/World/Placeholder", "/_Style", "/World/Nope"):
    print(path, "->", why_not_drawn(stage, path))

# /World/Robot/Body    -> Stage側の理由は見当たらない
# /World/Robot/Spare   -> active = false
# /World/Placeholder   -> 定義されていない（over だけ）
# /_Style              -> abstract（class）
# /World/Nope          -> そのPathにPrimが無い

unloaded = Usd.Stage.Open("payload-scene.usda", Usd.Stage.LoadNone)
print(why_not_drawn(unloaded, "/World/Heavy"))
# Payloadが未Load

ここまでのレッスンで作ってきたシーンを、そのまま通した結果です。5つの理由がすべて別々に検出されています。「描かれない」と言われたときは、まずこれを回してStage側に理由があるかどうかを切り分けます。どれにも当てはまらなければ、原因はカメラの向きや範囲、あるいはRenderer側です。

Beginner notes

visibilityとactiveの違い

OpenUSD Academy Note

visibilityはUsdGeomImageableが持つAttributeで、Stageには居るが描かないという指定です。親から子へ受け継がれ、親がinvisibleなら子も描かれません。STEP 61 Inactiveは構成そのものから外すので、Propertyも読めなくなります。描画だけ止めたいならvisibility、シーンから外したいならactiveと使い分けます。

よくある間違い

描画結果から合成を推測する

絵を見て原因を探す

Hydraには合成の経緯が渡りません。原因はStage側の道具で調べます。

Rendererの違いを考えない

同じStageでも、選んだRender Delegateによって見え方は変わります。比べるときは条件をそろえます。

visibilityとactiveを混同する

前者は描かないだけ、後者は構成から外れます。

描かれない理由を1つだけ確かめる

理由は複数あり得ます。上から順に切り分けます。

Glossary

このレッスンの用語

Hydra
Stageの内容を受け取り、描く仕組みへ渡す層。
Render Delegate
実際に絵を作る実装。Storm、Metal、RenderManなど。
Scene Index
Stageの内容をHydraへ渡すための仕組み。
Imageable
描画される可能性のあるPrimに共通する性質をまとめたSchemaの基盤。
visibility
描画するかどうかを決めるImageableのAttribute。親から子へ受け継がれる。
ComputeVisibility
親からの継承まで含めて、最終的に描画されるかを求めるPython API。
