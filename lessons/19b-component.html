STEP 61 · MODEL HIERARCHY

component

完成し、独立して再利用できるAssetを示すleaf model Kind

今日これだけ

componentの下に別のModelを入れない

componentはModel Hierarchyの探索を止めるleafです。内部の重要部品にはcomponentではなくsubcomponentを検討します。

公式情報に基づく説明

利用者へ渡せる完成品を示す

公式: componentは完全でreference可能な自己完結したAssetを表すmodel kindです。ペン、椅子、家のように規模が違っても、利用者が一つの製品として扱う単位が候補です。

公式: componentはModel Hierarchyのleafであり、子孫へ別のcomponent modelを含められません。すべての祖先はgroupまたはassemblyのようなgroupのsubkindでなければなりません。

OpenUSD Academy Note

「部品」という日本語だけで判断しません。Robotの腕が別売りAssetでも、Robot Asset内部で重要なだけならsubcomponentの可能性があります。公開・再利用の境界で考えます。

なんのためにあるのか

Assetの境界で探索を止める

ツールはcomponentを見つけると、その下のMeshやMaterialまで全探索せず一つのModelとして扱えます。Asset選択、Bounds取得、一覧表示、ValidationなどをScenegraphの詳細から切り離せます。

defaultPrimはLayerの入口、kindはPrimのModel Hierarchy上の役割です。丸括弧はMetadata、波括弧はPrim内容、引用符はtokenや名前の範囲を示します。

Python

componentを設定して確認する

create_component.pyPython
from pxr import Kind, Usd, UsdGeom

stage = Usd.Stage.CreateNew("chair.usda")
chair = UsdGeom.Xform.Define(stage, "/Chair")
stage.SetDefaultPrim(chair.GetPrim())

model = Usd.ModelAPI(chair)
model.SetKind(Kind.Tokens.component)

print(chair.GetPrim().IsComponent())
stage.Save()

Kind.Tokens.componentはcore Kind tokenです。IsComponent()で分類結果を確認し、出力はTrueになります。

例題

component境界を判断する

問題1 Asset Libraryで再利用するChair

答え: Chairの入口をcomponentにします。完成し、独立してReferenceする単位だからです。

問題2 Chair内部のSeat

答え: 通常は別componentにしません。重要な内部ノードとして検索したいならsubcomponentを検討します。

問題3 Chairを複数配置したRoom

答え: Roomはcomponentの親なので、groupまたはassemblyなどのgroup系Kindが必要です。

よくある間違い

名前の印象でcomponentを付けない

機械のすべての部品をcomponentにする

原因: componentを日本語の「構成部品」とだけ捉えています。

解決策: 独立して公開・再利用するAsset境界かで判断します。

componentの子へcomponentを置く

原因: leaf modelの規則を無視しています。

解決策: 親をgroup/assemblyへ変えるか、子をsubcomponentとして扱います。

祖先にKindを付けない

原因: component単体だけでModel Hierarchyが成立すると思っています。

解決策: componentの祖先をgroupまたはそのsubkindにします。
