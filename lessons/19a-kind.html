STEP 61 · MODEL HIERARCHY

Kind

PrimがModel Hierarchyで担う役割を分類するMetadata

今日これだけ

KindはPrim型ではなく役割のMetadata

XformはPrimが何であるか、kind = "component"はModel Hierarchyでどんな役割かを示します。

公式情報に基づく説明

深いScenegraphに浅い索引を作る

公式: Model KindはPrim-level Metadataで、PrimのModel Hierarchy上の役割を分類します。Schema型とは独立し、Kind Registryのtokenを使います。

公式: core kindにはabstractなmodel、leaf modelのcomponent、modelを整理するgroup、groupのsubkindであるassemblyがあります。subcomponentはmodel kindではなく、component内部の重要なPrimを示します。

OpenUSD Academy Note

Scenegraphが詳細な地図なら、Model Hierarchyは主要地点だけを載せた索引です。すべてのPrimへKindを付ける仕組みではありません。

なんのためにあるのか

Assetを高速に見つけて扱う

ツールはIsModel()、IsGroup()、IsComponent()などで、Geometryの細部をすべて走査せず高水準のModelを探せます。Asset選択、Model単位の処理、Traversalのpruning、再利用可能なAsset構造の検証に使います。

Prim名の後ろの丸括弧はPrim Metadataの範囲です。kindがMetadata名、=が値の設定、引用符内がKind tokenです。波括弧はPrimの内容、インデントは親子関係を示します。

一行ずつ読む

kind = "component"を分解する

  1. kind

    Model Hierarchy上の役割を保持するPrim Metadataです。

  2. =

    左のMetadataへ右のtokenを設定します。

  3. "component"

    このPrimが完全で再利用可能なleaf modelであることを示します。

  4. def Xform "Chair"

    Prim型はXformです。KindとSchema型は同じ欄ではありません。

Python

Kindを設定してModelか確認する

create_kind.pyPython
from pxr import Kind, Usd, UsdGeom

stage = Usd.Stage.CreateNew("kind.usda")
world = UsdGeom.Xform.Define(stage, "/World")
chair = UsdGeom.Xform.Define(stage, "/World/Chair")

Usd.ModelAPI(world).SetKind(Kind.Tokens.group)
Usd.ModelAPI(chair).SetKind(Kind.Tokens.component)

print(chair.GetPrim().IsModel())
print(chair.GetPrim().IsComponent())
stage.Save()

Kind.Tokens.componentは文字列の綴りを手入力せずcore tokenを使います。Usd.ModelAPIはPrimのModel Metadataを操作します。二つのprint()はどちらもTrueになります。

Model Hierarchyの規則

componentの祖先もModelにする

公式: component modelのすべての祖先はgroupまたはそのsubkindであるassemblyなどでなければなりません。componentはleaf modelなので、componentの子孫へ別のcomponent modelを置きません。

公式: component内部で重要なPrimを示す場合はsubcomponentを使えます。subcomponentはModel Hierarchyのmodel kindではありません。

例題

KindとSchemaを選び分ける

問題1 完成したChair Assetの入口

答え: kind = "component"。利用者が再利用するleaf modelだからです。Prim型は階層変換が必要ならXformなどを別に選びます。

問題2 Chairを100個まとめたRoom

答え: Roomはgroupまたは、公開されたaggregate Assetならassemblyを検討します。

問題3 Chair内部のWheelを重要部品として見つけたい

答え: componentの子へcomponentを置かず、subcomponentを検討します。

よくある間違い

すべてのPrimへKindを付けない

kind = "model"をassignする

原因: modelを一般用途の具体Kindだと考えています。

解決策: modelはabstractな基底Kindです。component、group、assemblyなど具体的な役割を選びます。

componentの下にcomponentを置く

原因: componentがleaf modelである規則を見落としています。

解決策: 内部の重要部品にはsubcomponentを使うか、Asset境界を再設計します。

ScopeとKindを同じものだと思う

原因: Prim型とMetadataを混同しています。

解決策: ScopeはIsA Schema、KindはModel HierarchyのMetadataです。

独自分類を何でもcustom kindにする

原因: portabilityとconsumer側の理解を考慮していません。

解決策: core KindはModel Hierarchyへ限定し、一般分類にはcustom PropertyやSchemaを検討します。

Glossary

このページで出た言葉

Kind

Model Hierarchy
Kindを使ってScenegraphの高水準なModelだけを示す階層。
model
componentとgroupのabstractな基底Kind。直接assignしない。
pruning
探索対象外の枝を辿らず処理を減らすこと。
Kind Registry
利用可能なKind tokenと継承関係を管理する仕組み。
