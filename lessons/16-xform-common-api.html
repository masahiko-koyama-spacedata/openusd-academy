XformCommonAPI

一般的な移動・回転・拡縮・pivotを、交換しやすい構成で扱うAPI

今日これだけ

標準的な変換ならXformCommonAPIから始める

自由なxformOp列ではなく、単一のtranslate・rotate・scale・pivotという共通構成で値を読み書きします。

公式情報に基づく説明

DCC間で扱いやすい変換を作る

公式: XformCommonAPIはnon-applied API Schemaです。一般的な単一のtranslation、rotation、scale、pivotをauthor・retrieveするための制限された構成を提供します。

公式: UsdGeomXformableは任意のxformOp列を扱えます。自由度は高い一方、「この物体の位置はどれか」のような単純な問い合わせが難しくなることがあります。XformCommonAPIは一般的な交換を簡単にするため、許可する操作と順序を限定します。

OpenUSD Academy Note

APIという名前ですが、値は最終的に通常のxformOp:translateなどとしてUSDAへ保存されます。独自ファイル形式を追加する仕組みではありません。

なんのためにあるのか

変換を見つけやすくする

任意のxformOp列には複数の回転やpivotを置けます。高度な動きには必要ですが、importerやexporterが単一の位置・回転・scaleへ対応させるのは難しくなります。共通構成を使うことで、一般的なDCCのtransform channelへ対応させやすくします。

Diagram

API操作はUSDAのPropertyになる

USDA

共通構成の変換を読む

common-transform.usdaUSDA
#usda 1.0

def Xform "Crate" {
    double3 xformOp:translate = (10, 0, 0)
    float3 xformOp:rotateXYZ = (0, 45, 0)
    float3 xformOp:scale = (2, 2, 2)
    uniform token[] xformOpOrder = [
        "xformOp:translate",
        "xformOp:rotateXYZ",
        "xformOp:scale"
    ]
}

double3とfloat3は三つの数を持つ型、コロンはnamespaceを区切る記号です。角括弧は配列、カンマは要素の区切り、引用符はtoken値を示します。uniformは値が時間変化する目的ではないことを示します。

Python

対応可能か確認して値を書く

create_transform.pyPython
from pxr import Usd, UsdGeom

stage = Usd.Stage.CreateNew("common-transform.usda")
crate = UsdGeom.Xform.Define(stage, "/Crate")
api = UsdGeom.XformCommonAPI(crate)

if not api:
    raise RuntimeError("XformCommonAPIで扱えません")

api.SetTranslate((10.0, 0.0, 0.0))
api.SetRotate(
    (0.0, 45.0, 0.0),
    UsdGeom.XformCommonAPI.RotationOrderXYZ
)
api.SetScale((2.0, 2.0, 2.0))
stage.Save()

if not api:はAPIがPrimと互換でない場合を調べます。コロンの次に字下げした行が条件内の処理です。raiseはエラーを発生させます。複数行の丸括弧内では引数を改行でき、カンマで区切ります。

USDA → Python mapping

Propertyとsetterを対応させる

  1. USDA

    xformOp:translate = (10, 0, 0)↓

    Python

    api.SetTranslate((10, 0, 0))

  2. USDA

    xformOp:rotateXYZ = (0, 45, 0)↓

    Python

    api.SetRotate((0, 45, 0), RotationOrderXYZ)

  3. USDA

    xformOp:scale = (2, 2, 2)↓

    Python

    api.SetScale((2, 2, 2))

例題

どのAPIを選ぶか

問題1 DCCの一般的な位置・回転・scaleと交換する

答え: XformCommonAPIから始めます。標準的なcomponent transformを扱う目的に合います。

問題2 惑星の公転と自転を別のpivotで二重に記述する

答え: 任意のxformOp列を扱えるUsdGeomXformableを検討します。XformCommonAPIの制限された共通構成では表しにくい例です。

よくある間違い

どのxformOp列にも使えると思わない

既存Primへ確認せずsetterを使う

原因: 任意の操作列が共通構成へ変換できると考えています。

解決策: UsdGeom.XformCommonAPI(prim)の有効性を確認します。

xformOpOrderを無視する

原因: Propertyが存在すれば自動で適用されると考えています。

解決策: 変換評価にはxformOpOrderへ操作名が入っている必要があります。順序の意味は独立レッスンで扱います。

API SchemaをApplyする

原因: すべてのAPI Schemaがapplied APIだと考えています。

解決策: XformCommonAPIはnon-applied API Schemaです。wrapperを作って互換性を確認します。

Glossary

このページで出た言葉

XformCommonAPI
一般的な単一の移動・回転・拡縮・pivotを扱うnon-applied API Schema。
non-applied API Schema
Primへ適用済み情報をauthorせず、互換なデータを操作するAPI Schema。
xformOp
translateやrotateなど、一つの変換操作を表すProperty。
xformOpOrder
使用するxformOpと評価順序を列挙するtoken配列。
pivot
回転や拡縮の中心。詳細は独立レッスンで扱う。
