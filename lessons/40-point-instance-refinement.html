STEP 107 · POINT INSTANCE REFINEMENT

Point Instanceに差を付ける

Primが無くても、配列とidで個体を扱えます

今日これだけ

Point Instanceの個体差は配列で配る Prototypeを増やすか 1体だけPrimへ引き上げるかを目的で選ぶ

公式情報に基づく説明

Pathが無いので、over では触れない

STEP 106で見たとおり、PointInstancerが置いた1体1体はPrimではありません。Pathを持たないので、overで名指しできず、STEP 104のHierarchical Refinementも使えません。

代わりに、PointInstancer自身が持つ配列が個体差の受け皿になります。positionsが1体ごとの位置であるのと同じ考え方で、色や大きさも配列で1体ずつ与えます。手段は3つあります。

1つ目はPrimvarを配る方法です。2つ目はPrototypeを増やしてprotoIndicesで振り分ける方法。3つ目がPromotionで、特定の1体だけを通常のPrimへ引き上げます。

1. Primvarを配る

interpolationはvaryingで、値は1体につき1個

PointInstancerへPrimvarを書くとき、1体ごとに値を変えたいならinterpolationにvarying（またはvertex）を指定します。STEP 35で見たMeshのvaryingが「Pointごとに1個」だったのと同じで、PointInstancerではインスタンス1体につき1個になります。値の個数はpositionsの要素数と一致させます。

point-refine.usda（抜粋）USDA
def PointInstancer "Scatter"
{
    rel prototypes = [
        </World/Scatter/Prototypes/Ball>,
        </World/Scatter/Prototypes/Box>,
    ]
    int[] protoIndices = [0, 1, 0, 1, 0, 1]
    int64[] ids = [0, 1, 2, 3, 4, 5]
    point3f[] positions = [
        (-2.5, 0, 0), (-1.5, 0, 0), (-0.5, 0, 0),
        (0.5, 0, 0), (1.5, 0, 0), (2.5, 0, 0),
    ]

    # 1体につき1個。Point Instance へ値を配るときは varying を使う
    color3f[] primvars:displayColor = [
        (0.85, 0.25, 0.2), (0.75, 0.45, 0.15), (0.55, 0.6, 0.2),
        (0.25, 0.6, 0.4), (0.2, 0.5, 0.75), (0.35, 0.3, 0.8),
    ] (
        interpolation = "varying"
    )
}

2. Prototypeを増やす

protoIndicesが、どの体がどのPrototypeを使うかを決める

Prototypeを増やすには3つを揃えます。1つ目は新しい形のPrim階層を定義すること、2つ目はそれをprototypesのRelationshipへ足すこと、3つ目はprotoIndicesを更新して、どの体がどれを使うかを指定することです。上の例では[0, 1, 0, 1, 0, 1]なので、球と立方体が交互に並びます。

ここで増えるものと増えないものを分けて考えます。Instanceを何体置いてもPrimは増えません。1000体でも配列の要素が増えるだけです。一方で、Prototypeの種類を増やした分は、その形のPrim階層が実際に増えます。種類が10あれば10種類分の構造を持つことになります。

つまり「体数に対しては軽いが、種類数に対しては軽くない」という性質です。同じ形を大量に置くことに向いていて、1体ずつ違う形にしたい用途には向きません。

3. Promotion

1体をpruneして、通常のPrimへ置き換える

「この1本の木だけ枝を折りたい」のように、配列では表せない編集をしたいことがあります。そのときはPromotionを使います。対象の1体をPointInstancerからprune（刈り取り）し、同じ位置に通常のPrimを置き直します。

pruneにはDeactivateId()を使います。これはinactiveIdsというPrim Metadataを書きます。配列から要素を削除するのではない点が大事で、削除しないので他の体の番号がずれません。

promote.pyPython
from pxr import Gf, Usd, UsdGeom

instancer = UsdGeom.PointInstancer.Get(stage, "/World/Scatter")
positions = instancer.GetPositionsAttr().Get()

# id 2 の体を prune する
instancer.DeactivateId(2)
print("inactiveIds :", instancer.GetPrim().GetMetadata("inactiveIds"))
print("ComputeMask :", list(instancer.ComputeMaskAtTime(Usd.TimeCode.Default())))

# 同じ位置に、通常のPrimとして置き直す
promoted = UsdGeom.Xform.Define(stage, "/World/Promoted")
promoted.GetPrim().GetReferences().AddInternalReference(
    "/World/Scatter/Prototypes/Ball")
promoted.AddTranslateOp().Set(Gf.Vec3d(*positions[2]))
print("引き上げ先  :", promoted.GetPrim().GetPath())
実行結果Output
inactiveIds : SdfInt64ListOp(Explicit Items: [2])
ComputeMask : [True, True, False, True, True, True]
引き上げ先  : /World/Promoted

ComputeMaskAtTimeの3番目だけがFalseになりました。これが「id 2 は描かない」という意味です。そして/World/Promotedは普通のPrimなので、overでも変換でもMaterial Bindingでも、何でも書けます。

positions[2]をそのまま渡す書き方は、上の例のようにPointInstancerに位置しか与えていない場合にだけ正しくなります。実際には1体ごとにorientationsやscalesを持てますし、Prototypeのroot自身が変換を持っていることも、PointInstancer自体が動いていることもあります。それらを取りこぼすと、引き上げた1体だけ位置や向きがずれます。

取りこぼさないためのAPIがComputeInstanceTransformsAtTime()です。1体ごとの変換を行列の配列で返します。ただし、そのまま呼ぶと落とし穴が2つあります。

promote_transform.pyPython
from pxr import Gf, Usd, UsdGeom

instancer = UsdGeom.PointInstancer.Get(stage, "/World/Scatter")
time = Usd.TimeCode.Default()
TARGET_ID = 2

instancer.DeactivateId(TARGET_ID)

# 落とし穴1: 既定の ApplyMask では、prune した体が配列から抜ける。
#            抜けた分だけ後ろが詰まり、添字が別の体を指してしまう。
#            prune した体の変換が欲しいので IgnoreMask を渡す
transforms = instancer.ComputeInstanceTransformsAtTime(
    time, time,
    UsdGeom.PointInstancer.IncludeProtoXform,
    UsdGeom.PointInstancer.IgnoreMask)

# id と添字は同じとは限らないので、ids から引く
ids = list(instancer.GetIdsAttr().Get())
index = ids.index(TARGET_ID)

# 落とし穴2: 返るのは PointInstancer のローカル空間の変換。
#            PointInstancer 自身の変換を掛けて world にする
to_world = UsdGeom.Xformable(instancer).ComputeLocalToWorldTransform(time)
world_xf = transforms[index] * to_world

promoted = UsdGeom.Xform.Define(stage, "/World/Promoted")
promoted.GetPrim().GetReferences().AddInternalReference(
    "/World/Scatter/Prototypes/Ball")

# 置き先の親にも変換があるかもしれない。world をそのまま local として
# 書くと親の分が二重に効くので、親の world の逆を掛けて戻す
parent_to_world = UsdGeom.Xformable(
    promoted.GetPrim().GetParent()).ComputeLocalToWorldTransform(time)
local_xf = world_xf * parent_to_world.GetInverse()

UsdGeom.Xformable(promoted).MakeMatrixXform().Set(local_xf)
実行結果Output
id 2 の world 変換 : (9.5, 4.0, 0.0)
親(/World)のworld  : (10.0, 0.0, 0.0)
書き込む local 変換 : (-0.5, 4.0, 0.0)
置いた後の world    : (9.5, 4.0, 0.0)
一致: True

この確認では、/Worldが(10, 0, 0)、PointInstancerが(0, 3, 0)、Prototype rootが(0, 0.5, 0)、scalesが(2, 2, 2)という状態にしてあります。求めたworld位置と、置き直したPrimのworld位置が一致しました。

引数値意味
doProtoXformsIncludeProtoXform（既定）Prototype root自身の変換を含める
ExcludeProtoXform含めない
applyMaskApplyMask（既定）pruneや非表示の体を配列から除く。要素数が減る
IgnoreMaskすべての体を返す。Promotionではこちら

OpenUSD Academy Note

ApplyMaskの落とし穴は、エラーにならずに静かに違う体を指すところが厄介です。実際に6体のうちid 2をpruneすると、返る配列は5要素になり、transforms[2]はid 3の変換になります（x座標が-0.5ではなく0.5になる）。1体ずれるだけなので、見た目でも気付きにくい間違いです。

idsを書いている場合、idと添字は一致するとは限りません。ids.index(TARGET_ID)のように必ず引き直します。

MakeMatrixXform()を使うと、求めた行列をそのまま1つのxformOp:transformとして書けます。translate・rotate・scaleに分解し直す必要がありません。分解は情報が落ちることがあるので、計算済みの行列を移すときはこちらが安全です。

USDAでは、inactiveIdsはPrimの丸括弧の中、つまりMetadataの位置に現れます。

promoted.usda（抜粋）USDA
def PointInstancer "Scatter" (
    append inactiveIds = [2]
)
{
    int64[] ids = [0, 1, 2, 3, 4, 5]
}

使い分け

inactiveIdsとinvisibleIdsは目的が違う

体を消す指定は2つあり、名前が似ていますが役割が違います。この違いはPromotionの正しさに直結します。

inactiveIdsinvisibleIds
正体Prim Metadata（SdfInt64ListOp）Attribute（int64[]）
書き方DeactivateId(id)CreateInvisibleIdsAttr([...])
時間で変えられるかいいえ。Metadataなので Time Sample を持てないはい。Time Sample を書ける
意味その体を構成から刈り取る（prune）その時刻に描かないだけ
用途Promotion。恒久的に1体を取り除く時間で現れたり消えたりする表現

OpenUSD Academy Note

実際にinvisibleIdsへTime Sampleを書くと、t=1では隠れ、t=10では戻る、という動きがComputeMaskAtTimeに現れます。一方inactiveIdsに同じことをしようとすると、そもそもMetadataなので値の型が違うと拒否されます。Promotionのように「ずっと消しておく」用途にinvisibleIdsを使うと、意図が伝わらない記述になります。見た目は同じでも、下流のツールは別のものとして扱います。

どちらも最終的にはComputeMaskAtTime()に反映されるので、実際に描かれるかどうかを確かめるときはこれを見ます。

Diagram

Point Instanceへの3つの手段

よくある間違い

配列の対応がずれる

Primvarの個数がpositionsと合わない

varyingなら、値の個数はpositionsの要素数と同じでなければなりません。1個でも足りないと、色が付かないか、意図しない体に付きます。

constantを指定して1体ずつ変えようとする

constantはPointInstancer全体で1個です。1体ずつ変えたいならvarying（またはvertex）です。

配列から要素を削除して1体を消す

positionsやprotoIndicesから要素を消すと、それ以降の体のindexがすべてずれます。他の配列との対応も崩れます。恒久的に取り除きたいときはDeactivateId()、時間で消したいときはinvisibleIdsを使います。

PromotionにinvisibleIdsを使う

見た目は同じになりますが、invisibleIdsは時間で変わる表示・非表示のための指定です。Promotionのように恒久的に取り除く場合はDeactivateId()（inactiveIds）を使います。下流のツールは両者を別のものとして扱うため、意図が伝わらなくなります。

idsを振らずにinvisibleIdsを使う

idsを書いていない場合、番号は配列のindexとして扱われます。要素を足し引きすると意味が変わってしまうため、個体を名指ししたいならidsを明示します。

pruneした後に既定のApplyMaskで変換を取る

ComputeInstanceTransformsAtTime()は既定で、pruneや非表示の体を配列から除きます。DeactivateId(2)のあとに既定のまま呼ぶと要素が1つ減り、transforms[2]はid 3の変換になります。エラーにならず1体分ずれるだけなので気付きにくい間違いです。PromotionではIgnoreMaskを渡します。

world変換をそのままlocalとして書く

置き先の親に変換があると、親の分が二重に効きます。親のComputeLocalToWorldTransform()の逆行列を掛けてlocal空間へ戻してから書きます。親が変換を持たないうちは問題が出ないので、後から親を動かしたときに初めて壊れます。

Promotionした体を隠し忘れる

invisibleIdsを書かずに通常のPrimを置くと、同じ場所に2つ重なります。見た目ではほとんど分からないので、気付きにくい間違いです。

Glossary

このレッスンの用語

Point Instance
PointInstancerが配列から置く1体。Primではないので、Pathを持たない。
protoIndices
1体ごとに、prototypesのどれを使うかを番号で並べた配列。
prototypes（Relationship）
PointInstancerが使う元の形を指すRelationship。複数持てる。
ids
1体ごとに振る識別番号。配列の増減があっても個体を名指しできる。
invisibleIds
その時刻に描画しない体をidsで指定するAttribute。Time Sampleを持てるため、時間で現れたり消えたりする表現に使う。
inactiveIds
体を構成から刈り取るPrim Metadata。SdfInt64ListOpで、Time Sampleは持てない。DeactivateId()が書き込む。
DeactivateId
指定したidの体をinactiveIdsへ加えるPython API。Promotionの前段で使う。
prune（刈り取り）
対象を構成から取り除くこと。表示を切るのとは違い、そこに無いものとして扱われる。
ComputeMaskAtTime
どの体が描かれるかをTrue／Falseの並びで返すPython API。
Promotion
Point Instanceの1体をDeactivateId()でpruneし、ComputeInstanceTransformsAtTime()で求めた変換を持つ通常のPrimを同じ場所へ置き直して、個別に編集できるようにすること。
ComputeInstanceTransformsAtTime
1体ごとの変換を行列の配列で返すPython API。positions・orientations・scalesと、既定ではPrototype root自身の変換もまとめて含む。返る行列はPointInstancerのローカル空間。既定のApplyMaskではpruneした体が配列から除かれるため、Promotionのようにpruneした体を扱うときはIgnoreMaskを渡す。
ApplyMask / IgnoreMask
ComputeInstanceTransformsAtTime()の引数。前者（既定）はinactiveIdsやinvisibleIdsで外れた体を配列から除き、後者はすべて返す。
