Property

シーン全体、構成要素、要素が持つ情報を三段階で整理します

今日これだけ

Stageはシーングラフを提示し、Primが階層を作り、PropertyがPrimの情報を持つ

公式情報に基づく説明

三つの役割を分ける

Stageは合成されたシーングラフを提示します。PrimはOpenUSDシーンの構成要素で、視覚的なものにも非視覚的なものにもなれます。PropertyはPrimの特徴や接続を表し、AttributeとRelationshipの二種類があります。

OpenUSD Academy Note

Stageを「全体」、Primを「項目」、Propertyを「項目の中身」と読んでから、正式な役割へ戻ると混同しにくくなります。

Diagram

全体から情報へ降りる

USDA

Sphere Primにradius Propertyを書く

stage-prim-property.usdaUSDA
#usda 1.0

def Xform "World"
{
    def Sphere "Ball"
    {
        double radius = 2
    }
}

SphereはPrim型、BallはPrim名です。doubleは数値型、radiusはAttribute名、=は値の指定、2は値です。4個、8個と増える空白は階層を見やすくします。

Python

Stageを作りPrimとPropertyを加える

create_ball.pyPython
from pxr import Usd, UsdGeom

stage = Usd.Stage.CreateNew("stage-prim-property.usda")
UsdGeom.Xform.Define(stage, "/World")
ball = UsdGeom.Sphere.Define(stage, "/World/Ball")
ball.CreateRadiusAttr(2)
stage.Save()

UsdGeomはgeometry関連のSchema APIです。ballはSphereを参照するPython側の名前で、Prim名とは別です。CreateRadiusAttr(2)はradius Attributeを値2で作ります。

Beginner notes

名前と型とPathを別々に読む

OpenUSD Academy Note

引用符内はPrim名、引用符の前は型です。波括弧はPrimの内容を囲みます。Path /World/BallではスラッシュがPrim名を区切ります。Pythonの丸括弧は引数、カンマは引数の区切りです。

Common mistakes

階層と情報を混同しない

radiusを子Primだと思う

radiusはBall PrimのAttributeです。defで始まるPrimとは役割が違います。

Stageはファイルそのものだと思う

Stageは複数Layerから合成される統一されたシーングラフです。
