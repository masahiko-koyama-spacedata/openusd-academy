STEP 30 · COLLECTION

Collectionで対象をまとめる

階層をまたいだ集まりに、名前を付けます

今日これだけ

Collectionは階層と関係なくPrimの集まりに名前を付ける仕組みで includes と excludes で組み立てる

公式情報に基づく説明

階層で表せない「まとまり」を作る

階層は1つの分け方しか表せません。/World/Buildingの下に壁とドアと窓を置けば、それは「建物の一部」というまとまりです。しかし「金属でできているもの全部」や「この光を当てる対象」のように、階層をまたぐまとまりを作りたいことがあります。

そのための仕組みがCollectionです。CollectionAPIを適用すると、そのPrimに名前付きの集まりを作れます。STEP 14で見たMultiple-Apply API Schemaの代表例で、1つのPrimにwalls・metalのようにいくつでも付けられます。

集まりの中身は2つのRelationshipで決めます。includesが「入れるもの」、excludesが「その中から除くもの」です。さらにexpansionRuleで、指定したPathの子孫まで含めるかどうかを決めます。

OpenUSD Academy Note

すでに何度か名前が出ています。STEP 41のLightはCollectionAPI:lightLinkとCollectionAPI:shadowLinkを自動で持っていて、「この光をどのPrimに当てるか」をCollectionで指定します。STEP 40のCollection-based bindingも同じ仕組みです。Collectionは、あちこちで「対象の集まり」を表すための共通部品です。

USDA

建物の中から、ドアだけを除く

collection.usda（抜粋）USDA
def Xform "World" (
    prepend apiSchemas = ["CollectionAPI:walls"]
)
{
    uniform token collection:walls:expansionRule = "expandPrims"
    rel collection:walls:includes = </World/Building>
    rel collection:walls:excludes = </World/Building/Door>

    def Xform "Building"
    {
        def Cube "Wall_A"
        {
            double size = 1
        }

        def Cube "Wall_B"
        {
            double size = 1
        }

        def Cube "Door"
        {
            double size = 1
        }

        def Cube "Lamp"
        {
            double size = 1
        }
    }
}

Property名の作りに注目してください。collection:walls:includesのように、真ん中にCollectionの名前が入ります。これがMultiple-Apply API Schemaの書き方で、apiSchemasのほうも"CollectionAPI:walls"とコロンで名前を付けます。別のCollectionを足したいなら、"CollectionAPI:metal"を並べてcollection:metal:includesを書きます。

このUSDAファイルを開く

Python

誰が入っているかを問い合わせる

collection.pyPython
from pxr import Usd, UsdGeom

stage = Usd.Stage.CreateNew("collection.usda")
world = UsdGeom.Xform.Define(stage, "/World")
for name in ("Wall_A", "Wall_B", "Door", "Lamp"):
    UsdGeom.Cube.Define(stage, "/World/Building/" + name)
UsdGeom.Cube.Define(stage, "/World/Props/Chair")

collection = Usd.CollectionAPI.Apply(world.GetPrim(), "walls")
collection.CreateIncludesRel().AddTarget("/World/Building")
collection.CreateExcludesRel().AddTarget("/World/Building/Door")
collection.CreateExpansionRuleAttr(Usd.Tokens.expandPrims)

print("apiSchemas:", world.GetPrim().GetAppliedSchemas())

query = collection.ComputeMembershipQuery()
for path in ("/World/Building", "/World/Building/Wall_A",
             "/World/Building/Door", "/World/Props/Chair"):
    print("  %-28s 含まれる? %s" % (path, query.IsPathIncluded(path)))

print("含まれるPath:",
      sorted(str(p) for p in Usd.CollectionAPI.ComputeIncludedPaths(query, stage)))
実行結果Output
apiSchemas: ['CollectionAPI:walls']
  /World/Building              含まれる? True
  /World/Building/Wall_A       含まれる? True
  /World/Building/Door         含まれる? False
  /World/Props/Chair           含まれる? False
含まれるPath: ['/World/Building', '/World/Building/Lamp', '/World/Building/Wall_A', '/World/Building/Wall_B']

/World/Buildingを1つincludesしただけで、expandPrimsにより子孫のWall_A・Wall_B・Lampまで入りました。Doorはexcludesしたので外れています。/World/Props/Chairは別の枝なので最初から入りません。

判定は自分で階層をたどらずComputeMembershipQuery()に聞きます。includesとexcludesとexpansionRuleの組み合わせを自前で実装すると、必ずどこかを取りこぼします。

expansionRule

どこまで広げるかを決める3つの値

値意味
explicitOnlyincludesに書いたPathそのものだけ。子孫は含まない
expandPrims（よく使う）書いたPathとその子孫のPrimを含む
expandPrimsAndProperties子孫のPrimに加えて、そのPropertyまで含む

用途で選びます。「この枝全部」ならexpandPrims、「名指ししたものだけ」ならexplicitOnlyです。expandPrimsAndPropertiesは、Property単位で対象を指定したいときに使います。

Beginner notes

名前が真ん中に入る理由

OpenUSD Academy Note

collection:walls:includesという名前は最初は読みにくいですが、規則は単純です。collection（何のAPIか）:walls（どのインスタンスか）:includes（どのProperty か）の3つをコロンでつないでいます。

1つのPrimに同じAPIを何度も付けられるのがMultiple-Apply API Schemaなので、区別するための名前が要ります。それが真ん中に入ります。STEP 14でCollectionAPI:renderとCollectionAPI:proxyが並んでいたのは、これが理由です。

よくある間違い

集まりが思ったとおりにならない

expansionRuleを書かずに子孫が入ると思う

既定はexpandPrimsですが、意図を明示するために書くことを勧めます。explicitOnlyのつもりで書き忘れると、意図せず枝全部が入ります。

自前で階層をたどって判定する

includes・excludes・expansionRuleの組み合わせは自前実装で取りこぼします。ComputeMembershipQuery()に聞きます。

Collection名を付けずにAPIを適用する

CollectionAPIはMultiple-Applyなので、名前が必須です。Apply(prim)ではなくApply(prim, "walls")です。

Prim構造を変えてCollectionを直し忘れる

includesはPathを指すRelationshipです。Primを移動・改名すると指し先が無くなります。STEP 112の壊れた参照と同じ壊れ方です。

excludesがincludesより弱いと思う

excludesはincludesで入ったものを除きます。両方に書けば除かれます。

Glossary

このレッスンの用語

Collection
階層と関係なくPrimの集まりに名前を付ける仕組み。CollectionAPIで作る。
CollectionAPI
Collectionを作るMultiple-Apply API Schema。1つのPrimにいくつでも付けられる。
includes / excludes
集まりに入れるPathと、そこから除くPathを指すRelationship。
expansionRule
指定したPathの子孫まで含めるかを決めるAttribute。explicitOnly・expandPrims・expandPrimsAndProperties。
Membership Query
あるPathがCollectionに含まれるかを判定するためのオブジェクト。ComputeMembershipQuery()で得る。
Light Linking
どのPrimを光で照らすかをCollectionで指定する仕組み。Lightに自動で適用される。
