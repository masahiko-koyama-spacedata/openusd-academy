STEP 43 · INTERPOLATION

補間とvelocities

書いていない時刻の値は、誰が決めているのか

今日これだけ

Time Sampleの間の埋め方は Interpolation Typeとvelocitiesの2つで変えられる

公式情報に基づく説明

書いていない時刻の値は、誰かが決めている

STEP 42で、timeSamplesに{0: ..., 10: ...}と書けば時間で値が変わることを見ました。ではその間、たとえばt = 5の値はどこから来るのでしょうか。書いていないので、規則で埋められています。その規則を決めるのがこのレッスンの内容です。

1つ目がInterpolation Typeです。Stage全体の設定で、既定はlinear（隣の値へ向かって直線的に変化）です。heldにすると、次のTime Sampleに達するまで前の値を保ち続けます。カクカクした切り替えや、離散的な値に使います。

2つ目がvelocitiesです。点の位置を持つGprim（PointBased）に限り、位置とは別に速度を書けます。速度があると、間の時刻は「隣のTime Sampleへ向かう補間」ではなく「その時刻の速度から求めた位置」になります。

OpenUSD Academy Note

velocitiesが必要になる典型は、点の数が時刻によって変わる表現です。パーティクルのように点が生まれたり消えたりすると、隣のTime Sampleと点の対応が取れないので線形補間ができません。速度なら1点ごとに独立して求められるので、対応が取れなくても破綻しません。

Interpolation Type

linearとheldを切り替える

interpolation_type.pyPython
from pxr import Gf, Usd, UsdGeom

stage = Usd.Stage.CreateNew("t.usda")
xform = UsdGeom.Xform.Define(stage, "/X")
op = xform.AddTranslateOp()
op.Set(Gf.Vec3d(0, 0, 0), 0.0)
op.Set(Gf.Vec3d(10, 0, 0), 10.0)

print("既定:", stage.GetInterpolationType())
print("t=5 :", tuple(op.Get(5.0)))

stage.SetInterpolationType(Usd.InterpolationTypeHeld)
print("Heldにすると t=5 :", tuple(op.Get(5.0)))
実行結果Output
既定: Usd.InterpolationTypeLinear
t=5 : (5.0, 0.0, 0.0)
Heldにすると t=5 : (0.0, 0.0, 0.0)

linearでは中間の5.0、heldでは前の値の0.0が返りました。これはStage全体の設定で、Attributeごとには変えられません。

ただし、値の型によってはlinearでも補間されません。tokenやstring、assetのように間の値を計算できない型は常にheldとして扱われます。xformOpOrderのようなuniform宣言の属性は、そもそもTime Sampleを持てません。

timeCodesPerSecond と framesPerSecond

似た名前だが役割が違う

Metadata役割合成への影響
timeCodesPerSecondTime Codeを秒へ変換する率。velocitiesの計算などに実際に使われるある
framesPerSecond再生の目安として下流ツールへ伝える値ない

STEP 42で「Time Codeは単位を持たない数」と説明しました。その数を秒に結び付けるのがtimeCodesPerSecondです。24なら、Time Codeの24が1秒にあたります。

framesPerSecondは再生速度の申し送りで、値の解決には関与しません。2つは普通は同じ値にしますが、意味は別です。

USDA

velocitiesを書いたものと、書かないもの

velocity.usda（抜粋）USDA
#usda 1.0
(
    startTimeCode = 0
    endTimeCode = 24
    timeCodesPerSecond = 24
    framesPerSecond = 24
)

# velocities 無し。Time Sample どうしを線形に補間する
def Points "NoVel"
{
    point3f[] points.timeSamples = {
        0: [(0, 0, 0)],
        24: [(10, 0, 0)],
    }
    float[] widths = [0.2]
}

# velocities 有り。位置は「速度 × 経過秒」で決まる
def Points "WithVel"
{
    point3f[] points.timeSamples = {
        0: [(0, 1, 0)],
        24: [(10, 1, 0)],
    }
    vector3f[] velocities.timeSamples = {
        0: [(24, 0, 0)],
        24: [(24, 0, 0)],
    }
    float[] widths = [0.2]
}

velocitiesの型はvector3f[]です。pointsのpoint3f[]とはroleが違います。STEP 08で見たとおり、pointは位置、vectorは方向と大きさを表し、変換のかかり方が違います。

このUSDAファイルを開く

Python

間の時刻を並べて比べる

compare_velocity.pyPython
from pxr import Usd, UsdGeom

stage = Usd.Stage.Open("velocity.usda")
a = UsdGeom.Points(stage.GetPrimAtPath("/World/NoVel"))
b = UsdGeom.Points(stage.GetPrimAtPath("/World/WithVel"))

print("timeCodesPerSecond =", stage.GetTimeCodesPerSecond())
for t in (0.0, 6.0, 12.0, 18.0, 24.0):
    ra = UsdGeom.PointBased.ComputePointsAtTime(a, t, t)
    rb = UsdGeom.PointBased.ComputePointsAtTime(b, t, t)
    print("t=%-6s 無し=%-8s 有り=%s"
          % (t, round(ra[0][0], 3), round(rb[0][0], 3)))
実行結果Output
timeCodesPerSecond = 24.0
t=0.0    無し=0.0      有り=0.0
t=6.0    無し=2.5      有り=6.0
t=12.0   無し=5.0      有り=12.0
t=18.0   無し=7.5      有り=18.0
t=24.0   無し=10.0     有り=10.0

両端は同じですが、間がまったく違います。左は0から10へ直線的に進みます。右はvelocities = (24, 0, 0)、つまり秒あたり24進む速度で計算されるので、t=12（0.5秒）では24 × 0.5 = 12まで行きます。

ComputePointsAtTime()は、この規則をすべて解いた結果を返します。pointsを直接Get(t)するとvelocitiesは無視されるので、速度を使う表現では必ずこちらを使います。

Beginner notes

velocitiesは位置と同じ時刻に書く

OpenUSD Academy Note

velocitiesのTime Sampleは、pointsと同じ時刻に揃っていなければなりません。ずれているとvelocity samples are not aligned with position samplesという警告が出て、速度は使われず線形補間に戻ります。

この教材を書く途中でも、velocitiesをt=0にだけ書いてpointsを0と24に書いたところ、この警告が出て速度が効きませんでした。両方に書いて初めて期待どおりになりました。

よくある間違い

時間の値が思ったとおりにならない

velocitiesを書いたのに効かない

pointsと時刻が揃っていないと無視されます。警告は出ますが、値は返ってくるので気付きにくい間違いです。

points.Get(t)で速度込みの位置を取ろうとする

Get()はvelocitiesを考慮しません。ComputePointsAtTime()を使います。

timeCodesPerSecondとframesPerSecondを同じものだと思う

前者は値の解決に使われ、後者は再生の目安です。velocitiesの計算に効くのは前者だけです。

Interpolation TypeをAttributeごとに変えようとする

Stage全体の設定です。個別には変えられません。

token型の値が補間されると思う

間の値を計算できない型は、linear設定でも常にheldとして扱われます。

Glossary

このレッスンの用語

Interpolation Type
Time Sampleの間をどう埋めるかのStage全体の設定。linear（既定）とheldがある。
held（補間）
次のTime Sampleに達するまで前の値を保つ埋め方。間の値を計算できない型では常にこの扱いになる。
velocities
点の速度を表すAttribute。型はvector3f[]。位置とは別に持ち、間の時刻の位置を速度から求める。
accelerations
点の加速度を表すAttribute。velocitiesと併せて、より正確に間の位置を求める。
timeCodesPerSecond
Time Codeを秒へ変換する率。velocitiesの計算に実際に使われる。
framesPerSecond
再生の目安として下流へ伝える値。値の解決には関与しない。
ComputePointsAtTime
velocitiesまで含めた点の位置を返すPython API。
