STEP 87 · DEBUGGING

壊れたReferenceとPathを直す

よくある3つの壊れ方を、症状から見分けます

今日これだけ

Primはあるのに中身が空なら、たいていReferenceが解けていない

公式情報に基づく説明

解けなかったArcは、静かに空になる

参照先のファイルが見つからない、あるいは指定したPathが相手のファイルに無い場合、OpenUSDは例外を投げません。そのPrimは存在するが、中身が空という状態になります。この振る舞いは、一部が欠けても残りが開けるようにするためのものです。裏を返せば、壊れていても動いてしまうということでもあります。

OpenUSD Academy Note

この章までに学んだ道具が、ここで組み合わさります。STEP 65 Hydraで作った「描かれない理由」の切り分けを回して、どれにも当てはまらないのに空、という場合が本レッスンの対象です。

USDA

3通りに壊したシーン

broken.usda（抜粋）USDA
def Xform "World"
{
    def "Good" (
        references = @part.usda@
    )
    { ... }

    def "MissingFile" (
        references = @missing-part.usda@       # ファイルが無い
    )
    { ... }

    def "WrongPath" (
        references = @part.usda@</Prt>         # Path の綴りが違う
    )
    { ... }

    def Scope "Selection"
    {
        custom rel members = [
            </World/Good>,
            </World/Nowhere>,                  # 存在しないPathを指す
        ]
    }
}

1つ目は正しく、残り3つがそれぞれ違う壊れ方をしています。

このUSDAファイルを開く

結果

見た目には「1つしか出ない」

走査した結果Python
from pxr import Usd

stage = Usd.Stage.Open("broken.usda")

for name in ("Good", "MissingFile", "WrongPath"):
    prim = stage.GetPrimAtPath("/World/%s" % name)
    print(name, [c.GetName() for c in prim.GetChildren()])

# Good         ['Body']
# MissingFile  []          … Primはあるが空
# WrongPath    []          … Primはあるが空

Primは3つとも存在します。違うのは子がいるかどうかだけです。「Primはあるのに子がいない」が、Referenceが解けていないときの典型的な症状です。

2つの壊れ方が、それぞれ別のメッセージで報告されます。どのファイルの、どのPrimが原因かまで書かれているので、そのまま直しにいけます。

道具

usdcheckerが教えてくれないこと

上の出力に、/World/Nowhereを指しているRelationshipは出てきません。存在しないPathを指すRelationshipは、Compositionのエラーではないためです。

check_targets.pyPython
from pxr import Usd


def check_targets(stage):
    """存在しないPathを指しているRelationshipを探す。"""
    broken = []
    for prim in stage.TraverseAll():
        for rel in prim.GetRelationships():
            for target in rel.GetTargets():
                if not stage.GetPrimAtPath(target.GetPrimPath()):
                    broken.append("%s -> %s" % (rel.GetPath(), target))
    return broken


stage = Usd.Stage.Open("broken.usda")
print(check_targets(stage))
# ['/World/Selection.members -> /World/Nowhere']

STEP 77 Prim Hierarchy Transformationで書いたものと同じ検査です。この種の壊れは自分で探すしかありません。STEP 75 Material BindingもRelationshipなので、材質が当たらない原因もこれで見つかります。

Diagram

症状から原因へ

Python

直す

fix.pyPython
from pxr import Sdf, Usd

stage = Usd.Stage.Open("broken.usda")

# 1. 参照先のファイルを差し替える
prim = stage.GetPrimAtPath("/World/MissingFile")
refs = prim.GetReferences()
refs.ClearReferences()
refs.AddReference("part.usda")

# 2. Path の綴りを直す
prim = stage.GetPrimAtPath("/World/WrongPath")
refs = prim.GetReferences()
refs.ClearReferences()
refs.AddReference("part.usda", "/Part")

# 3. 切れたtargetを取り除く
rel = stage.GetPrimAtPath("/World/Selection").GetRelationship("members")
alive = [t for t in rel.GetTargets()
         if stage.GetPrimAtPath(t.GetPrimPath())]
rel.SetTargets(alive)

stage.Save()

参照はClearReferences()で一度消してから張り直すのが確実です。STEP 49 List Editingのとおり、追加だけすると古い記述が残ったままになるためです。

Beginner notes

相対パスの基準

OpenUSD Academy Note

ファイルが見つからない原因で多いのが、相対パスの基準の取り違えです。@part.usda@のような相対パスは、それを書いているファイルの場所を基準に解決されます。Stageのルートでも、実行時の作業ディレクトリでもありません。ファイルを別の場所へ移したときは、そのファイルが書いている相対パスも見直す必要があります。

よくある間違い

エラーが出ないことを根拠にする

usdcheckerが通ったから大丈夫と考える

Relationshipのtarget切れは報告されません。自前の検査も回します。

空のPrimを「無い」と判断する

Primは存在しています。中身が来ていないだけなので、原因はComposition側です。

ClearせずにAddReferenceする

古い記述が残り、両方が効いたり順序で混乱したりします。

相対パスの基準を実行場所だと思う

基準は、その記述を書いているファイルの場所です。
